# World events (0.8.25)

The read-only feed ships in every build because bounded notifications are useful to passive readers without granting test or write capabilities. The recorder remains an explicit autonomous/test-hook facility. No new recurring game-thread poll is installed. All evidence below is **source/offline** until the maintainer runs the WE rows.

| Family | Producer | Bounds and limits |
|---|---|---|
| `session` | Codeware lifecycle, or script attach/ready/detach fallback | Fallback has no early load/save coverage |
| `death` | Shared death/defeat/status wraps | Knockdown is distinct; exact incident receipt or null |
| `combat` | Player combat-state wrap | State edges |
| `heat` | Wanted/chase fact listeners and heat-stage wrap | V's heat, not every world crime |
| `dialogue` | Scripted dialog consumer and selected-index listener | Two hubs/four choices/48-character prefixes; partner unavailable |
| `journal` | State/Tracked/Counter callbacks | Bounded parent path with completeness flag |
| `fact` | 93 named quest-fact listeners | Watch list only |
| `call` | PhoneCallInformation variant listener | Identical snapshots coalesced |
| `district` | UI_Map.currentLocationEnumName string listener; reads newLocationDiscovered in the callback | Bounded enum name/previous enum, observed discovery flag; empty initial previous value; trigger/flag ordering needs WE9 |
| `vehicle` | Shared PlayerPuppet mount/unmount and VehicleObject.StealVehicle wraps | Parent/child entity ids and seat; theft names vehicle, record and thief; one theft fan-out to incidents/probe/feed |
| `vehicle.acquired` | VehiclePurchaseData.PurchasedVehicleRecordID variant listener | TweakDB record id; only the engine's purchase signal, not proof of every ownership route |
| `time` | Shared GameTimeUtils.FastForwardPlayerState wrap; existing recorder V samples | Explicit menu callback plus separately inferred signed jumps; no new poll |

The four second-cut families use the same ring, epochs, per-family QPC budgets, loss counters and optional recorder `events` delivery as the first eight. District and purchase listeners live on the saved blackboards from OnPlayerAttach to OnDetach, then clear their references/history. Their old probe subscriptions are replaced by fan-out. Existing probe mount/unmount/menu wraps and both theft wraps are consolidated; every shared wrap calls `wrappedMethod` exactly once before observing and preserves its return value.

`time {what: "menu_skip", inferred: false}` observes FastForwardPlayerState after the menu has already set the clock; it does not measure hours skipped. `time {what: "jump", source: "recorder.v", inferred: true, cause: "unknown"}` compares existing valid `game_time_s` samples in one recorder run/world/session: emit only when the absolute game-time delta exceeds `max(300, 60 * elapsed_real_s)`, with positive elapsed real time no greater than 30 seconds. It includes previous game seconds, signed delta, real elapsed seconds and the threshold. First, missing/invalid, changed-run/epoch, equal/backward-QPC and long-gap samples rebaseline. A menu callback and an inferred jump may describe the same skip; they are observations, not two counted skips. Sleeping, quests, fast travel and bridge clock writes have no inferred cause label. Other jumps are observable only while the autonomous recorder samples V; disabling V recording means no sampled-jump coverage. No new TimeSystem read, timer or poll is installed.

`world.events` has its own 2,048-entry ring, so gameplay cannot evict command receipts from `session.events`. The fixed twelve families each admit 20 events per QPC second; contention and rate refusals increment counters, carried as `dropped` on the next kept family event. Producers use a nonblocking ring lock. Read pages cap at 100 rows/48 KiB; `next` is inclusive and moves over skipped kinds. `missed` and `evicted` expose overwritten history. All payloads cap at 4 KiB. QPC `s` shares the recorder clock; game seconds are null until the script gate opens. The native session counter increments on Codeware Start, or script attach without Codeware; it survives save loads, as does this ring. A short producer-only epoch lock captures the native world read and session transition together at ingress; insertion carries that immutable pair even if a newer Start inserts first. Ring readers never hold this lock. Start counters advance even if the corresponding notification is rate-dropped. A new bridge process resets cursors.

Codeware's persistent `ScriptableService` observes BeforeStart/Start/Ready/BeforeSave/AfterSave/BeforeEnd/End. It registers no gameplay listeners. Without Codeware, `coverage.session_callbacks` is `script_layer_only`: script attach/player-ready/detach only, with no early load/start/save detection. This is limited coverage, not equivalent lifecycle evidence. Blackboard/fact/journal listeners attach after `XFBridgeSystem.OnPlayerAttach` opens the native gate and unregister from their saved boards in `OnDetach`.

Shared death/defeat wrappers fan out to the unchanged incident perception/admission logic, the old probe, and the feed. An optional correlation token is added only to the incident wire envelope; native accepted-observation bookkeeping returns the exact `inc-N` receipt to the same callback and native world generation. Rejected/unobserved deaths carry `incident_id: null`; there is no nearest-person/time heuristic. The old incident observation and report payloads are unchanged. Knockdown is `death` with `what: knockdown`; it is not a kill and does not open an incident. Heat facts fan out from one subscription each.

Dialogue wraps scripted `dialogWidgetGameController.UpdateDialogsData(const data: script_ref<DialogChoiceHubs>) -> Void` after the original consumer, plus `UIInteractions.SelectedIndex`. It makes a native QPC admission check before borrowing at most two indexed hubs through a `script_ref<ListChoiceHubData>` helper. No whole hub or choices array is copied; only scalar fields and up to four 48-character choice prefixes per hub are materialized; counts and truncation flags disclose omissions. Equal bounded snapshots are coalesced. `ListChoiceHubData` has no partner entity, and no script-visible dialogue-system accessor in the checked bundle supplies one, so `partner: null, partner_available: false` is explicit. It does not guess from a look-at target. Selected index is a highlight; a pick remains inferred. Journal State/Tracked/Counter records resolve hash to entry, then parent ids (16 levels, 24 characters per segment); `path_complete: false` exposes absent/clipped paths. There are 93 named fact listeners from the main-story list, attached once per world. Calls retain the engine's IncomingCall/StartCall/EndCall phases and contact id.

`test.journal.track` is the only new explicit game action: autonomous/test-hooks only, act class, and a single `JournalManager.TrackEntry` call on an existing active quest/objective. It accepts a unique path or unsigned journal hash, refuses an already tracked/non-active/non-quest entry and returns the requested/previous/observed tracked hashes. No entries are created and no quest state/counter is set. `quest.set`/`quest.objective` are the separate journal-free HUD tracker (`native/src/core/DmService.cpp`), so they cannot provoke these journal callbacks.

Producer signatures and source locations are cited in [game events](../../../knowledge/game-events.md#11-what-the-bridge-has-and-what-it-should-add). This implementation changes no incident grouping, perception, write budget or game-thread dispatcher pacing. Optional recorder `events` copies each retained world envelope at ingress; coverage heartbeats report the feed metadata without a game call. Recording stops across loads as before; independent `world.events` retains those edges.
