# XF Photo Mode Tools

Status: an independent peer project in research, not part of XF Studio. Its successor, **XF Photo Mode**, is designed as the first plugin on the XF Core runtime base and will ship on the same Nexus page. The first feature is complete photo-mode snapshots: unlimited named snapshots that restore everything, unlike the game's three slots. A per-character head-and-eye freeze replaces the legacy tool. Design, restore order, test plan, phases and open questions: [research/runtime/photo-snapshots-design.md](../../research/runtime/photo-snapshots-design.md). The facts it rests on are in [knowledge/photo-mode.md §9–10](../../knowledge/photo-mode.md#9-the-three-save-slots).

**The legacy tool** (`D:/Dev/xf-photo-mode-tools/bin/x64/plugins/cyber_engine_tweaks/mods/photo_mode_tools/init.lua`, research input only) had one feature: a gaze freeze through the global engine option `LookAt/MaxIterationsCount`. It set 1.0 on init, toggled 0.9/1.0 to freeze, and hard-coded 3.0 on restore and shutdown, without capturing the original value. That affects every character, not only the photo-mode actor. Nothing else from it needs preserving. The replacement is the per-character freeze through individual time dilation, with the global option only as a guarded fallback that captures and restores the original value ([design §4](../../research/runtime/photo-snapshots-design.md#4-head-and-eye-freeze)).

Useful references: `D:/Dev/cp2077-photomode-ex`, `cp2077-codeware`, `cp2077-cet-kit`, `appearancemenumod`, `CP77_nativeSettings`, and the photo, pose and camera mods on the reference MO2 profile (Photo Mode Pose Selector, Photo Mode Preferences, CharLi). Use a project-local `src`, `data`, `resources`, `build`, `dist` layout when implementation begins.
