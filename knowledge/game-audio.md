# Game audio: dispatch, names and source attribution

**Maturity: Draft.** Static R2 research for **Cyberpunk 2077 2.31**, 24 October 2026. **[binary]** The retail executable exports Wwise's three `AK::SoundEngine::PostEvent` overloads, object registration and unregistration. Their addresses and calling conventions are located below. **[source/binary]** Script sound requests and a native dialogue-line consumer are also located. **[hypothesis]** These are candidates for the [runtime bridge](../projects/xf-runtime-bridge/README.md), not commissioned hooks: no new tap was implemented or run, and **posting does not prove audibility**. Gunshot/ambient producer chains, exact runtime threads and general audio-object-to-entity attribution remain open.

Grades: **[source]** inspected decompiled game scripts or public framework source, with file/line; **[binary]** inspected executable exports, RTTI or instructions, with image-relative address; **[wiki]** the pinned Modding Docs; **[hypothesis]** proposed design or inference requiring a session. **[offline]** means a local tool result, never gameplay. Source combinations such as [source/binary] distinguish independently supporting evidence. This supplements [input and choices](input-and-choices.md), [runtime access](runtime-access.md), [game events](game-events.md), [NPC reactions](npc-reactions.md) and [lip sync](lipsync.md).

## 3. Script requests and native engine dispatch

### Names and entities before the audio queue

**[source]** `core/systems/audioSystem.script:10–20` declares native `Play(eventName: CName, opt entityID: EntityID, opt emitterName: CName)`, `Stop`, `Switch`, `Parameter`, `PlayImpact` and `PlayOnEmitter`. `Play` returns `Void`, so its wrapper cannot report a Wwise playing ID. A concrete named-emitter caller is the pocket radio: `core/gameplay/pocketRadio.script:118,135` uses the player's entity ID and `pocket_radio_emitter`. Vehicle warning callers use `vehicle_engine_emitter` (`core/components/scriptComponents/vehicleComponent.script:3727–3728`).

**[source]** `GameObject.PlaySound` is not a synonym for that native call. At `core/entity/gameObject.script:772–787`, a defined entity ID routes through `PlaySoundEvent`; the other branch calls `AudioSystem.Play`. `PlaySoundEvent` validates the name and queues `AudioEvent` (`:809–816`); `PlaySoundEventWithParams` additionally sets action/flags (`:818–827`). `PlayMetadataEvent` sets the Metadata flag (`:838–843`). Preserve this distinction: names can identify metadata and actions as well as play requests.

**[source]** That defined-entity branch does not copy the helper's `emitterName` argument into `AudioEvent`; it passes only `self` and `eventName`. A recorded helper argument is therefore not proof of the effective native emitter selection (`gameObject.script:772–787,809–827`).

**[source]** SDK `Scripting/Natives/Generated/ent/AudioEvent.hpp:18–35` describes the actual `entAudioEvent`: `eventName +0x40`, **`emitterName +0x48`**, `nameData +0x50`, `floatData +0x58`, `eventType +0x5c`, `eventFlags +0x60`, size `0x68`. The decompiled script declaration (`orphans.script:18275–18287`) omits `emitterName`; absence from that script declaration does not mean absence from native RTTI. Similarly, `game/audio/events/PlaySound.hpp:16–30` identifies `SoundPlayEvent` as `gameaudioeventsPlaySound`, with sound, emitter, tag, seek and unique fields.

**[binary]** `AudioSystem` registration `0x1048000` names the alias at `0x104803d`, calls Play registration `0x938520` at **`0x1048069`**; `0x938570` installs thunk **`0x62aad0`**. That thunk reads **three** VM arguments. A zero entity ID goes through `0x62abc0` at `0x62aba3`; the nonzero cold branch **`0x1ec5d9a`** passes entity ID, emitter name and an event-parameter block to **`0x103cac`** at `0x1ec5dc1`. `PlayOnEmitter` registration `0x1cb2d70` installs **`0x1cb2f00`** at `0x1cb2dcb`; it also reads three arguments, reaching `0x103cac` at `0x1cb2fe5` or the global route at `0x1cb3017`.

**[source/binary] VM ABI:** SDK `Scripting/Functions.hpp:93` defines `Handler_t` as `void (*)(void*, CStackFrame&, void*, rtti::IType*)`. Thus Windows x64 uses RCX=context, RDX=frame pointer, R8=result storage, R9=result type. The thunks above consume/advance that frame. **[hypothesis]** An observational hook must not decode it once and hand the advanced frame to the original. Prefer script-producer logging plus a later native post tap; use a thunk hook only with a separately validated, non-mutating argument reader. These are called on the invoking VM thread; **its runtime thread identity was not established**.

### Selected VO is a different event

**[source]** `GameObject.PlayVoiceOver` can reject missing objects, vehicle-mounted actors, server execution and invalid triggers before queuing; a delay can defer it (`gameObject.script:743–769`). SDK `ent/GameplayVOEvent.hpp:19–39` supplies `voContext`, quest/frustum/distance/global-limit flags, debug context, answering entity and expression/context overrides. Codeware `scripts/Base/Addons/SoundPlayVo.reds:1–17` exposes the additional native fields. Observing this request does not identify which line survived selection and limits.

**[source]** Codeware imports `DialogLineEvent` (`scripts/Base/Imports/DialogLineEvent.reds:1–3`) and `audioDialogLineEventData` (`scripts/Base/Overrides/audioDialogLineEventData.reds:1–12`). SDK `game/audio/events/DialogLine.hpp:16–23` and `audio/DialogLineEventData.hpp:18–35` give a size-`0x68` Event, with size-`0x28` data at `+0x40`: `stringId +0`, context/expression `+8/+9`, player/rewind/holocall flags `+0x10/+0x11/+0x12`, `customVoEvent +0x18`, seek `+0x20`, playback-speed parameter `+0x24`. Codeware adds **gender at data+0xc** (`src/App/Audio/audioDialogLineEventData.hpp:3–5`). This is a line identity and playback request, not a Wwise event ID.

**[binary]** Type registration **`0x16b848c`** names `gameaudioeventsDialogLine`, size `0x68`, descriptor slot **`0x3430c60`**. The `soundComponent` registration at **`0x12a7130`** names the alias at `0x12a71a4` and calls **`0x12a7660`** at `0x12a73cf`. That registration loads the dialogue descriptor at `0x12a76b9`, installs handler **`0x533878`** at `0x12a76d1` and registers it at `0x12a76e3`. The handler's observed entry contract is **RCX=sound component, RDX=DialogLineEvent pointer**; it reads `event+0x58` (custom VO event), falls back to `component+0x1a0`, and passes `event+0x40` into **`0x5339e0`** at `0x53397b`. The component offset matches SDK `game/audio/SoundComponent.hpp:25` (`voEventOverride`).

**[binary]** `0x5339e0` reads line ID/gender at `0x533a64–0x533a8c`, branches for rewind/holocall and calls a resource lookup **`0xa93f84`**. On a successful normal branch, **`0x533b9d–0x533bc0`** builds a command with type `6`, resource pointer and seek time and submits it through **`0x130b84`**. That submission function has null/lifetime checks and calls `0x130bdc` at `0x130ba7`. This locates a native audio-command boundary; it does not establish which worker consumes it. No return contract for the event handler or safe component-owner lookup was fully validated, so commission those before making a typed handler detour. Do not call these functions as stimulus.

**[source] Presentation cross-check:** `cyberpunk/UI/subtitles/baseSubtitlesControllers.script:120–129` uses delayed `ShowDialogLine/HideDialogLine/HideDialogLineByData` listeners. `orphans.script:44905–44925` supplies line ID, text, speaker weak reference/name, type and duration. Native audio requests can be compared with these records, but text-only bridge barks can populate the UI without audio, and delayed notifications are not an every-post feed. **[hypothesis]** Line/speaker matching must report ambiguity, especially simultaneous dialogue, repeated IDs, suppressed subtitles and holocalls.

## 4. Wwise: concrete posting and object-lifecycle hooks

**[binary]** These functions are exported by this executable under decorated C++ names. For example the numeric overload is **`?PostEvent@SoundEngine@AK@@YAII_KIP6AXW4AkCallbackType@@PEAUAkCallbackInfo@@@ZPEAXIPEAUAkExternalSourceInfo@@I@Z`**. The exports encode argument types, independently checked against each body's register/stack use. Resolve the exact export on the pinned executable, rather than matching a bare `PostEvent` string: the plain profiling string has no useful direct RIP reference.

| Export / address | Windows x64 observational ABI | Grade / boundary |
|---|---|---|
| `PostEvent(uint32 eventID, uint64 audioObjectID, uint32 flags, callback, cookie, uint32 externalCount, externalSources*, uint32 playingID)` **`0x1ac8d90`** | RCX low32 event; RDX object; R8 low32 flags; R9 callback; **entry** stack `+0x28` cookie, `+0x30` external count, `+0x38` external pointer, `+0x40` requested playing ID; EAX returned playing ID. Forward all eight original arguments. | **[binary]** Call to shared implementation at **`0x1ac8e2e`**. Early external-source preparation can fail and return zero. |
| `PostEvent(const char* name, …same remaining args…)` **`0x1ac9090`** | RCX is the borrowed name pointer; other arguments/return as above. | **[binary]** Hashes the name locally, calls shared implementation at **`0x1ac9181`**; it **does not call the numeric public overload**. |
| `PostEvent(const wchar_t* name, …)` **`0x1ac91c0`** | RCX borrowed UTF-16 name pointer; other arguments/return as above. | **[binary]** Calls shared implementation at **`0x1ac9277`**. Hooking only the numeric export cannot promise coverage of the name overloads. |
| `RegisterGameObj(uint64 id)` and `RegisterGameObj(uint64 id, const char* name)` **both `0x1acbab0`** | RCX=id, EAX=native result code. **RDX is unused in this body.** | **[binary]** One physical hook for both exports. A debug name cannot be recovered from this build's implementation by assuming RDX is valid. It enqueues object registration at `0x1acbaf8`. |
| `UnregisterGameObj(uint64 id)` **`0x1ad1930`** | RCX=id, EAX=native result code. | **[binary]** Object-lifetime boundary; not entity detach. |
| `UnregisterAllGameObj()` **`0x1ad17b0`** | No arguments; EAX=native result code. | **[binary]** Enqueues the same command kind as unregistration with object ID `0xffffffffffffffff` at `0x1ad17e8`. Observing only individual unregister calls misses this bulk lifetime boundary. |
| `GetIDFromString(const char*)` **`0x1ac6850`**; wide overload **`0x1ac68a0`** | RCX=string pointer, EAX=32-bit ID. | **[binary]** A helper for actual Wwise names, not a general RED-name→event mapping. |
| `ExecuteActionOnEvent` numeric **`0x1ac5870`**, narrow **`0x1ac5a10`**, wide **`0x1ac5a90`** | Exported typed action route; full detour ABI not traced here. | **[binary]** Located, **not implementation-ready**. Stop/fade/pause coverage needs this and other playing-ID actions researched separately. |

**[binary]** All three PostEvent overloads converge on **`0x1ac8e70`**. It checks initialization, looks up the event, creates a command, allocates a playing ID and submits through **`0x1ae8580`** at `0x1ac902b`; `0x1ac906c` returns that ID, and failure paths return zero. Locks/atomic instructions are visible. **[hypothesis]** This is evidence of submission, not proof of voice instantiation, mixer execution or output. Hook public entry/return pairs first: the common helper has a different external-source argument representation and is unnecessary for the initial design.

**[binary]** Other exported lifecycle/control leads are `StopAll(uint64)` **`0x1ad0390`**, `StopPlayingID` **`0x1ad07d0`**, `ExecuteActionOnPlayingID` **`0x1ac5ad0`**, and `RenderAudio(bool)` **`0x1acc000`**. Their bodies and downstream effects were not traced here. A post-and-object feed therefore does not yet observe every stop, fade, pause or end-of-playback transition.

**[binary]** Three inspected native direct calls to the numeric export were found:

| Engine call site → function | Information still available at the engine boundary |
|---|---|
| **`0xa2f659`** in **`0xa2f548`** | Converts the incoming RED name through **`0xa30324`** at `0xa2f58f`; posts with **one external source**, cookie equal to the playback-state pointer and callback **`0x1fc57c`**. Audio object is `*(*(state+0x30)+0x10)`. Stores returned playing ID at `state+0x44`. **[binary]** |
| **`0xa2f855`** in **`0xa2f80c`** | Converts a name from an input object through `0xa30324` at `0xa2f824`; audio object is `[thirdArgument+0x10]`, callback **`0xb11830`**, cookie=third argument. **[binary]** |
| **`0xa302dd`** in **`0xa30218`** | Incoming RDX is the RED name used by `0xa30324` at `0xa30250`; R8 is playback state. Same object/state and returned-playing-ID offsets as the external-source route, **zero external sources**. **[binary]** |

**[binary]** The native lookup **`0xa30324`** takes **RCX=lookup owner, RDX=64-bit RED CName**, returns a 32-bit ID in EAX, uses the map at owner+`0x120`, indexes size-`0x68` values and reads value+`0x30`. Missing entry returns **`0x811c9dc5`**, which callers test before posting. This layout is consistent with SDK `audio/AudioEventMetadata.hpp:22–33` (`wwiseId +0x30`). **[hypothesis]** A return hook here is a compact way to learn the *effective* runtime RED-name→Wwise-ID mapping, including remapping, without reading a proprietary bank format. Do not treat the missing-entry sentinel as a real mapped event.

**[binary] Emitter identity counterexample:** native allocator **`0xbf1558`** selects a pool slot, increments the counter at owner+`0x7000` (`0xbf15d8–0xbf15de`), calls `RegisterGameObj` at **`0xbf15ed`**, retries unless result is `1`, and stores that ID at slot+`0x10` (`0xbf1601`). The Wwise object ID is therefore demonstrably **not generally an EntityID**. SDK `audio/EntityEmitterSettings.hpp:19–29` also allows named emitters, named positions, decorators, keep-alive and per-position objects. **[hypothesis]** One entity can need several audio objects; world emitters can have no entity. A complete creation/assignment/teardown join to entity/component/world node was **not located**.

**Thread result [binary/hypothesis]:** PostEvent and RegisterGameObj execute synchronously on whichever thread called them and enqueue further work in the inspected bodies. The callers' Windows thread identities and downstream audio-worker affinity are **not established by static analysis**. Treat every native audio hook as potentially concurrent and real-time-sensitive; do not label it “game thread” or “audio thread” before recording thread IDs against a bridge update marker in game. No safe place to call RTTI/entity methods from those hooks has been established.

## 6. Bounded bridge design

**[hypothesis; proposed, not built]** Add one observation owner to the bridge's [recording service design](../research/runtime/autonomous-testing.md#tier-1--source-taps-and-a-rich-synchronised-session-recording). Start with the exported **three PostEvent entry/return hooks**, **one RegisterGameObj address**, **UnregisterGameObj** and **UnregisterAllGameObj**. This gives six physical detours. Optionally add **`0xa30324`** as a seventh hook to learn RED-name/ID pairs. These observe existing calls, preserving original arguments, callbacks, flags, cookies and return values. Do not add Wwise callback flags, play sounds, add objects or modify switches to obtain telemetry.

**[hypothesis]** Keep producer records independent: script-wrap `GameObject.PlayVoiceOver`, selected script sound helpers and bridge-owned sound commands; record the selected `DialogLineEvent` at the native consumer only after its complete handler ABI and lifetime are commissioned. Observe subtitle notifications separately. Publish `coverage: request`, `line_consumer`, `post`, `object_lifecycle`, or `subtitle`; never change a request into a “played” record. The initial post hooks can remain useful even when source attribution is `unknown`.

**[hypothesis]** Fixed-size native record: schema/channel, process/world generation, sequence, QPC source time, OS thread ID, entry call token, return-address RVA, event ID, audio object ID, flags, requested/returned playing IDs, external-source **count**, success/failure classification and loss counter. A name-overload record may include a strictly capped copied prefix only with a validated bounded pointer-read adapter; otherwise record `name_unread`, not a deferred raw pointer. Callback/cookie/source pointers are opaque original-call values; do not serialize addresses or dereference them. Register/unregister records carry ID, native result and lifetime generation. No RTTI, entity lookup, string pool, JSON, logging framework, filesystem or pipe call on the hook path.

**[hypothesis]** Entry/return correlation uses a small bounded per-thread stack/token. Overload identity prevents double counting: these overloads call a shared internal function, so do **not** simultaneously count that function as another post. Do not retain event/component/frame/source/name pointers past callback return. On normal bridge update, copy known live entity/component identities and resolve requested CNames in bounded batches; a background encoder handles only copied plain data. Match IDs with process/world/object generations and clear on load/detach. Failed/absent mappings stay explicit. No guessed offset may manufacture an entity association.

**[hypothesis] Cost budget:** a preallocated **4,096 × 128-byte** multi-producer queue uses **512 KiB**, plus a bounded name/object cache; at 1,000 records/s, record payload alone is about **125 KiB/s**. These are design arithmetic, **not measured rates or hook timings**. One consumer drains batches through the existing recorder; cap per-update name resolution (for example 32 misses), expose queue depth/high-water mark and per-channel drops. A full queue drops observations without blocking engine work.
