## 3. Road space: lane semantics are separate from walkability

### Lane classification and shape

**[source]** SDK `Scripting/Natives/Generated/world/TrafficSplineNodeUsage.hpp:12–16` distinguishes **Pavement=0** and **Road=1**. Authoring `TrafficSplineNode.hpp:26–41` carries usage, width, exits, lights, bidirectionality, traffic-disabled, no-AI-driving and no-autodrive switches. Cooked `TrafficLanePersistentFlags.hpp:12–31` names these independent bits:

| Bit | Meaning in the reflected lane enum |
|---|---|
| `0x0008` | Pavement |
| `0x0010` | Road |
| `0x0020` | Intersection |
| `0x0080` | TrafficDisabled |
| `0x0100` | CrossWalk |
| `0x0200` | GPSOnly |
| `0x2000` | NoAIDriving |
| `0x4000` | Highway |
| `0x8000` | NoAutodrive; the reflected signed enum spells it `-32768` |

**[source]** `TrafficLanePersistent.hpp:29–49` has `outline: [Vector3] +0x20`, accumulated lengths `+0x30`, road materials `+0x40`, `polygon: [Vector2] +0x50`, node-ref hash `+0x70`, length/width/area `+0x78/+0x7c/+0x80`, flags `+0x88`, lane number `+0x8c`, reversal `+0x90` and max speed `+0x91`; stride **`0xa0`**. `TrafficPersistentData.hpp:22–25` owns lanes at `+8` and neighbour groups at `+0x18`; `TrafficPersistentResource.hpp:21` embeds that data. These are concrete data-model fields, not a measured lane atlas or proof that every combination of flags occurs. A crosswalk must not be labelled safe from its flag alone.

### What the script traffic query actually tests

**[source]** `GameInstance.GetTrafficSystem` is declared at `orphans.script:11443`; `TrafficSystem` exposes **`IsPathIntersectingWithTraffic(path: [Vector4], distanceFromTraffic: Float, out intersection: Vector4) -> Bool`** and `FindEntitiesNearPlane` (`:50656–50660`). The latter is used to find entities near the plane of a thrown NPC (`cyberpunk/player/psm/carriedObject.script:1149`), so its name alone is not an all-nearby-vehicles reader or a time-to-collision result.

**[binary]** The path query's registration **`0x14cc2b4`** installs VM handler **`0x24288d8`**, which reads the three arguments and calls **`0xe12654`** at `0x24289cc`. That helper obtains the runtime traffic owner from interface **`+0x40`** and calls **`0xe126f4`**. Its filter requires **Road `0x10`** and excludes **TrafficDisabled/GPSOnly `0x280`** (`0xe12696–0xe126d1`); predicate **`0x252920`** checks required bits at filter `+6`, excluded bits at `+8`, against **lane flags `+0x88`** (`0x25292a–0x252945`). Thus this is not a query for every pedestrian/crosswalk lane.

**[binary]** Candidate gather **`0x197b04`** reads runtime **`+0x1d8`**, queries its spatial structure, resolves uint16 lane indices into a **`0xa0`-stride** array at data **`+8`**, applies that filter, and measures distance to the lane outline (`0x197bc2–0x197cbe`). The path routine supplies each lane's **polygon `+0x50` and outline `+0x20`** to **`0xe12934`** (`0xe128bf–0xe128de`). That function iterates polygon edges and tests them against path segments in XY, with an additional interpolated-position box test through **`0xe125e8 → 0x14d004`**. It is lane geometry, not a loop over moving vehicle bodies. A one-point path explicitly returns no intersection (`0xe12814–0xe1285e`).

**[hypothesis, constrained by binary]** Keep this result as **`road_boundary_intersection`**, with input path, tolerance and returned point. A point list wholly inside a road polygon need not cross an edge; false therefore cannot be promoted to **`V is off road`**, **`path avoids all lanes`** or **`no vehicle approaching`**. Do not use duplicate points as a point-containment hack. Exact `distanceFromTraffic`, height/tolerance and edge/corner behaviour still need commissioning; its name does not establish a horizontal safety margin.

### What can classify V, and what cannot

**[source]** `VehicleObject.IsOnPavement()` only returns the vehicle's cached `m_onPavement`, set by `OnPavement`/`OffPavement` (`core/gameplay/vehicles.script:1098–1107`). It is not V's sidewalk reader. `CrosswalkEvent` contains current/old traffic-light colours and distances (`orphans.script:32525–32533`); `ReactionManagerComponent.OnCrosswalkEvent` updates its crowd crosswalk state and asks the crowd movement component to reverse/jog when the light changes (`core/components/scriptComponents/reactionComponent.script:4986–5020`). No equivalent player crossing subscription or general crosswalk/light-at-point reader was located. SDK `world/TrafficLightDefinition.hpp:21–27` describes extent, group, timeline and position-on-lane, not a live signal getter.

**[source]** `PreventionSpawnSystem.GetNearestRoadFromPlayerInfo` returns `{pathLength, point}`; it also has `IsPlayerOnHighway` and `GetIntersectionInFrontOfPlayerPos` (`core/systems/preventionSpawnSystem.script:28–34`, `orphans.script:33543–33547`). Prevention uses the nearest road for fallback spawn distance and height checks (`preventionSystem.script:2631–2641`). That is useful diagnostic context, not lane containment. `AutoDriveSystem.CheckCurrentLaneValidity` serves its mounted-vehicle availability/enable flow (`autoDriveSystem.script:77–107,190–203`); no arbitrary on-foot point argument exists (`orphans.script:37321`). Do not borrow its `NotOnRoad` label for V on foot.

**[source/hypothesis]** Human-navmesh APIs return walkability/path data, not lane IDs or sidewalk categories (`core/systems/navigationSystem.script:4–18`; §5). The streamed-navmesh check's optional allowed/blocked masks have no sidewalk/road bit mapping established here. SDK `world/NavigationTileData.hpp:22–31` describes agent size, tile references and variants, not a script-readable sidewalk field. **Sidewalk navmesh classification was not located** in those declarations, character-aware navigation, SDK tile/config-area layouts or the scoped documentation search. Do not reuse traffic flag values as navmesh masks.

**[hypothesis] Proposed reader:** first commission a native, game-thread snapshot of nearby **all relevant lane flags and shapes**, independently of the road-only query's filter. Use the located runtime/data relationship only after owner, lock, streaming lifetime and world-generation validation; no arbitrary pipe-thread array walk. Copy bounded data with stable node/lane/reversal identity, coverage box and unavailable/truncated flags. Classify a capsule footprint against polygons with outline-derived height separation, preserving **overlapping road/crosswalk/pavement** memberships and edge distance; bridges/tunnels require vertical discrimination. No 2D-only safe label. A validated pavement point outside the expanded road envelope is a **candidate holding point**, still subject to physics clearance, dynamic vehicles and streaming checks.

**[hypothesis] Road-crossing contract:** combine classified start/finish holding volumes, path/clearance, nearby live vehicle transforms, velocities and extents, an explicitly measured prediction horizon, and the contact recorder in §4. Those dynamic readers and horizon are **not proven by this static trace**. Unknown lane coverage, a vehicle entering the horizon, stale observations or unavailable stopping room stops/refuses the crossing. Until commissioned, return `road_safety=unknown`; the bridge's navmesh snap cannot choose a proven safe roadside spot. Holding in traffic is a later explicit hazard fixture, not a default safe-placement policy.

## 4. Contact: positive car-hit evidence, incomplete no-contact proof

### The important player-specific callback

**[source]** **`PlayerPuppet.OnCarHitPlayer(evt: OnCarHitPlayer)`**, `cyberpunk/player/player.script:5776–5829`, is the direct player car-impact route. Event fields are **`hitDirection`, `carId`, `seperationImpulse`** (the game's spelling; `orphans.script:43532–43538`). SDK `game/OnCarHitPlayer.hpp:24–27` places them at **`+0x40`, `+0x60`, `+0x50`**, size `0x70`; native type registration **`0x168f67c–0x168f73c`** confirms `gameOnCarHitPlayer` and that size **[binary]**.

**[source]** The handler first refuses while VehicleKnockdown/BikeKnockdown is active, then refuses within **five seconds** of `m_vehicleKnockdownTimestamp` (`player.script:5786–5792`). After that it constructs `Attacks.CarHitPlayer`, queues a hit, applies a separation impulse if nonzero and plays `v_col_player_impact`. Critically, the constructed attack's **source and instigator are V herself**, while the actual vehicle is resolved later from **`evt.carId`** (`:5794–5809,5819`). A damage feed attributing this hit only by its attack source can misidentify it.

**[hypothesis]** Wrap this **script-bodied** callback and copy the event **at entry, before its early returns**, preserving original behaviour. Record callback receipt separately from whether downstream damage/reaction occurred; do not remove the cooldown. This catches delivered suppressed callbacks, but does not prove that native physics emits an event for every touch. Low-speed brushes, a stationary vehicle, active knockdown, mounted V and other controller/ragdoll paths remain counterexample fixtures.

**[hypothesis]** Reading this within an existing valid PSM callback is a bounded script probe. A retained `StateGameScriptInterface` is not an established safe global service handle. Hooking its getter only records when vanilla asks, which is insufficient for every-frame coverage. A production contact recorder must commission the underlying report producer/update and identity association, or another complete physics contact boundary, across all selected benchmark states. No safe complete native contact producer/vehicle-association tap was established by the inspected event registrations, report copier, SDK and script consumers. Leave that capability unavailable.

**[hypothesis] Proof contract:** define the benchmark precisely as **no vehicle-body contact**, including zero-damage contacts; supporting ground is expected. Preserve broader non-ground contacts separately. Latch every positive event for the run; do not sample a last-hit bool between agent turns. Return `vehicle_hit_observed`, `vehicle_contact_observed`, `other_contact`, and `coverage` separately. Only **continuous, validated coverage of the relevant physics paths**, with no overflow/gap/load or identity loss, can support a negative. Otherwise the result is **INCONCLUSIVE**, even with unchanged health and a clean trajectory. Invulnerability, collision disabling, teleport corrections or damage suppression cannot be used to pass this benchmark.

## 5. Player-aware path queries and following

**[source]** Human navigation is directly exposed: `GameInstance.GetNavigationSystem`, `CalculatePathOnlyHumanNavmesh`, `FindPointInSphereOnlyHumanNavmesh`, `FindWallInLineOnlyHumanNavmesh`, streamed-location check and owned obstacle add/remove (`core/systems/navigationSystem.script:4–22`). Check the point/wall **status**, not just a vector or `isHit`: statuses are OK/InvalidStartingPosition/InvalidEndPosition/OtherError (SDK `world/NavigationRequestStatus.hpp:12–18`). `NavigationPath.path` and `CalculateLength` are declared at `orphans.script:29743–29747`; require a defined, nonempty, finite path and validate the endpoint against the intended volume. Nearby navmesh is not PSM grounded state; use `PlayerStateMachine.IsOnGround` for that ([player control](player-control.md#what-the-bridge-builds-on-06-to-08)).

**[source]** The more actor-aware route is **`GameInstance.GetAINavigationSystem(game)`** (`orphans.script:11497`) → **`CalculatePathForCharacter(start,end,tolerance,owner=V)`**, `FindWallInLineForCharacter`, `FindPointInSphereForCharacter` / `FindPointInBoxForCharacter` (`cyberpunk/ai/aiNavigationSystem.script:4–16`). Their owner parameter is `Entity`; the declarations do not restrict it to NPCs. **[hypothesis]** V's actual agent settings and valid ownership in each PSM state still need commissioning; a callable signature alone is not a successful V fixture.

**[source]** The same system offers **`StartPathfinding(query) -> Uint32`, `GetResult(id,result) -> Bool`, `StopPathfinding(id)`**. Query fields are source/target `AIPositionSpec` and allowed/blocked CName tags (`orphans.script:29725–29733`); results include `hasFailed`, `hasPath`, closest-navmesh/reachable-point flags and source/target positions (`:29752–29768`). This result contains **reachability information, not a waypoint array**. The corpus's `ExampleNavigationTask` starts a query on activation and stops its owned query on deactivation (`aiNavigationSystem.script:264–290`). Retain only the owned ID, check result availability and cancel on supersession/detach; no sidewalk tag vocabulary was established here.

**[source]** The script AI path-condition consumer populates `query.allowedTags` from **`AllowedOffMeshTags()`**, then performs **separate** dynamic-obstacle and straight-path checks (`core/ai/actions/tweakAIConditionChecks.script:1324–1410`). Its dynamic check casts the owner to `NPCPuppet` and calls `GetInfluenceComponent().IsLineEmpty`; that component also exposes `IsPositionEmpty` (`orphans.script:26383–26391`, `cyberpunk/NPC/NPCPuppet.script:3819–3821`). `gameinfluenceTestLineResult` includes **Unknown** as well as Fail/Success (`orphans.script:85–89`). This is another NPC occupancy lead, not proof that a navmesh path is free of moving obstacles or that V has a usable influence component. The observed tag use concerns off-mesh links; it does not establish sidewalk-area filtering.

**[source]** NPC movement commands are a separate execution layer. `AIComponent.SendCommand/GetCommandState/CancelCommand/StopExecutingCommand` (`core/components/aiComponent.script:14–34`) feeds behaviour handlers: `AIMoveToCommandHandler.UpdateCommand` writes movement/facing/navigation/start/stop/distance mappings into a **behaviour execution context** (`cyberpunk/ai/commands/aiMoveToCommandHandler.script:26–88`). The [NPC direction](npc-direction.md#3-ai-commands) command list is not proof V has that running behaviour graph. V inherits component discovery, but a component/type existing does not make its NPC move handler active for the player. **No proven script/RED4ext command that makes V follow this path through ordinary locomotion was located** in the inspected player/PSM, AI command and navigation surfaces.

**[source/hypothesis]** The located ordinary player route is mapped **`MoveX/MoveY` input → player PSM → native locomotion** (`cyberpunk/player/psm/defaultTransition.script:587–588,639`; [input research](input-and-choices.md#5-r1-general-input-dispatch-and-native-hook-points)). `AdjustTransformWithDurations` is a real PSM alignment/nudge request (`defaultTransition.script:319–340`), but is not a located path follower. The existing bridge glide uses teleports while holding NoMovement (`projects/xf-runtime-bridge/redscript/XFRuntimeBridgePlayer.reds:239–267,356–380`); it remains a labelled setup shortcut and cannot validate walking or contact avoidance.

**[source]** Obstacle surfaces: nav-wall queries test navigation boundaries; `SpatialQueriesSystem.Overlap/OverlapByQueryFilter` and ray variants are general system calls (`orphans.script:27637–27647`). **Sweeps**, multi-hit rays and locomotion-specific overlaps/sweeps are on `StateGameScriptInterface` (`:42468–42498`), not an established free-standing bridge handle. V also has `PlayerObstacleSystem.GetCurrentClimbInfo/GetSlopeInfo/GetCoverDirection` (`:46134–46156`). Query-filter membership, self-exclusion, dynamic-body coverage and timing limits remain as documented in [R4](hud-and-occlusion.md#5-collision-and-visibility-queries); a clear centre ray is not capsule clearance.

**[hypothesis] Minimal follower:** local deterministic waypoint steering with measured camera/body basis, bounded input pulses and explicit neutralisation; no frame-by-frame LLM control. ## 6. Hostile targets and who perceives V

**[source]** Read **directed live attitude** with `GameObject.GetAttitudeTowards(observer,V)` / attitude agents, not affiliation or gang name (`core/entity/gameObject.script:451–478`). Missing objects/agents return **Neutral**, so preserve `attitude_available` independently; null is not evidence of friendliness. The [population](population-and-affiliations.md#5-faction-affiliation-and-district-records) records describe default groups and affiliations, not a complete current hostility result.

**[source]** V's `GetTargetTrackerComponent().GetHostileThreats(false/true)` reads **V's own tracker**. To find actors tracking V, use the inverse **`V.GetTargetTrackerComponent().CollectTrackers(true,false)`** (`orphans.script:24492`): `SenseComponent` uses this exact route, then reads each tracker's `TrackedLocation` for V (`core/components/senseComponent.script:668–679`). Query each observer through `ThreatFromEntity(V,out location)` or `TargetTrackingExtension.GetTrackedLocation(observer,V,...)` (`targetTrackingComponent.script:411–416`). `onlyInContact` is a tracker API parameter; it is **not physics contact**.

**[source]** `TrackedLocation` holds local/shared current and last-known positions/directions, entity, speed, accuracy/shared accuracy/delay, threat, **visible**, invalid expectation and tracked status (`orphans.script:25672–25698`). Preserve those as distinct knowledge states; a last-known/shared location is not a fresh view of V. `GetHostileThreats(onlyVisible)` and `GetTopHostileThreat` filter the selected tracker's list (`:24418–24424`). Absence from that list cannot rule out a newly streamed or not-yet-detecting hostile.

**[source]** For each valid NPC observer, **`GetSenses().IsAgentVisible(V)`**, **`GetDetection(V.GetEntityID())`**, `GetTimeSinceLastEntityVisible`, `GetVisibilityTraceEndToAgentDist`, current preset and sense shapes are available (`core/components/senseComponent.script:47–69,109`). Vanilla explicitly uses the NPC→V visibility direction to assess dodging out of sight (`cyberpunk/player/player.script:844–851`). `SenseManager.IsObjectVisible(observerID,V_ID)` / `IsPositionVisible` are additional system queries (`orphans.script:27742–27746`), with R4's filter/renderer limits. Detection scale, stale/LOD behaviour, smoke/camo and differences between these predicates need fixture checks; do not silently normalise detection to a percentage.

**[source]** `SenseComponent.OnSenseVisibilityEvent` receives target, visible flag, shape ID and description (`senseComponent.script:447–456`; event at `orphans.script:24394–24402`), and routes V entering/leaving perception. It has a script body and can be wrapped. In contrast `OnDetectedEvent` is declared without a script body (`senseComponent.script:547`); it is not a general native tap through `@wrapMethod`. Likewise the public native sense/tracker getters require a native detour to observe all engine calls, if that later becomes necessary ([native-wrap limit](game-events.md#wrapping-a-native-method)).

**[source]** `PlayerPuppet.OnStartedBeingTrackedAsHostile/OnStoppedBeingTrackedAsHostile` (`player.script:6230–6236`) feed a **boolean** in `playerCombatController.script:168–176`. Their declared events carry no tracker-entity field (`orphans.script:50226–50230`). They are useful aggregate transitions, not a located per-hostile identity stream. `UI_Stealth.numberOfCombatants` is another aggregate; it cannot name who sees V.

**[hypothesis] Bounded awareness snapshot:** union inverse trackers with nearby streamed NPCs/known fixture entities, keeping source and coverage for each. `GameObject.GetNPCsAroundObject(range)` enumerates filtered nearby NPCs (`gameObject.script:715–731`); that does not exhaust cameras, turrets, remote netrunners or unstreamed police. Return per-actor directed attitude, alive/active/type, tracker knowledge and observer visibility/detection with source time/age. Report missing components and truncated lists. AI perception, a muzzle ray, and what the current camera renders are separate results. Never turn “no listed watcher” into “nobody can see V”.

## 7. Cover for NPCs and cover for V

**[source]** NPC selection has a native **`AICoverSelectionSystem`** (SDK `AI/CoverSelectionSystem.hpp:15–23`) and native **`AIbehaviorSelectCoverTaskDefinition`** with cover/ID/multi-cover, combat/friendly target, combat zone, selection/initial/second-stage presets and change threshold (`AI/behavior/SelectCoverTaskDefinition.hpp:26–40`). `CoverSelectionPreset_Record` exposes gather radius, combat ring, Filtering/Scoring/PostFiltering lists, dismissed-cover timer and UsesLineOfSight (`orphans.script:60186–60221`). Named parameter classes include distance/angle, health, cover type, path length/security, line of sight and separation from others (`:59978–60000,60181–60184,61967–61991`). These locate the selection machinery and tuning vocabulary; the native gather algorithm, exact score aggregation and safe standalone invocation ABI were **not located**. SDK `AI/CoverScoringData.hpp:17–21` leaves its storage opaque.

**[source]** Once a candidate **cover ID** exists, `GameInstance.GetCoverManager` provides validity/availability, position/forward/up/height/health, horizontal protection against an object, threats not protected from, usable exposure methods against a target and current occupant cover (`orphans.script:25740–25796`). `AICoverHelper` reads the AI cover blackboard, stance/exposure methods and currently-exposed flag; its occupancy checks distinguish regular cover from shooting spots (`core/ai/covers/aiCoverHelper.script:80–93,128–145,176–219`). `MultiSelectCovers` stores selected IDs/ring types/LOS use/preset names (`orphans.script:30525–30533`). These are useful AI outputs, not a general enumerate-all-cover-points API.

**[source]** `AIMoveToCoverCommand` and `AIUseCoverCommand` resolve a demanded node through `CoverManager.GetDemandCoverHolder`, validate its ID and write behaviour cover arguments (`cyberpunk/ai/commands/aiMoveToCoverCommand.script:35–61`, `aiUseCoverCommand.script:35–62`). They rely on NPC behaviour execution, like the move handler in §5. A registered cover occupant is not proof that V's physical body is protected or peeking successfully.

**[source] V has a separate readable auto-cover route.** `SpatialQueriesSystem.GetPlayerObstacleSystem().GetCoverDirection(V)` returns **None/Up/Left/Right** (`orphans.script:27633,46152,10317–10322`). `ActivateCoverEvents` enables auto-cover; while active it sets **`PlayerStateMachine.UsingCover`** from `direction != None`, and clears it on normal/forced exit (`cyberpunk/player/psm/coverActionTransitions.script:134–157`). `CoverAction.coverActionStateId` is written separately: inactive **0**, activation **1** (`:99–123,139–140`). Activation alone is not actual cover use. Peek eligibility depends on aim/vision/gadget/scene/mount/slide states (`:35–75`). This is script-readable without inventing an NPC cover ID for V.

**[hypothesis]** Initial one-target testing should only **read** V's cover direction/state and use independently validated clearance/line-of-fire. Candidate search for V stays unavailable until native selection/gather semantics or a validated geometric alternative is commissioned. Do not invoke `RegisterCoverOccupant`, write the blackboard, or call `OnAutoCoverActivation` as a substitute for ordinary approach/aim behaviour in a cover benchmark. A cover ID or true UsingCover is not a guarantee of protection from every hostile angle/projectile.

## 8. Weapon readiness, aim, reload and fire

**[source]** Resolve V's actual **held weapon**, not only the equipment inventory: vanilla uses `TransactionSystem.GetItemInSlot(V,t"AttachmentSlots.WeaponRight") as WeaponObject` (`cyberpunk/player/player.script:4023`). **[source]** Aim state is **`PlayerStateMachine.UpperBody=6`**, written by `AimingStateEvents` (`cyberpunk/player/psm/upperBodyTransitions.script:1326`); CameraAim input and interruption/gating drive entry (`:919,1112` onwards). `TargetingSystem.LookAt(V,AimRequest)` turns the camera and can be bounded/cancelled ([player control §3](player-control.md#3-the-camera), `orphans.script:22412–22422,26044–26088`). **[source]** The ordinary fire/reload route is **mapped `RangedAttack`/`Reload` input → PSM**.
