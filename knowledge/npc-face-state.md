# NPC face state: submitted features, graph inputs and evaluated output

**Maturity: Draft.** Static R3 research for **Cyberpunk 2077 2.31**, 24 October 2026. **[source/binary]** The submission → animation-controller event → keyed feature store → bound animated component → typed graph-input write path is located. **[binary]** This supplies a candidate observation of an **applied graph input**, later than command acceptance. **[hypothesis]** It is not yet a commissioned reader. No safe final-face, eye-bone, blend-weight or active-clip reader was established; keep those capabilities unavailable and cross-check with calibrated face crops. A graph can retain smile inputs without its final output looking like a smile.

Grades: **[source]** inspected decompiled game scripts, framework/bridge source or an explicitly identified session report; **[binary]** executable instructions/RTTI with RVA; **[resource]** existing extracted game data; **[wiki]** pinned Modding Docs; **[hypothesis]** inference or proposed work requiring commissioning. A session report is evidence of what was reported, not a new observation of the running game. This supplements [NPC direction](npc-direction.md), [facial expressions](facial-expressions.md), [facial animation](facial-animation.md), [body animation](body-animation.md) and [lip sync](lipsync.md).

## 3. Submission to controller to graph storage

### The script call queues an event

**[source]** `core/components/animationControllerComponent.script:30–45` constructs `AnimInputSetterAnimFeature`, assigns `key`, `value`, `delay`, and calls `obj.QueueEvent`. Item objects additionally forward it to child items. `ApplyFeatureToReplicate` calls this producer and separately `obj.ReplicateAnimFeature`; replication is not an acknowledgement of rendering. `ScriptedPuppet.GetAnimationControllerComponent` returns the cached controller (`cyberpunk/puppet/scriptedPuppet.script:1106–1108`).

**[source]** `AnimFeature_FacialReaction` is two Int32 properties, `category` and `idle` (`orphans.script:32382–32387`). The event's script declaration is `:18963–18969`; SDK `ent/AnimInputSetterAnimFeature.hpp:19–29` places `delay +0x48`, the feature handle `+0x50`, size `0x60`, and its inherited key is `+0x40`. Recording the producer says only what was queued. A delayed request may arrive later; this research did not establish the dispatcher's delay semantics.

**[source]** A native method cannot be made a general engine tap with `@wrapMethod`; see the [native-wrap limit](game-events.md#wrapping-a-native-method). Wrapping the static script producer is valid but misses direct native submissions. The private native `ApplyFeature` method and the static script overload are distinct routes.

### Located native boundaries

**[binary]** The controller's event registration **`0xfc19d4`** reads the `entAnimInputSetterAnimFeature` descriptor slot **`0x342db30`** at `0xfc1a2d`, registers consumer **`0x931fd0`** at `0xfc1a45–0xfc1a57`. The descriptor's type/size are registered at **`0x16fa390`**, name at `0x16fa3df`, size `0x60` at `0x16fa3fc–0x16fa400`. The consumer reads `event+0x50/+0x58`, loads its key at `+0x40`, then calls **`0x2e0e3c`** at `0x931ff7`. Entry arguments are **RCX=animation controller, RDX=event**; the full handler return contract was not established.

**[binary]** The separate native VM method is registered from **`0x1875298`**: name `ApplyFeature` at `0x18752a1`, wrapper **`0x240c218`** installed at `0x18752e8–0x1875306`. The wrapper reads two VM arguments and calls the same **`0x2e0e3c`** at `0x240c2ab`. Prefer observing the common setter/event route; do not consume a VM frame twice. SDK `Scripting/Functions.hpp:93` supplies the VM handler ABI, as in [R2](game-audio.md#3-script-requests-and-native-engine-dispatch).

**[binary]** Common setter **`0x2e0e3c`** receives **RCX=controller, RDX=key CName value, R8=feature-handle address**. It locks at controller `+0x1db`, rejects a null feature or zero key, obtains/creates a reference-counted store at controller `+0xc8/+0xd0` through **`0x2e0d88`**, and calls **`0x2e0ec0`**. The store walks **24-byte entries** in its `+0x70` array (count `+0x7c`), compares the CName and replaces the handle at entry `+8`, or appends a new entry (`0x2e0ed0–0x2e0f28`). `controller+0x1d8` marks pending handoff. These internal offsets are evidence on this executable, not an SDK-supported snapshot ABI. Holding a feature handle also does not make its mutable fields an immutable historical record; copy the scalar values at observation time.

**[source/binary]** The handoff follows **animation-control attachments**. SDK `entIComponent.hpp:25–35` describes the attachments array at `+0x70`, and `ent/IAttachment.hpp:21–25` the source/destination weak handles. Controller update **`0x2e125c`** updates its look-at and IK controllers, then calls **`0x2e142c`** at `0x2e1284`. That function checks pending state, finds `entAnimationControlAttachment` destinations, and passes the store to **`0x2e09d4`** at `0x2e150b`; it clears the pending marker at `0x2e1542`. The destination is checked as `entAnimatedComponent` by **`0x2e0bec`** (descriptor **`0x342df98`**, registered at `0x16f3af8`). Handoff installs a shared store reference at an internal runtime object's `+0x2590` (`0x2e09ed–0x2e0a42`) and follows further animation-control attachments. A receipt on one controller therefore does not by itself name the face graph that consumed it.

**[binary]** Later consumer **`0x328d0c`** walks that store's features at **`0x328ece–0x328f28`**, calling **`0x32a020`** with **RCX=graph resource, RDX=instance storage context, R8=key, R9=feature object**. It also visits additional graph contexts through **`0x329f68`**; preserve graph/instance identity, not just actor plus key. `0x32a020` matches the graph's declared feature name/class at `graph+0xd8` and recursively enumerates the feature's reflected properties through **`0x339d50`**. Missing name/class/property can skip the write. Its boolean return is not proof that every property matched.

**[binary]** Property lookup **`0x339e04`**, called at `0x339da7`, keys on **feature-group name and property name**, returning a native variable descriptor. **`0x339f0c`** dispatches by descriptor type; type **4** selects the **Int32 writer `0x3cf550`** (`0x339f63–0x339f6d`). That writer validates the reflected property's type, obtains its value, and writes **`*(uint32*)(context.data + descriptor.offset)`** at **`0x3cf5b9–0x3cf5c0`**, returning `AL=1`; a mismatch returns zero at `0x3cf5db`. Its cold type-name initialization at **`0x1e77373`** says `Int32`. The Float branch uses **`0x33a04c`**, write **`0x33a0ba`**. This is a concrete **applied-input** boundary. No script getter or safe stand-alone call into these helpers was established.

**[hypothesis]** A bounded observation inside the original typed-write call can copy the two facial integers after a successful write. It must first establish actor/component/graph/instance lifetime and the hook's runtime thread; do not walk unknown buffers from the pipe thread. None of the instance offsets above establishes a safe after-evaluation pose buffer or a cross-frame pointer lifetime.

## 4. What the graph can show instead

**[resource]** The existing vanilla `woman_average_sermo.animgraph.json` declares `FacialReaction` (`:168–180`). In the **Reactions** state, `AnimDatabase` handle **278** reads `category`/`idle` through handles **279/280**, loops, and references **`facial_reactions_male.csv`** (`:12950–13095`). The female-named graph really contains that male table reference; do not silently substitute the female table. The existing male CR2W table and female JSON agree on the relevant pairs: **3/1 anger, 3/5 joy, 3/6 happy, 2/2 neutral** (female JSON `:71–112`; male table rows keyed by Category/Idle). “Smile” is the bridge/community label for 3/6, not the name of a final blend state or a strength.

**[resource]** Conditional entry **71** selects Reactions when `category > 0` (`:2108–2125`). Transition **304** enters Reactions over **0.6 s**, condition **305** is `category > 0`; **307** returns to Idle over **0.5 s** when condition **308** is `category == 0` (`:13648–13741`). The surrounding state machines also have action, shooting/reload, hurt, death and ragdoll routes. These graph declarations make competing routes and transitions concrete; their runtime priority for the session actor is not established here.

**[resource]** The reaction clip is upstream of the facial mixer, facial look-at/constraints and two `EyesTracksLookAt` nodes, with **Sermo** at the output (`woman_average_sermo.animgraph.json:275` onwards, handles **2/3/4/26/34**). The eye nodes write named direction tracks from look-at bones. The **FacialMixerSlot**, handle **34**, holds the gaze-change blink definitions; the controller's requested target is therefore not an eye orientation. Sermo and the facial setup then turn mixed tracks into facial joint motion; [facial animation](facial-animation.md#1-from-control-values-to-moving-bones) and [lip sync](lipsync.md#3-how-the-face-combines-an-expression-with-speech) describe the resource/solver evidence and its limits.

**[source/hypothesis]** A readable Int32 graph input would distinguish “request never reached this instance” from “this instance retained smile inputs while its output differed.” It cannot distinguish a disabled/inactive reaction branch, clip streaming/fallback, competing mixer content, reduced envelope, another facial setup or a rendered smile that simply reads poorly. Those need post-evaluation evidence or the crop cross-check; do not pick a cause from input telemetry alone.

## 5. Head, eyes, locomotion and tempting false readers

**[source]** Codeware `scripts/Entity/Entity.reds:1–8` provides component enumeration. `scripts/Base/Addons/AnimatedComponent.reds:1–44` exposes graph/rig/sets, facial setup and LOD/visibility configuration; `AnimationControllerComponent.reds:1–8` exposes database references and control binding. SDK `ent/AnimatedComponent.hpp:35–57` leaves internal regions untyped. These are good identity/capability readings, not evaluated tracks. `animParameters` contains track/parameter names and a **defaultValue**, not live samples (`ent/AnimTrackParameter.hpp:18–27`). `animAnimFeatureEntry` contains name/class/forceAllocate (`anim/AnimFeatureEntry.hpp:16–26`), not the last feature object.

**[source]** Head/chest are partly reachable already: `ScriptedPuppet.GetSlotComponent` (`cyberpunk/puppet/scriptedPuppet.script:1066–1068`), native `SlotComponent.GetSlotTransform` (`orphans.script:21657–21660`). The bridge uses **Head position only**, falling back to entity position +1.62 m and marking `head_slot=false` (`redscript/XFRuntimeBridgeScene.reds:103–118`). A probe should preserve the full successful transform and binding identity. SDK/Codeware expose slot definitions, but an absent eye slot cannot be invented by passing an arbitrary bone name. No safe general eye-bone/eyelid transform getter was found.

**[source/binary]** Do not confuse input targets with results: the SDK's controller look-at data holds request references and position providers (`entAnimationControllerComponent.hpp:46–83`). Requested head/chest weights and the bridge's separate Eyes request (`XFRuntimeBridgeNpc.reds:1130–1165`) do not read the post-constraint head or eye orientation. The graph-input write route above may observe relevant properties when a particular graph declares them, but eye-direction tracks generated inside the graph bypass feature submission telemetry.

**[source/hypothesis]** Locomotion has the same distinction. The bridge builds AI move/follow commands, not a final gait pose. `cyberpunk/ai/commands/aiMoveToCommandHandler.script:317–324` converts a facing target into strafing when requested, while `:47–51` writes a supplied facing target into the behaviour argument; it is not an animation-output getter. SDK `anim/AnimFeature_Locomotion.hpp:17–36` describes native action/style/speed-progress inputs, and `AnimFeature_CrowdLocomotion.hpp:17–26` crowd speed/slope inputs; neither identifies the final contributing clip. The common native feature tap can cover native producers, but no exhaustive locomotion-to-clip reader was located. Keep measured displacement, entity forward/yaw and command outcome separate from `evaluated_gait` (unavailable); a head turned toward V does not prove backward body motion.

**[source/binary]** Debugger names are leads, not a usable retail debugger: SDK `anim/AnimGraphDebugState.hpp:18–25` and Codeware's corresponding import expose a nodes array; `AnimNodeDebugState.hpp:18–26` offers node ID/active only. `AnimDebuggerCommand_WeightChanges.hpp:15–22` leaves its payload opaque; its RTTI registration is **`0x1792b7c`**. `PoseInfoLogger.hpp:19–31` describes logging configuration, and Codeware's `animSermoTestController.reds` is a struct of control fields, not an actor getter. No attach/read API, per-actor producer, retail recording buffer, thread/lifetime contract or post-Sermo hook was established for these. Do not enable logging or mutate shared graph resources to manufacture a reader during a running session.

## 6. Session 17: explanation and discriminating probe

**[source: recorded report]** [Session 17's NPC-direction account](npc-direction.md#10-session-17-on-bridge-0810-23-october-2026) records an almost-scowling actor despite smile sent **0.07 s after spawn**, and joy **19 s later**. It reports suppressed expression-check/reset/look-at paths but no recorded `TriggerFacialLookAtReaction` scowl request. That constrains the instrumented producers; it does **not** rule out every native submission, graph route or mixer contribution. The [survey's N3 row](../research/runtime/autonomous-testing.md#session-17-13-card-rows) correctly treats the held-face string as insufficient.

**[hypothesis]** The defensible explanation is **a gap between submitted intent and final output**, with the cause still unresolved. Early delivery before the bound graph existed, a subsequent reset/write, an unapplied property, a different winning graph/clip, a graph transition or later blending all remain candidates. There is no evidence that locomotion specifically clears this feature. A successful late resend would narrow the problem but would not by itself prove a loading race.

**[source]** In particular, bridge **`prepared` is not animation readiness**. `XFRuntimeBridgeNpc.reds:889–908` sets attitude and optional immortality and then sets that flag; it does not test graph loading, feature installation or evaluation. The existing scheduled resend (`native/src/core/Npc.cpp:2697–2707`) and its first-six-send log (`XFRuntimeBridgeNpc.reds:1190–1196`) are useful submission evidence but cannot say an early send was lost.

**[hypothesis: proposed bridge probe, no implementation]** Keep one owner beside the NPC recorder, opt-in and bounded to the selected nearby actor. Record these stages independently, joined by world generation, actor/component generation, request sequence and monotonic time:

1. **Submitted:** immutable feature name/type/category/idle, source (XF, known script producer, unknown native), queue time/delay, reset/resend reason and the bridge's existing `prepared` flag with its actual meaning.
2. **Controller received/stored:** tap `0x931fd0` and/or common `0x2e0e3c`, validate owner/feature type, copy the scalars in-call; entry/return-pair the setter. A wrapper exit alone does not establish graph delivery.
3. **Graph input applied:** carry scoped context from `0x32a020` (graph resource, instance storage context, key, feature), observe the Int32 branch of `0x339f0c`/`0x3cf550`, and copy `category`/`idle` only after a successful typed write. Validate the reflected property type, descriptor, destination allocation and owning generation before dereferencing. `AL=1` here means a property was written, including an unchanged value; the aggregate parent boolean is not an all-properties acknowledgement. Count each property separately and report missing/skipped writes. Observe additional graph contexts without conflating them with `face_rig`.
4. **Evaluated:** `available=false, reason=post_evaluation_reader_unlocated` for controls/bones/weights/clips. Head slot transforms, sampled entity motion and **rendered crop analysis** are separate observations, never substituted into that field. Clear applied-input knowledge on graph/appearance replacement, detach, load, hook loss or unobserved writers; do not keep a stale “smile” after an instance changes.

**[hypothesis]** Commission native taps on the pinned executable first: original call exactly once, unchanged arguments/return, no guessed function calls, thread IDs, re-entrancy-safe scoped context, no script/RTTI allocations or JSON inside the hook. Native callers may bypass the event or use different paths. Whitelist the actor on the game thread using supported lifetime handles; drain a fixed-capacity numeric ring outside the callback. Store copied values, not borrowed pointers, in the ring. Drop counters, unknown owner, overflow and stale joins force **INCONCLUSIVE**. Stop and unregister with the recorder; do not retain pointers across loads. A script-only first version should explicitly advertise `coverage=script_submissions`, retaining captures until the native boundaries are commissioned.

**[hypothesis]** Publish the native result as `last_observed_graph_input` with observation time, age and coverage, not a timeless current face. An observed write is historical evidence; absence of another observed write cannot exclude an uncovered setter, graph reinitialisation or direct native buffer change. No safe polling snapshot of all current graph inputs was commissioned by this research, and input application does not establish which evaluation frame consumed it.

**[hypothesis]** Run one controlled comparison: neutral → 3/6 happy → neutral → 3/5 joy, first standing, then turning/walking, then at the question. Compare a send at spawn against one after a stable graph/component identity; include a deliberately overwritten/reset face as a negative control. If there is no controller receipt, investigate queue/lifetime; receipt without a facial graph property write points to bindings/graph eligibility; both properties applied but a bad crop points downstream. Do not force all these outcomes into one boolean `face_applied`.

### Calibrated visual cross-check

**[hypothesis]** Use the same actor, appearance, camera/lens, head pose, distance and controlled light. Save neutral/happy/joy/anger baselines **labelled by the maintainer from the rendered crops**, not automatically from the command's requested face, and a brief time series covering the **0.6 s** resource transition plus settled output; declare the actual sampling/settling budget and measure it in the session. Record graph/rig/setup identities with the crop. Fix exposure, reject occlusion, profile views, motion blur or too-small faces, and keep raw images private. Head slots are framing anchors, not facial landmarks.

**[hypothesis]** Measure within-actor mouth-corner/eye-aperture deltas, optionally MediaPipe blendshape deltas as proposed by the [autonomous-testing plan](../research/runtime/autonomous-testing.md#research-list-locate-the-system-before-choosing-a-fallback). Calibrate on labelled rendered game faces, hold out actors/lighting and include false positives. A real-face model's label is not a game-engine state or a measure of warmth. Until calibration passes, an agent can report an image difference with confidence/quality limits, while a human decides whether it reads as the intended smile. Gaze needs its own left/right/up/down targets and eye close-ups; do not infer it from the target request or a smile score.
