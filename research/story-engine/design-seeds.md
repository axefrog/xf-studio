# Design seeds

Fine-grained design points that come up before the plan reaches their level. Each one waits here until a second-level plan absorbs it. That plan then owns the point, and the entry here links to where it went. Add a seed whenever one comes up. Plans are named in the [first-level plan](plan.md#5-second-level-plans).

Status: **waiting** (not yet absorbed), **anchored** (absorbed by a written plan, with a link), **resolved** (designed or decided), **dropped** (with the reason).

| DS-42 | **Author priorities per field:** fixed, preferred (with a strength) or open, plus intent notes (tone, theme, what it should feel like) and fallbacks for when the window closes. Intent notes are partly structured, using the composite's terms, so fitting can act on them | P4, P6 | waiting |
| DS-43 | **The fit report and pinning.** The author previews how a seed would fit across sample story states (several saves, several Vs): when and where it triggers, and what was filled in. They pin what they like as fixed and reject what they don't. Vague becomes precise step by step, only where the author cares | P6, P10 | waiting |
| DS-44 | **Windows on the game's own story.** Authored seeds name story-state windows ("after the parade", "while he's alive and allied") in terms of the game's facts and phases. This needs a map of the main story's progression, from P2's corpus | P2, P4 | waiting |
| DS-45 | **Say early what can't be expressed.** At authoring time, flag anything the runtime can't do, such as new voiced lines for a vanilla character (no cloning: reuse, text, or a consenting performer), intimate scenes needing new animation, or interplay with vanilla romance state | P6, P8 | waiting |
| DS-46 | **One engine, three game ports.** The engine reaches the game only through a game-port interface. There are three implementations: a simulated game (offline prototype and tests), the external link (host-side, H1), and the companion link that XF Core opens when it launches the engine (H2, H6). Each port reports what it can do, so the same seeds run in all three | P7, [requirements](runtime-requirements.md) | waiting |
| DS-47 | **The world as sampled fields over dimensions.** A domain of concern is a bundle of dimensions: geography, the built environment (building, floor, street), organisations, weather, time, people, and so on. Domains relate to each other through maps (a building projects to its district; a person embeds at a home). Each dimension's content is a field: a set of constants, a graph, a vector field, or control points with falloff. Sampling at a locality (a point or region across the dimensions) returns what is there, with every condition and context a seed can anchor to. The same idea as a voxel engine sampling a density function, with only sampled places ever materialised | P3 | waiting |
| DS-48 | **Canon is a sparse layer of changes over a procedural base,** as voxel worlds store only player edits over terrain regenerated from a seed. The base is a pure function of seed, locality and inputs, so anything unchanged can be dropped and regenerated identically. Only canon, observed facts and committed seeds are stored (sharpens [DS-04](design-seeds.md)) | P3 | waiting |
| DS-49 | **Casting is a level-set query.** A seed's constraints ("private, Tyger Claw influence above 0.6, night, little police") define a region of the space, found the way marching cubes finds a surface. Each field supplies conservative bounds per region at each level of detail, so a search prunes whole districts at once, like empty-space skipping | P3, P4 | waiting |
| DS-50 | **Changing level of detail converts between fields and individuals.** Coarse levels hold aggregates (densities, flows, pressures); fine levels hold individuals. As V arrives, fields spawn individuals consistent with them (as many gang members as the influence implies). As V leaves, anonymous individuals dissolve back into the field, while anyone who has become canon stays an individual | P3 | waiting |
| DS-51 | **Applied category theory as a lens, not a framework.** Ologs (categorical knowledge representation), categorical databases, and sheaf-style consistency (local views must agree where they overlap, and with the coarser view) give a vocabulary for domains, maps between them and consistent refinement. Implement a small set of dimension types and operators (project, embed, aggregate, derive); use the theory to check the design. Also a candidate form for P1's composite | P1, P3 | waiting |
| DS-52 | **The engine ships as a companion process** that XF Core launches through the plugin system: frictionless for the player, crash-isolated from the game, with the full desktop runtime of the host-side route ([requirements H6](runtime-requirements.md)) | P7 | waiting |
