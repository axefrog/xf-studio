# CCXL merge boundary and character-creator ownership

Source check: 23 September 2026. This note maps the customization mechanism relevant to XF Studio's one-selector eye-makeup collection. It is source and resource research, not a claim of successful game rendering or save behavior.

## What CCXL owns

“CCXL” is the character-customization feature of [ArchiveXL](https://github.com/psiberx/cp2077-archive-xl/tree/5474e34d56112f5d8843ae863e1e72ff510957c0), not a separate scripting language or the entire creator UI. The inspected checkout is ArchiveXL **1.27.3**, commit `5474e34d56112f5d8843ae863e1e72ff510957c0`, matching the [stable release](https://github.com/psiberx/cp2077-archive-xl/releases/tag/v1.27.3). `src/App/Extensions/Customization/Extension.cpp` hooks the native character-customization system's initialization, resource acquisition, option initialization, appearance lookup and appearance changes ([lines 24–39](https://github.com/psiberx/cp2077-archive-xl/blob/5474e34d56112f5d8843ae863e1e72ff510957c0/src/App/Extensions/Customization/Extension.cpp#L24-L39)).

The data path is:

1. An ArchiveXL `.xl` file supplies `customizations: male:` and/or `female:` paths to `.inkcharcustomization` resources. [Config.cpp, lines 5–53](https://github.com/psiberx/cp2077-archive-xl/blob/5474e34d56112f5d8843ae863e1e72ff510957c0/src/App/Extensions/Customization/Config.cpp#L5-L53) parses a path or list for each sex. The [community switcher guide](https://wiki.redmodding.org/cyberpunk-2077-modding/for-mod-creators-theory/core-mods-explained/archivexl/archivexl-character-creator-additions/ccxl-creating-a-switcher) shows the authoring pattern.
2. ArchiveXL prefetches each resource, then merges it into the game's male or female `gameuiCharacterCustomizationInfoResource` before the system reads that resource ([Extension.cpp, lines 91–95, 233–332](https://github.com/psiberx/cp2077-archive-xl/blob/5474e34d56112f5d8843ae863e1e72ff510957c0/src/App/Extensions/Customization/Extension.cpp#L233-L332)). The resource contains separate head, body and arms option and group arrays.
3. The game builds customization state and UI from the resulting options. ArchiveXL explicitly inserts eligible new appearance/morph option names into state and activates eligible new switchers when they are enabled and not hidden ([lines 97–143](https://github.com/psiberx/cp2077-archive-xl/blob/5474e34d56112f5d8843ae863e1e72ff510957c0/src/App/Extensions/Customization/Extension.cpp#L97-L143)). It also redirects appearance descriptors where a choice extends a different `.app` resource ([lines 145–195, 217–231](https://github.com/psiberx/cp2077-archive-xl/blob/5474e34d56112f5d8843ae863e1e72ff510957c0/src/App/Extensions/Customization/Extension.cpp#L145-L231)).
4. A selected appearance resolves through its `.app` definition, components, mesh appearance and material resources. The customization-scope fallback can clone a template `.app` appearance and assign the suffix after `__` as its mesh appearance; the component pass handles both skinned and morph-target skinned meshes ([lines 779–925](https://github.com/psiberx/cp2077-archive-xl/blob/5474e34d56112f5d8843ae863e1e72ff510957c0/src/App/Extensions/Customization/Extension.cpp#L779-L925)). This fallback requires the `.app` to be in the customization resource scope. XF Studio's [ArchiveXL strategy](../archive-xl/eye-artistry-strategy.md) and [one-selector package](../../experiments/005-preset-collection/README.md) document the precise template contract and its offline verification.

## The merge contract, including negative findings

`MergeCustomEntries` processes each custom resource in order. It first appends entries to matching head/body/arms groups, expands shorthand **unnamed** appearance entries, merges named options, then makes a second pass for anonymous `uiSlot`/`link` overlays. It finally regenerates choice indexes and appends newly registered hair-colour tags to the relevant TweakDB flat ([Extension.cpp, lines 270–332](https://github.com/psiberx/cp2077-archive-xl/blob/5474e34d56112f5d8843ae863e1e72ff510957c0/src/App/Extensions/Customization/Extension.cpp#L270-L332)). `MergeCustomGroups` only finds an **existing group with the same name** and appends option names to it; it does not create a new group from a custom resource ([lines 334–352](https://github.com/psiberx/cp2077-archive-xl/blob/5474e34d56112f5d8843ae863e1e72ff510957c0/src/App/Extensions/Customization/Extension.cpp#L334-L352)). Group names also select different game perspectives/contexts, so a `character_customization` head entry alone does not establish FPP, TPP or photo-mode use; see the [switcher theory guide](https://wiki.redmodding.org/cyberpunk-2077-modding/for-mod-creators-theory/core-mods-explained/archivexl/archivexl-character-creator-additions/ccxl-theory-switchers).

For a named option, a matching target must have the same native option type. The appearance path merges definitions by `name`; morph and switcher choices merge by `localizedName`. A new named option is appended whole. An anonymous option targets existing options by `uiSlot` and/or `link` (including prefix wildcard matching) and merges the type-specific choices ([lines 354–566](https://github.com/psiberx/cp2077-archive-xl/blob/5474e34d56112f5d8843ae863e1e72ff510957c0/src/App/Extensions/Customization/Extension.cpp#L354-L566)). The source does **not** copy top-level metadata such as `index`, `defaultIndex`, `editTags`, `hidden`, `enabled`, `linkController`, `randomizeCategory`, `onDeactivateActions`, `useThumbnails` or `switchVisibility` onto an already existing option during that merge. These can be authored on a wholly new option, but a choice overlay is not a general property patch. `ExpandCustomizationOptions` copies definitions and possibly the `.app` path from the preceding nonempty *unnamed* appearance option; it does not generate an arbitrary matrix of named choices ([lines 569–603](https://github.com/psiberx/cp2077-archive-xl/blob/5474e34d56112f5d8843ae863e1e72ff510957c0/src/App/Extensions/Customization/Extension.cpp#L569-L603)).

The reflected [resource type](https://github.com/WopsS/RED4ext.SDK/blob/ad7277714ad30d6885d7050c5ba24fa0102f6920/include/RED4ext/Scripting/Natives/Generated/game/ui/CharacterCustomizationInfoResource.hpp) also contains `perspectiveInfo`, `uiPresets`, `excludedFromRandomize` and `versionUpdateInfo`. ArchiveXL's above merge never copies these arrays from a custom `.inkcharcustomization`; their presence in a new CCXL resource is therefore not proof they affect the merged base resource. Nor does reflection prove script/UI access or game behavior. The [option type](https://github.com/WopsS/RED4ext.SDK/blob/ad7277714ad30d6885d7050c5ba24fa0102f6920/include/RED4ext/Scripting/Natives/Generated/game/ui/CharacterCustomizationInfo.hpp), [switcher type](https://github.com/WopsS/RED4ext.SDK/blob/ad7277714ad30d6885d7050c5ba24fa0102f6920/include/RED4ext/Scripting/Natives/Generated/game/ui/SwitcherInfo.hpp), [appearance type](https://github.com/WopsS/RED4ext.SDK/blob/ad7277714ad30d6885d7050c5ba24fa0102f6920/include/RED4ext/Scripting/Natives/Generated/game/ui/AppearanceInfo.hpp) and [indexed appearance choice](https://github.com/WopsS/RED4ext.SDK/blob/ad7277714ad30d6885d7050c5ba24fa0102f6920/include/RED4ext/Scripting/Natives/Generated/game/ui/IndexedAppearanceDefinition.hpp) show data fields for slot/link control, edit contexts, actions, randomization, icons/colours and thumbnails. Their actual UI semantics need narrower evidence or runtime tests.

## A demonstrated switcher pattern and its limit

The installed [**Heterochromia Eyes - CCXL**](https://www.nexusmods.com/cyberpunk2077/mods/20349) v2.0.0, credited to **icxrus**, is an inspected example. Its `heterochromia` switcher has one choice naming both `eyes_color_left` and `eyes_color_right`, and another naming `eyes_color` plus `eyes_color_none`; it uses `uiSlots`, `switchVisibility` and an `Activate` action. The extracted reference is the ignored, local `research/consumers/heterochromia/json/heterochromia_pwa.inkcharcustomization.json`; it is not supplied by a source clone. This demonstrates a data pattern for one choice referencing multiple appearance options; it is not proof that the XF Studio package switches several new components atomically or preserves them through a 2.31 save. The mod and learning use are already recorded in [community credits](../../docs/community-credits.md).

For XF Studio, [experiment 005](../../experiments/005-preset-collection/README.md) already compiles a single eye-makeup selector with Off and authored complete-look choices. Its archive, customization resource, mesh/morph pair and maps round-trip offline. The immediate game proof remains A → B → Off clearing, correct material/mesh appearance, reload persistence, and behavior when a UUID-stable choice is reordered or removed. Independent design/colour/finish selectors and a full option matrix are historical research, not the current product direction.

## Where the other layers begin

- **RED4ext** is the native plugin loader; its [source](https://github.com/WopsS/RED4ext/tree/c52c8d802f67013cceae722d9996a3418608b991) describes hosting plugins and the separate SDK. ArchiveXL uses this layer for the hooks above. Reflected SDK declarations at commit `ad7277714ad30d6885d7050c5ba24fa0102f6920` identify classes and fields, not method bodies or a current game UI implementation.
- **TweakXL** [1.11.4 source](https://github.com/psiberx/cp2077-tweak-xl/tree/f8da6be4fb7b8340d5744d822a85de1400f2cafb) changes TweakDB data. ArchiveXL can append hair colour tags to a TweakDB flat, and icons reference TweakDB IDs, but TweakXL is not the `.inkcharcustomization` merger or an automatic Ink layout engine.
- **redscript** is the game script language/compiler. Its local checkout follows a 1.0.x development line; the pinned runtime-compatible release tag is [0.5.31, `fca2682`](https://github.com/jac3km4/redscript/tree/fca2682c5b9faee1be6c393ad7ebb9d6bc7cc1cc). **Codeware** [1.20.5, `613a1cb`](https://github.com/psiberx/cp2077-codeware/tree/613a1cb830ecf33508ffca839d3ea631073504ef) imports/adds native customization fields and the action enum for scripts (see local `scripts/Base/Addons/gameuiCharacterCustomizationInfo.reds` and `scripts/Base/Imports/gameuiCharacterCustomizationActionType.reds`). That makes a script-level probe plausible; it does not itself install new creator widgets or save arbitrary editor state.
- The game's **Ink UI controllers and widget resources** own the visible layout, colour picker, pagination and input. A [May 2025 RTTI dump](https://github.com/xf-hq/red-dump-json/blob/a8e529900db3a3618eab5f308fa9b1b0a607eca8/classes/characterCreationBodyMorphMenu.json) lists `characterCreationBodyMorphMenu` fields/methods such as `optionsList`, `colorPicker`, page buttons, `InitializeList`, `OnOptionUpdated` and `ApplyUIPreset`. This historical dump is a class/method lead only; it predates game 2.31 and supplies no method bodies. RED4ext.SDK's current base/in-game controller declarations do not establish the full 2.31 widget flow.

## Bounded next probes

| Candidate | What is established | Smallest useful proof |
|---|---|---|
| Complete eye-makeup selector | XF Studio's archive and three-choice fixture verify offline; ArchiveXL has the matching resource/appearance mechanisms. | In one prepared 2.31 session, select A → B → Off, save/reload, then inspect selected component and appearance names plus visual clearing. |
| Linked or conditional later controls | Switcher `names`, slots, links and actions exist; Heterochromia provides a concrete two-eye data example. | Build one minimal two-option fixture using two uniquely named components, then observe activation, deactivation and persistence. Do not infer independent colour/material context from the UI state. |
| More morph choices | ArchiveXL merges morph choice arrays and regenerates indexes. | Inventory candidate morph names and actual morph buffers first; test one validated target through creation and later edit contexts. No unbacked geometry should be offered. |
| Better palette browsing | Appearance data has icon/colour/thumbnail fields; historical Ink controller has picker/paging methods. | Measure current thumbnail and option-list limits with a small CCXL fixture. Search, paging redesign or custom preview widgets require current 2.31 UI/controller/resource tracing beyond this merge. |
| Custom preset/save migration fields | Reflected types contain `uiPresets` and `versionUpdateInfo`, but ArchiveXL does not merge them. | Do not put these in a normal CCXL resource expecting an effect. Trace game 2.31 loading and persistence first; consider script/native work only after an explicit product need. |
