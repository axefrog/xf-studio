# Read-only character-creator catalog probe

24 September 2026. This is a bounded offline prototype, not a current game/runtime selector graph. The source is [`catalog_readonly.py`](../../projects/xf-appearance-studio/authoring/tools/catalog_readonly.py); its output stays local because it contains personal mod names and paths. It selects either an MO2-profile or direct-game physical-file view, inventories candidate `.archive`, `.xl` and loose `.inkcharcustomization` files, and keeps the manual game mod root in either view. It resolves **loose virtual-file** candidates by MO2 priority where applicable, retains disabled candidates for diagnosis, reads active `.xl` `customizations` declarations, validates explicitly supplied WolvenKit JSON exports against those declarations, and normalizes vanilla and selected mod resources into options/choices with per-choice provenance. A narrow named/anonymous appearance overlay shows the supported portion of ArchiveXL's merge. It never modifies a save, game installation or mod manager.

## Reproduction and boundaries

Run `py -m unittest projects/xf-appearance-studio/authoring/tests/test_catalog_readonly.py -v` (ten focused tests). For a live snapshot, use `py projects/xf-appearance-studio/authoring/tools/catalog_readonly.py --help`; pass a game-version-matched base JSON, manual game mod root, and each selected `PROVIDER=DEPOT=JSON` custom resource. The default `--launch-context mo2` additionally requires `--mo2-root` and `--profile`; `--launch-context direct` excludes staged MO2 files, even if MO2 is installed, while retaining manual game files. To compose the saved eye's app path, also supply the installed bundle's `PlayerCustomizationEyesFix.xl` and `PlayerCustomizationEyesScope.xl` via the two optional flags in an MO2 view. The tool requires an active female `.xl` registration for every custom JSON. Its output is an ordinary local JSON file with the selected launch route recorded. Tests now cover route exclusion as well as disabled contenders, MO2 file priority, cross-provider ambiguity, scalar/list declarations, choice provenance, exact uint64 app/definition matching, and app fix/scope composition. Choosing a route is a research input, not evidence of how a particular past game session launched.

Scan exclusions are explicit in the output: unqueried archive hashes, payload decoding, the hundreds of registered but unexported customization payloads, ArchiveXL merge ordering beyond one appearance overlay and this app fix, other resource patches/links, REDmod and script/UI changes, actual game launch context, Vortex deployment, and runtime rendering. The opt-in selected-hash index stage below narrows the first gap. MO2's enabled flag does not establish that the game loaded an archive. The full local output stores the option metadata for examination but should not be distributed as a catalog of installed mods. A later version should decode all registered resources with version/hash evidence, apply ArchiveXL operations in actual order, and expose conflicts and missing dependencies in the UI before allowing edits.

## Focused archive-hash stage — 24 September 2026

The opt-in `--archive-hash DECIMAL_UINT64` stage now reads RDAR **indexes only** for selected resource hashes after the explicitly chosen `--launch-context` has selected physical containers. It keeps disabled and shadowed archive candidates in `physical_candidates`, separates them from `visible_candidates`, and reports `source_derived_winner` independently of the always-null `runtime_observed_winner`. For meaningful base-game coverage, supply the installed `archive/pc/content`, `ep1` and `hot` directories with repeated `--base-archive-root`; omitted roots make a winner unresolved. The probe scans the supplied roots rather than assuming they are complete. It records the full archive SHA-256 for matching containers, but the index entry's SHA-1 is **not** treated as an extracted-payload digest.

For standard `archive/pc/mod` containers, the order follows the [MO2 Cyberpunk support guide](https://github.com/ModOrganizer2/modorganizer-basic_games/wiki/Game%3A-Cyberpunk-2077#load-order): first archive in alphabetical order wins unless a **visible** `archive/pc/mod/modlist.txt` supplies explicit first-to-last order. The probe reads and fingerprints the actual visible list when present; it does not infer a list from MO2's `enforce_archive_load_order` or `reverse_archive_load_order` settings. Unknown or duplicated list names, duplicate archive basenames, ambiguous virtual archive files, active index errors, base-versus-mod collisions and nonstandard bundle mounts keep the winner unresolved. This is an offline source rule for a selected route, not evidence that Nathan launched through that route or that REDengine rendered those bytes. ArchiveXL patches, links and dynamic customization overlays remain separate graph stages.

The local MO2 route `2025 (again)` was probed for Nathan's saved-eye diffuse `7140168419554698265`, normal `15957548315662394704` and roughness `15197097397900794989`. The three selected base directories plus selected MO2/manual view yielded 1,161 physical archive indexes, zero read errors, zero ambiguous active virtual archives and no visible archive modlist. Each hash had exactly one physical and visible indexed candidate, Kala's Eyes Standalone V2, in `basegame_Kala Standalone Eyes V2.archive` (container SHA-256 `e79e609dd009bf747d3cdff6844b480d8d0709ab7c920d067d3fc941e3c6a127`). Thus the **source-derived** winner for each queried texture is Kala under that selected route and scanned corpus; no runtime winner was observed in this probe. The September 16 ArchiveXL log remains historical evidence for the bridge and material instantiation, not current texture-byte loading. The direct-game route with the same three base directories found **zero** physical or visible candidates for the diffuse hash, demonstrating why an explicit route matters.

The focused test suite has ten cases, including synthetic duplicate archive hashes whose winner reverses between alphabetical and a visible modlist, disabled candidates, direct-route exclusion, virtual-file ambiguity, missing base coverage, base-versus-mod collisions, uint64 validation and truncated indexes. Run `py -m unittest projects/xf-appearance-studio/authoring/tests/test_catalog_readonly.py -v`. The CLI opt-in uses `--archive-hash` and `--base-archive-root` in addition to the catalog's existing inputs; both may repeat. The output remains local because it records personal mod paths. Current exclusions include uninspected roots, resource payload bytes, hash collisions within a single archive, bundle-specific load order, REDmod/Vortex deployment, framework mutations after static archive resolution and current game runtime evidence.
