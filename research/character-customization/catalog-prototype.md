# Read-only character-creator catalog probe

24 September 2026. This is a bounded offline prototype, not a current game/runtime selector graph. The source is [`catalog_readonly.py`](../../projects/xf-appearance-studio/authoring/tools/catalog_readonly.py); its output stays local because it contains personal mod names and paths. It reads MO2's selected profile and physical candidate `.archive`, `.xl` and loose `.inkcharcustomization` files, plus a manual game mod root. It resolves **loose virtual-file** candidates by MO2 priority, retains disabled candidates, reads active `.xl` `customizations` declarations, validates explicitly supplied WolvenKit JSON exports against those declarations, and normalizes vanilla and selected mod resources into options/choices with per-choice provenance. A narrow named/anonymous appearance overlay shows the supported portion of ArchiveXL's merge. It never modifies a save, game installation or mod manager.

## Reproduction and boundaries

Run `py -m unittest projects/xf-appearance-studio/authoring/tests/test_catalog_readonly.py -v`. For a live snapshot, use `py projects/xf-appearance-studio/authoring/tools/catalog_readonly.py --help`; pass the MO2 root, selected profile, manual game mod root, a game-version-matched base JSON, and each selected `PROVIDER=DEPOT=JSON` custom resource. The tool requires an active female `.xl` registration for every custom JSON. Its output is an ordinary local JSON file. The tests cover disabled contenders, MO2 file priority, ambiguity across different provider kinds, scalar/list `.xl` declarations, anonymous slot overlay with choice provenance, and exact high-value app-hash/definition matching.

Scan exclusions are explicit in the output: archive entry indexes and resource hash conflicts, the hundreds of registered but unexported customization payloads, ArchiveXL merge ordering beyond one appearance overlay, resource patch/link/scope transforms, REDmod and script/UI changes, actual game launch context, Vortex deployment, and runtime rendering. MO2's enabled flag does not establish that the game loaded an archive. The full local output stores the option metadata for examination but should not be distributed as a catalog of installed mods. A later version should take provider-neutral inventory snapshots, index archive hashes, decode all registered resources with version/hash evidence, apply ArchiveXL operations in actual order, and expose conflicts and missing dependencies in the UI before allowing edits.
