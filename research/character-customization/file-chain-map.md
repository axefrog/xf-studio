## The chain to resolve

```text
.archive.xl: customizations (sex-specific .inkcharcustomization), resource patches/links
  → .inkcharcustomization: head/body/arm group → switcher/appearance/morph option
    → appearance option: .app resource + named appearance definition
      → .app definition: components, partsValues .ent, partsOverrides
        → mesh component: .mesh path + meshAppearance + chunkMask
          → .morphtarget baseMesh, when applicable: base geometry + named morph deltas
          → .mesh appearance: per-submesh chunkMaterials names
            → materialEntries: name → local/external list + index
              → local instance or external .mi chain → .mt/.remt shader + values → .xbm/.hp/etc.
```

The arrow from `.inkcharcustomization` to `.app` is direct for `gameuiAppearanceInfo`; a cyclic `gameuiSwitcherInfo` instead names other appearance options, and `gameuiMorphInfo` names morph targets. A root `.ent` is an additional route for an item/NPC: its public appearance entry maps `name` to an `.app` `appearanceName` and `appearanceResource`. An `.app` may itself contain mesh components, so do not insert a root `.ent` into every character-creator chain. The diagrams below establish these distinctions.

## ArchiveXL transformation, and what remains explicit

The [dynamic-material guide](https://github.com/CDPR-Modding-Documentation/Cyberpunk-Modding-Docs/blob/be2f44eed8419342ec13f72ed9cab008e9f7b289/for-mod-creators-theory/core-mods-explained/archivexl/archivexl-dynamic-materials/README.md) and inspected [expansion screenshot](https://github.com/CDPR-Modding-Documentation/Cyberpunk-Modding-Docs/blob/be2f44eed8419342ec13f72ed9cab008e9f7b289/.gitbook/assets/mesh_appearances_auto_expansion.png) show later mesh appearances with empty `chunkMaterials` inheriting the first list, with their appearance name substituted into matching material names. Another [screenshot](https://github.com/CDPR-Modding-Documentation/Cyberpunk-Modding-Docs/blob/be2f44eed8419342ec13f72ed9cab008e9f7b289/.gitbook/assets/image%20%28345%29.png) (`.gitbook/assets/image (345).png`) shows a `Soft` `*...{material}.mlsetup` reference. The [CCXL eye-texture guide](https://github.com/CDPR-Modding-Documentation/Cyberpunk-Modding-Docs/blob/be2f44eed8419342ec13f72ed9cab008e9f7b289/for-mod-creators-theory/core-mods-explained/archivexl/archivexl-character-creator-additions/ccxl-eye-textures.md) uses the same idea for `Albedo` ([screenshot](https://github.com/CDPR-Modding-Documentation/Cyberpunk-Modding-Docs/blob/be2f44eed8419342ec13f72ed9cab008e9f7b289/.gitbook/assets/ccxleyes012%20%281%29.png)) and `.xl` patch/link rules ([patch screenshot](https://github.com/CDPR-Modding-Documentation/Cyberpunk-Modding-Docs/blob/be2f44eed8419342ec13f72ed9cab008e9f7b289/.gitbook/assets/ccxleyes008.png), [link screenshot](https://github.com/CDPR-Modding-Documentation/Cyberpunk-Modding-Docs/blob/be2f44eed8419342ec13f72ed9cab008e9f7b289/.gitbook/assets/ccxleyes017.png)). **The selectable appearance names still exist**; expansion reduces duplicated material and chunk-list definitions, not the number of selector entries to zero. The [scopes/extensions guide](https://github.com/CDPR-Modding-Documentation/Cyberpunk-Modding-Docs/blob/be2f44eed8419342ec13f72ed9cab008e9f7b289/for-mod-creators-theory/core-mods-explained/archivexl/archivexl-character-creator-additions/ccxl-theory-scopes-and-extensions.md) and [makeup mesh image](https://github.com/CDPR-Modding-Documentation/Cyberpunk-Modding-Docs/blob/be2f44eed8419342ec13f72ed9cab008e9f7b289/.gitbook/assets/ccxl_makeup_mesh_example.png) warn that a single mesh containing multiple makeup *styles* prevents future colour extensibility; its stated extensible pattern uses one mesh per style with `@context` and colour-specific `.mi` files. Our authored-preset approach should test whether this distinction applies to compiled, intentionally fixed presets before copying that template.

For a saved-V renderer, record each resolved edge with its source archive/provider, patch or link, and confidence. This is an **implementation inference** from the documented chain: first resolve effective vanilla/modded `.inkcharcustomization` options and ArchiveXL transformations, then saved choice to `.app` definition, its components/overrides and morph regions, then mesh appearances/material inheritance and texture/hair-profile data. Keep missing edges explicit; installed files and illustrative screenshots do not prove runtime winners or rendered pixels.

## Documentation limits and credit

The character-creator overview calls its subject `.inkcc`, while its guide, screenshots and examples actually use `.inkcharcustomization`. Its link to `.inkcharactercustomization-cc-options.md` points to a file **absent from this clone**. Other links include `broken-reference/README.md`. The `.app` guide explicitly marks some `parentAppearance`, `proxyMesh`, and lazy-dependency behavior as uncertain; `commonCookData` is labelled historical after game 2.1. The morphtarget page's claim about lacking general new activation has no publication date and should be checked against current ArchiveXL implementation before applying it to CCXL. All screenshot evidence is resource-editor evidence, not a game runtime test.
