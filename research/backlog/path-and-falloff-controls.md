# Path, falloff and surface-control feedback

Nathan’s seven explicit requests, 23 September 2026. Preserve these across context changes. This is queued functional authoring work; the current idle checkpoint continues first.

1. **Insert at the nearest path section.** Double-click should insert into the section of the curve nearest the click, independent of which point was selected. Current code inserts after `selected`, which can connect unrelated parts of the contour. Choose the actual curved segment, handle the closing segment and mirrored side, preserve useful weights/handles, selection and one-step Undo. Verify both source recipe and raster output.
2. **Single-eye UV mode.** Toggle between both eyes and an enlarged single side so the shape fills the pane with useful editing space. Preserve source UV coordinates, symmetry and aspect ratio; crop/view state must not rewrite the recipe. Persist view mode and retain access to either eye, handles and off-crop points. Keep actual texture/head context visible for judging placement.
3. **Point-weight discontinuities are a reported bug.** The current evaluator chooses the nearest sampled boundary segment, interpolates its point weights, then multiplies opacity by that weight. Nearest-segment changes can abruptly change the multiplier even inside the shape, producing seams. Do not dismiss this as expected art control behavior or simply hide it by raising resolution. Reproduce quantitatively and visually; require continuous, intentional strength/falloff behavior across medial boundaries and close curve sections.
4. **Bézier handles.** Editable tangent handles are requested rather than only automatic Catmull–Rom interpolation. Keep shape, field and finish data separate. New curve data needs explicit versioning/migration and the same evaluation in preview, mask export and material compilation; do not silently reshape existing recipes.
5. **Corner points.** Support decoupled incoming/outgoing handles and useful corner/cusp behavior, with an obvious way to return to a smooth point. Preserve Undo and stable point/shape interaction semantics. Corner geometry must not accidentally imply a discontinuous pigment field.
6. **Directional/asymmetric falloff.** Nathan wants one side/direction soft and another abrupt. Current Selected point weight is local pigment strength, not feather width; current Edge softness is global. Expose understandable, separate controls for edge softness/direction and pigment strength. Consider per-edge/per-point feather controls and inward/outward profiles where useful, but choose a coherent model rather than overloading weight. Test soft/abrupt boundaries, symmetry, corners, zero strength and field warping without unwanted internal seams.
7. **Surface handles above geometry.** Controls remain anchored to the animated/morphed head/plate but should render over eyelashes and other nearby geometry. An overlay pass/material policy must give points, tangents and guides consistent visibility without changing the actual makeup material. Picking must agree with displayed controls, especially overlapping mirrored controls, camera-facing versus rear-facing anchors and eye openings. Keep intentional surface controls on/off and normal raycast/UV-gap safeguards. Do not force users to hide their lashes just to select an edit handle.

The user asked whether weight supplies directional softness: it currently does not. A deterministic numeric fixture now confirms that nearest-edge strength interpolation can jump from zero to full coverage across just 2e-8 UV inside a shape. This reproduces the algorithm defect, not the exact draft Nathan was editing. The [design/reproduction follow-up](../authoring/path-and-falloff-design.md) records the evidence and proposed fixes.
