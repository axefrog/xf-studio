# Runtime bridge supervisor: first slice (0.8.15) and XF actors (0.8.19)

**Status: source/offline, 25 October 2026 (XF actors added in 0.8.19).** Round 3 added V's autonomous-build supervisor; 0.8.19 adds the bridge's own XF actors and several entries ([below](#xf-actors-and-several-entries-0819)). Neither has run in game. The coordinator commits and reviews this candidate before the [SV815 session](runtime-bridge-test-card.md#supervisor-0815-round-3). R6 [navigation/contact limits](../../knowledge/navigation-and-safety.md) apply throughout. This is a bounded observer and policy executor, not a movement controller or proof of safety.

An actor owns a versioned plain entry. `actor:{kind:"player",ref:"V"}`, `actor:{kind:"npc",ref:"a1"}` and `actor:{kind:"spawn",ref:"1"}` share the schema; V's adapter and (0.8.19) the XF actor adapter can be armed; a picked passer-by (`p1`) and a spawned-object reference parse and are refused with `actor_unavailable`, rather than acquiring a misleading inactive entry. No entity pointer is retained. Replacement discards the previous anchor and invalidates its work. Since 0.8.19 the storage is the actor-keyed bounded collection this note reserved, with the entry data unchanged: up to five active entries, one per actor.

```json
{
  "schema": "xfb/supervisor-entry-1",
  "actor": {"kind": "player", "ref": "V"},
  "goal": {"kind": "hold_position", "at": [0, 0, 0], "radius_m": 1},
  "invariants": ["not_in_combat", "no_contact", "not_on_road", "alive"],
  "policy": {
    "goal": "return_last_safe",
    "not_in_combat": "pause_world",
    "no_contact": "return_last_safe",
    "not_on_road": "handover",
    "alive": "handover"
  },
  "tick_hz": 3,
  "safe_after_s": 3
}
```

Replace the example point with the observed destination. `hold_position` detects departures from its radius (0.2–10 m); optional `facing` has a fixed 15° tolerance. It requires a `goal` policy. `idle_safe` has no movement target and takes only its kind. Neither installs a movement hold, periodically teleports V, nor fabricates a game idle. Each selected invariant requires exactly one whitelisted policy. Unknown fields, arbitrary methods, scripts, expressions and actions outside the whitelist refuse. The entry accepts 1–5 Hz and 1–30 seconds for quiet dwell. There is no host timer: the game Running tick evaluates at deadlines, never bursts after a stall.

| Policy | Existing dispatcher route | Scope and refusal |
|---|---|---|
| `stop_behaviours` | `behave.stop {all:true}` | Stops our behaviour runner; ordinary cleanup follows on the game tick. |
| `release_holds` | `player.stop {}` | Releases the bridge's player effects/look/motion, not arbitrary mods' effects. |
| `withdraw_nearby` | individual `npc.release {who,how:"despawn"}` / `world.despawn {id}` | Only bridge-spawned actors, props and vehicles observed within 30 m; rechecks ownership and live position on the executing frame. Adopted passers-by and lights are excluded. Each command retains its NPC/DM permission. |
| `return_last_safe` | `player.stop`, then `player.teleport` after 0.4 seconds | Normal player/phase/busy/traffic/pacer checks apply. No anchor, death, combat, changed owner or takeover refuses. The short delay lets the stop cleanup run; it does not grant permission. No far/road override. |
| `pause_world` | `world.pause {paused:true}` | Needs world permission; successful pause cancels supervision. |
| `handover` | `bridge.handover {on:true}` | Cancels supervision and follows the established handover cleanup route. |

Arming also checks the caller's selected policy capabilities: player always, world for pause, and both NPC and DM for nearby withdrawal. Stop/return/handover use the existing emergency-control capability. The command catalogue declares these additional requirements; MCP passes its allow set to the command API, which refuses before sending. The API injects `caller_write_classes` (config-style names such as `player`, `world`, `npc`, `dm`) into the authenticated request envelope, never into untrusted entry data. Native arming fails closed without that claim, snapshots its mask into queued work, and checks the selected policies against it and config. Every worker request carries the captured mask, which the dispatcher checks against that action's class. Config remains the ceiling. This is permission narrowing by a trusted local frontend, not cryptographic separation from another process that already possesses the session token. Raw-pipe clients must provide an explicit claim to arm.

The game-independent `core/Supervisor` owns entry transitions, quiet dwell, contact sequences and violation edges. A single bounded worker submits only the routes above through the normal dispatcher: authentication, rate/write-class/kill/pause/handover/script gates still apply. Trusted C++ execution guards propagate to **each** queued game step, including teleport's later write. They compare entry generation, actual player identity, world/connection generation, fresh phase and input on every step. Violation checks apply immediately before state changes and bridge-thread admission; settlement reads may observe a resolved goal and preserve the successful result/undo, while still refusing a changed owner, input or lifecycle. This guard cannot be supplied by request data. Existing restore scopes remain unconditional cleanup. A bridge-thread bookkeeping action receives a guarded game-frame admission first; the native behaviour stop itself changes bookkeeping only. Setting a replacement is also guarded against a clear admitted while it waited in the queue.

Each violation edge queues one policy, never an automatic retry loop. A new contact receipt batch is a new edge. Persistent combat/death/goal deviation does not cause a command storm; a refusal remains visible until an explicit new entry or a newly observed edge. At most 16 actions are pending; overflow is an explicit `supervisor.action` refusal. Deletion plans resolve at most the existing 3 actor / 24 object limits. Their position-only adapter never changes DM watcher subscriptions or drains watcher events. Each executed or refused command gets its result, including multi-command returns. A planning/read failure is also a result. Kill, bridge pause, handover and accepted load invalidate the owner immediately through bookkeeping; detach, lost connection, invalid observations and observed non-gameplay/world-freeze cancel it too. No automatic re-arm after resume/load.

The independent player listener uses the existing mapped movement/camera/jump/crouch/sprint/dodge reads, plus mapped `RangedAttack`, `CameraAim`, `Reload`, `MeleeAttack`, `MeleeLightAttack`, `MeleeHeavyAttack`, `MeleeStrongAttack`, `MeleeBlock`, `QuickMelee` and interact. These follow the pinned 2.31 PSM consumers, not PrimaryAttack/SecondaryAttack. Non-axis mapped input yields on a fresh button press or value at least 0.3, so stationary triggers do not depend on mouse/stick motion. It shares the existing thresholds (mouse action delta 3; axes 0.3). With Codeware it also observes raw mouse/stick axes (6 counts in a report or 15 accumulated; stick 0.3). First observed deliberate input cancels the native owner in its callback, without waiting for the supervisor deadline; all already-queued game actions then fail their guard. Listener removal follows on the next live tick, or system detach. It never unregisters another glide's listener. This is not complete hardware coverage; consumed/unmapped buttons, raw buttons, very small deltas and brief phase changes between observations are not proven observed. Current policies create no supervisor-owned movement holds to release on takeover.

The last safe point is an **observed quiet anchor**, recorded by the supervisor after V remains within 0.15 m for N seconds, alive, outside combat, with no covered contact receipt. A hold goal must also be satisfied; positive Road cannot mature an anchor. A missed interval longer than two evaluation periods resets dwell. Positive contacts reset candidate dwell but preserve the prior mature anchor. This is intentionally not a no-contact proof: R6's controller reports can include supporting ground, have no body identity and miss continuous passive contacts. Road containment remains unknown (RB-232), so `not_on_road` only reports a note and performs no intervention. Anchor and return evidence carry that uncertainty. V cannot be returned before an anchor exists, even if a target was supplied in `hold_position`.

Supervisor/contact ingress is independent of recorder selection and has no private history store. It copies bounded pending receipts into the existing session log and optional/default `supervisor` recorder channel. Native ingress never calls gameplay functions or recorder sinks while holding the supervisor mutex. Sinks flush outside VM sampling; bounded pending-event overflow emits `supervisor.gap`, increments state drops and makes catch-up history incomplete. `supervisor.violation`, `supervisor.action` (full result), quiet-anchor, contact and cancellation receipts feed `game.catchup.supervisor_summary`: “while you were away: …”. Recorder/session duplicates are reconciled by process-unique receipt identity across calls, using the returned cursor. Only matching world-generation receipts created in the run's source interval [start,end] (open while active) affect its summary or contact latch. Creation QPC time is retained before deferred sink flushes, so a pre-run contact cannot acquire the flush time of a newer run. The cursor retains at most 512 receipt identities. Compaction retires older identities, suppresses late older copies and explicitly makes reconciliation history incomplete; raw feeds remain available for audit. Unscoped/foreign receipts do not become current-run safety evidence. The tools share one heartbeat/connection lease for recording and supervision, so stopping recording cannot drop supervision; the heartbeat observes native cancellation and releases the supervisor lease, while clear overtakes a pending set on the control route. After recording stops, supervision continues and raw `session.events` retains later receipts. Catch-up for that stopped run summarises only its closed source interval; it excludes later activity. Session/ring/archive losses remain explicit. A recorder run is still needed by today's catch-up cursor API; `session.events` works independently.

## XF actors and several entries (0.8.19)

**Status: source/offline, 25 October 2026; not run in game.** It lives in the autonomous test build like the rest of the supervisor.

**The collection.** `supervisor.set` arms one entry for its actor: `actor:{kind:"player",ref:"V"}` or `actor:{kind:"npc",ref:"a1"}` (an XF actor from `npc.spawn` or `npc.substitute`, never a picked passer-by). At most **five** entries are active, whichever mix (V plus four actors, or five actors); a sixth is refused `supervisor_limit`, and replacing an actor's own entry is always allowed. Each entry is an independent owner slot: its own generation, anchor, violation edges, caller capabilities and queued-work guard; the receipt identity sequence is shared. `supervisor.state` reads every entry (schema `xfb/supervisor-state-2`: `active` is true while any entry is, `count`, `limit`, `entries`) or one with `actor`; `supervisor.clear` cancels every entry or one with `actor`, and answers what is still armed (`cleared` names what went). A clear of one actor does not end the connection's lease for the others; the last clear does. Setting or clearing one actor never touches another's.

**What an XF actor's entry takes.**

| Part | Allowed |
|---|---|
| Goal | `hold_position` (departures from its radius, optional facing; the supervisor never moves the actor to hold) or `idle_safe`, as for V |
| Invariants | `alive`, `not_in_combat` and (new) `not_lost`: the actor still exists and is streamed in. `no_contact` and `not_on_road` are V's and refuse for an actor; `not_lost` refuses for V |
| Policies | `release` (`npc.release`, despawn; harmless for an actor already gone), `return_last_safe` (`npc.place` to the observed quiet point, so the normal range, ground and streaming checks apply and `too_far` is a visible refusal), `handover` and `pause_world`, from the same whitelist. V's `stop_behaviours`, `release_holds` and `withdraw_nearby` refuse for an actor; `release` refuses for V |
| Capabilities | **Admission follows the actor.** `supervisor.set` is a plain write whose handler checks the classes the entry really needs (`RequiredWriteClasses`): an actor's entry needs the NPC write class, plus the world class for `pause_world`, and no player class; V's entry needs the player class. The caller's grant (the tools' allow list) must hold the same classes, so an NPC-only profile and an NPC-only caller can arm an actor's entry; `handover` is the control route, and an actor's `return_last_safe` is an NPC write (`npc.place`), not a control one |

**Adapter.** A read-only game step (`XFSupervisorActors.Read`) resolves the registry's handle afresh each tick (no pointer is kept) and reads position, heading, `IsDead`, `NPCPuppet.IsInCombat` and whether the dynamic entity system says it is spawned and the puppet attached. An actor the registry does not know, or that is not streamed in, reads as **lost**. Without `not_lost` in the entry a lost actor ends its supervision (`actor_lost`); with it, the loss is one violation edge, the policy runs once (its guard accepts the lost reading for exactly that violation) and the entry stays armed until cleared.

**Safety rules, unchanged and applied per entry.** One owner per entry; cancelled by the kill switch, a handover, the pause (the dispatcher cancels every entry synchronously), a load, a changed connection owner, an entity behind the handle changing and V's non-gameplay phase; V's own input ends only V's entry (an actor is not under the player's hands); contact receipts belong to V's entry. Execution-frame guards compare the entry's generation, world, connection, fresh reading and the violation itself on every queued step. Receipts (`supervisor.set`, `.violation`, `.action`, `.cleared`, `.safe_position`) carry the actor and feed `game.catchup`, whose `supervisor_summary` adds `by_actor` counts. The queue bound (16 pending actions) and the single worker are shared by all entries.

**Not claimed.** The hold observer does not move an actor, and an actor mid-walk never matures a quiet anchor. Whether `npc.place` of an XF actor behaves under the supervisor as under a direct call, and the `not_lost` read for a really streamed-out actor (an XF actor is spawned always-spawned, so it rarely is) are the card's SV8191 to SV8195.

Extension points are deliberately small:

- **NPCs and vehicles:** actor adapters supply fresh identity, position, combat/liveness/contact and takeover ownership, in bounded actor-keyed slots rather than a V-only schema. The XF actor adapter exists (0.8.19, below). Picked passers-by (the bridge does not own them) and a spawned vehicle's driver/input ownership need their own commissioning.
- **Scene beats:** a scene owner can replace versioned entries at beat boundaries, retaining incident causality. Do not put loops, callbacks or source code into policy data.
- **Goal-shaped movement:** add a goal planner such as “safe pavement near X” only after live traffic containment/nearest pavement are commissioned (RB-232), then select from safe existing movement executors. The current point/radius observer is not a path follower.
- **Frame-rate reflexes:** a distinct game-frame adapter can consume the same actor observations and policy ownership token for twitchy benchmarks. It needs measured budgets, input arbitration and a bounded action pipeline; increasing this 3 Hz tick to frame rate is not commissioning a realtime controller.

Offline verification and native counts are recorded in the [bridge README](../../projects/xf-runtime-bridge/README.md). Runtime commissioning remains the session card, especially parked-car contact delivery (RB-233), input under consumed camera actions and queued load/clear races. No game.quit or native lifecycle consumer invocation is added.
