# First irregular Glitter browser checkpoint

23 September 2026. The main XF Studio editor now exposes an explicit **Try irregular glitter** action for a Glitter layer. It saves `irregular-planar-1` settings in `xfs/recipe-7`; v1–v6 recipes retain their existing cell-flake appearance and mask bytes. The game compiler continues to reject Glitter. No third-party photograph or game asset enters the product bundle.

The candidate uses the project-authored polygon field from Experiment 007. The first browser default (16,000 global candidates, radius 0.0012 UV) was too sparse: the face-framed verification showed tens of conspicuous pale facets per eye. The revised **pre-merge** recipe-7 default is 350,000 deterministic global IDs, radius 0.00045 UV and spread 0.7, with a 16-sample covered-only optical bake. The two fixed eye UV regions cover U 0.20–0.50 and 0.50–0.80, V 0.12–0.36. Only flakes intersecting those regions are retained (hard cap 80,000), so identity is stable across preview sizes and shape edits. Dense authored masks extending outside those regions fail visibly rather than receiving a clipped flake field. Counts at or below 32,768 still use the full atlas; the higher count and radius limits apply only to the fixed-region path. The 16-sample/covered-only change alters the unreleased recipe-7 browser-candidate rendering, not legacy recipe-1–6 output or the separately recorded Experiment 007 study default.

A single cancellable raster worker constructs its catalogue in slices, bakes mask and optical maps, extracts compact one-channel coverage and alpha caches, and composes a linear-light RGB mixture with exact shape alpha. It publishes only a complete latest-version bundle. Normal and surface maps are reused across base/flake colour edits when their optical key is unchanged; a shape edit uses cached field coverage. The receiving stack binds an sRGB RGBA albedo at white material colour and keeps the prior complete material while a replacement is pending. Switching finishes, disabling, replacing, or removing a layer disposes candidate resources. The ordinary mask remains authoritative for UV editing and PNG export.

The operational budget counts four RGBA maps per enabled candidate, its largest replacement bundle, worker outputs and scratch, a 64 MiB compact cache allowance and a conservative 128 MiB catalogue/index allowance. The current fixed 1 GiB guard admits a single 2K candidate (575 MiB estimate in the isolated verification) and rejects 4K. Quality changes release the old maps before the new tier starts. This is an allocation guard, not a report of free GPU memory. Ordinary mip filtering still loses subpixel normal variance. No lighting, view-distance or game-parity claim follows from deterministic map tests.

Validation in the isolated worktree: typecheck and browser bundle build passed; the full suite covers frozen legacy flake hashes, old SQLite revision retention, strict schema-7 rejection, candidate alpha/colour/cache and cancellation behavior, material disposal and the compiler rejection. Ignored local preview GLBs were linked from HQ for asset-dependent tests, and remain ignored. An alternate-port `?verify=1` server served the editor and both bundles successfully. The revised default was inspected at full-face and close-eye framings at 1K and 2K against Nathan's locally stored fine-flake photographs. It produces a densely distributed fine speckle with some size variation rather than the first preview's isolated large confetti. It is still a flat planar/normal-map approximation: at face distance it reads as grain rather than the vivid, angle-dependent scintillation in the photographs, and the current light skin/pink base differs from their darker saturated substrates. Runtime game evidence remains open.
