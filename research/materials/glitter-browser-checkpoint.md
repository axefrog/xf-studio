# First irregular Glitter browser checkpoint

23 September 2026. The main XF Studio editor now exposes an explicit **Try irregular glitter** action for a Glitter layer. It saves `irregular-planar-1` settings in `xfs/recipe-7`; v1–v6 recipes retain their existing cell-flake appearance and mask bytes. The game compiler continues to reject Glitter. No third-party photograph or game asset enters the product bundle.

The candidate uses the project-authored polygon field from Experiment 007. The first browser default (16,000 global candidates, radius 0.0012 UV) was too sparse: the face-framed verification showed tens of conspicuous pale facets per eye. The revised **pre-merge** recipe-7 default is 350,000 deterministic global IDs, radius 0.00045 UV and spread 0.7, with a 16-sample covered-only optical bake. The two fixed eye UV regions cover U 0.20–0.50 and 0.50–0.80, V 0.12–0.36. Only flakes intersecting those regions are retained (hard cap 80,000), so identity is stable across preview sizes and shape edits. Dense authored masks extending outside those regions fail visibly rather than receiving a clipped flake field. Counts at or below 32,768 still use the full atlas; the higher count and radius limits apply only to the fixed-region path. The 16-sample/covered-only change alters the unreleased recipe-7 browser-candidate rendering, not legacy recipe-1–6 output or the separately recorded Experiment 007 study default.

A single cancellable raster worker constructs its catalogue in slices, bakes mask and optical maps, extracts compact one-channel coverage and alpha caches, and composes a linear-light RGB mixture with exact shape alpha. It publishes only a complete latest-version bundle. Normal and surface maps are reused across base/flake colour edits when their optical key is unchanged; a shape edit uses cached field coverage. The receiving stack binds an sRGB RGBA albedo at white material colour and keeps the prior complete material while a replacement is pending. Switching finishes, disabling, replacing, or removing a layer disposes candidate resources. The ordinary mask remains authoritative for UV editing and PNG export.

The operational budget counts four RGBA maps per enabled candidate, its largest replacement bundle, worker outputs and scratch, a 64 MiB compact cache allowance and a conservative 128 MiB catalogue/index allowance. The current fixed 1 GiB guard admits a single 2K candidate (575 MiB estimate in the isolated verification) and rejects 4K. Quality changes release the old maps before the new tier starts. This is an allocation guard, not a report of free GPU memory. The worker now counts region-retained candidates, approximate centres inside the finished shape mask, and painted atlas pixels with resolved coverage; the centre cache is under 0.61 MiB at the 80,000 retained-fragment cap and stays inside the existing cache allowance. It publishes those measurements with the complete layer bundle, never with a partial bake. The editor presents the former global candidate count as a 0–100% **flake field density** control and explicitly reports the measured shape-centre and atlas-pixel counts. Neither is labelled as visible screen glints.

Validation in the isolated worktree: typecheck and browser bundle build passed; the full suite covers frozen legacy flake hashes, old SQLite revision retention, strict schema-7 rejection, candidate alpha/colour/cache and cancellation behavior, material disposal and the compiler rejection. Ignored local preview GLBs were linked from HQ for asset-dependent tests, and remain ignored. An alternate-port `?verify=1` server served the editor and both bundles successfully. The local visual and count audit is in [Experiment 007](../../experiments/007-irregular-glitter/visibility-audit.md).

**Visual acceptance remains blocked for the raster candidate.** In the full-face view it still reads as weak pale grain over pink, without the photographs' fine clustered, angle-dependent glints over a continuous dark sheen. A 500,000 global-ID setting implies neither 500,000 retained flakes nor 500,000 visible glints. Its .00025 UV radius projects to a median diameter of only 0.39/0.77 atlas pixels at 1K/2K and covers about 5% of painted mask area. Ordinary mip filtering and covered-sample averaging remove most high-contrast fine detail at face distance. More IDs alone raise catalogue cost while leaving that filter bottleneck. Recipe-7 and game export cannot silently inherit another shader. Runtime game evidence remains open.

The separately versioned opt-in browser model now has its own [direct-light checkpoint](direct-glint-browser-checkpoint.md). It improves screen glint size and density without modifying recipe-7 raster semantics. Neither model is game-calibrated.
