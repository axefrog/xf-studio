# REDengine glitter on a skinned, skin-preserving eye plate

23 September 2026. Read-only inspection of the installed game's shader cache and locally extracted material templates. This is a feasibility assessment, **not** a render-tested material. The cache is the installed game's RDHS v10 `F:/Games/Cyberpunk 2077/engine/shader_final.cache` (SHA-256 `339145371a3b5aaa08eb4ef82d558f445b632e28603ee0f3b4860270dfc3ccfa`, 161,804,693 bytes); the template JSONs cited below were previously exported with WolvenKit 8.16.2 from game-version-2200 resources. The current cache proves compiled variants exist, but old JSON pass defaults should be refreshed from current resources before release.

## Decision

**The available stock paths do not yet prove a true fine-glitter cosmetic material.** `mesh_decal.mt` is the best established skin-preserving plate path: its compiled skinned post-G-buffer program accepts separate pigment, normal, roughness, metalness and coverage maps. This can make *resolved* flakes change with light and view. It represents one filtered normal/surface value at a pixel, so the fine subpixel flakes in [the lit-head study](../../experiments/007-irregular-glitter/lit-head-findings.md) lose their distinct reflections. Neither a bigger map nor denser baked flakes by itself repairs that filtering problem.

`base\fx\shaders\metal_base_glitter.mt` is a misleading shortcut. Its compiled MeshSkinned G-buffer pass writes depth without blending in the serialized template. The pixel program combines ordinary PBR channels with noise/time-modulated **emission**, not a proven stochastic glint BRDF. Putting that material over the eyelid may occlude skin rather than act as transparent makeup. An emissive decal can add attractive sparkle, but its bright marks are not light-dependent reflections.

There is **no demonstrated supported custom-shader injection path** in the resources inspected here. A stronger physically filtered glint shader might require engine-level work; do not treat a modified `.mt` blend state as a way to add missing shader computations. A bounded hybrid with one or more skinned decals remains worth game-testing under the single preset selector, provided it is labelled as an approximation.

The DXIL evidence is **compiled program inspection**, not editable HLSL source. The selected `mesh_decal_emissive_subsurface` MeshSkinned programs were extracted read-only from the cache into temporary local files and disassembled with the installed Windows SDK `dxc.exe -dumpbin`; no game files were changed. For the actual emissive program, the output reads UVs, two masks and material constants, and has no view/light vector input or surface-normal calculation. The “highlights” pixel program contains only four zero stores. These observations are specific to those selected cache compilations; other vertex factories or passes may differ. The [cache reader](../../projects/xf-appearance-studio/authoring/tools/inspect_shader_cache.ts) and its [index](evidence/shader-cache-index.json) make the GUID/stage selection reproducible. The reader preserves storage order because WolvenKit's historical first/second shader labels disagree with the observed DXIL stage headers.

## Feasible approximation and remaining gap

1. **Baseline:** one morph-skinned `mesh_decal` plate carrying authored pigment and resolved flake normal/roughness/metalness maps. This preserves soft coverage and real PBR response where flakes occupy enough screen pixels. The [decal import fixture](../../experiments/003-decal-material-import/README.md) already isolates map packing and coverage behavior offline.
2. **Optional sparkle accent:** a *separately masked* emissive decal component from the same authored preset, using deterministic UV-anchored flecks. Keep its brightness sparse, bounded and optically honest. It is an artistic approximation and may glow even when physical glitter would be dark; test under opposing light directions and with lights off. It consumes another component/pass and must respect morphs and preset clearing.
3. **Research route for genuine fine glints:** a filtered distribution of facet orientations evaluated against view/light or environment at the pixel footprint. The [primary filtering research](glitter-filtering-research.md) explains why one averaged normal cannot do this. No examined stock material exposes the necessary distribution and evaluation controls. A geometry-based route would also need skinned/morphed flakes, soft skin coverage and draw-cost proof; it is not established by the current material inventory.

For an authored preset, the compiler should retain its editable pigment/flake parameters even if the first game adapter uses a lower-fidelity representation. One CCXL selector can choose an appearance with multiple components; it does not require one material pass. Multiple overlaid decals still need a deterministic order test, and blending material properties into the G-buffer is not the same as separately shading two reflection lobes.

## Offline checks before asking Nathan to launch the game

- Serialize **current-game** copies of the three candidate `.mt` templates and compare pass names, depth writes, target blend factors, parameter names and hashes with the older JSON above. Validate that each selected MeshSkinned compilation is in the installed cache and that the generated `.mi`, mesh and `.app` references resolve.
- Generate one small, high-contrast test preset: matte dark pigment, few resolved metallic facets, an optional independently switchable emissive overlay, plus Off. Keep coverage maps and channel encodings explicit. Verify bundle/resource IDs, all 105 plate morphs, exact native skin weights, naming (`xfs_`) and no missing assets through the existing offline validators.
- Compare 1K/2K/4K mip chains for flake occupancy and edge alpha; measure glint/pigment stability in the browser at close/face/distant views and fixed light sweeps. This forecasts aliasing but cannot validate REDengine lighting.
- Prepare a single runtime capture with toggles for PBR-only, emission-only and combined. Photograph/capture the same eyelid at fixed pose while rotating light/camera separately, including dim illumination, blink and face-framed distance. Look for skin occlusion, light-independent specks, temporal shimmer, near/far mip transitions, bloom, and old components remaining after preset switch/Off. Save ArchiveXL/CET logs and GPU/runtime version with the captures. Update installed framework versions first as [toolchain](../../docs/toolchain.md) requires.

The decision boundary is visual and operational: if the PBR-only facets disappear at normal framing while emission-only flecks stay bright under every light angle, that prototype is a stylized sparkle, not a faithful glitter finish. Do not describe the studio preview as game parity until a controlled run supports it.
