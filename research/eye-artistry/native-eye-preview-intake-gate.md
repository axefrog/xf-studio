# Native-eye preview intake and promotion gate

25 September 2026. The installed 2.31 female eye **morph** is now reproducibly stageable as an ignored local input, but it is not selected by the Studio renderer. This separates resource readiness from rendering policy: a source-hash match does not establish the live game's five-target bind blend, optical shader or blink graph. The current rigid/reference eye, saved-V colour resolution and clean-user UV-only/five-file flows remain authoritative. The [source graph](../../experiments/015-native-eye-assembly/source-graph-trace.md) and [morph-matched render](../../experiments/015-native-eye-assembly/h091-comparison.md) motivate the candidate; neither proves game parity.

## Reproducible private intake

`projects/xf-studio/authoring/tools/intake_native_eye.ts` takes three explicitly supplied, local paths: the WolvenKit 8.17.4 `MeshOnly` GLB exported from `he_000_pwa__morphs.morphtarget`, the raw sibling `he_000_pwa_c__basehead.mesh`, and the raw morph resource. It verifies the exact SHA-256 of all three against [source-bound evidence](../../experiments/015-native-eye-assembly/source-graph-evidence.json), checks the complete GLB header/digest, loads it, and requires the three 12,393/668/152-vertex skinned chunks, the 57-joint rig and 21 eye morphs including `h091_eyes`. All checks finish before it writes to ignored `public/assets/native-eye/eye-h091.glb` and `manifest.json`. The manifest parser accepts only this source triplet, local URL and `staged-research-only` state; staging never selects or renders the candidate. No source game bytes or derived GLB are tracked or releasable.

```powershell
cd projects/xf-studio/authoring
bun tools/intake_native_eye.ts '<private morph export GLB>' '<private base eye mesh>' '<private eye morph resource>'
```

The tool was exercised against newly extracted, exact installed 2.31 sources in an isolated worktree on 25 September: source mesh 258,137 bytes, morph 2,508,277 bytes, GLB 11,676,080 bytes; three chunks passed. Extraction stayed under ignored `experiments/015-native-eye-assembly/generated/`. Focused intake tests, TypeScript check and browser build passed. This proves a deterministic private staging path, not a Studio or game visual result. It was deliberately **not** added to the five-file first-run intake, which must work on a clean user's installation without an experimental eye source.

## Required optional preview architecture

1. Add a workspace-only typed `preview.setEyeGeometry` action with explicit `reference` and `native-study` choices. The action owns validation, persistence and state transitions; the renderer port owns GLB loading, skin material and disposal. No recipe, collection or package identity changes. The capability must return a reason when the exact source asset is absent, stale, too large, invalid, or the character is unsupported. A requested native study must never silently become active on a failed load; publish `requested`, `active`, `reason` and any error through the detached preview status. On restore, fall back visibly to the reference eye while retaining the requested choice for repair. UV-only startup and existing five-file import remain unaffected.
2. Bind the three source chunks to the existing solved facial idle before publishing an active candidate. Preserve the real native skin weights and their original inverse binds; never apply the legacy two-joint gaze shortcut to the native mesh. Keep the saved head's five vertex targets and the eye `h091_eyes` target synchronized when that exact saved choice is selected. Other eye shapes require their own source-name, geometry and bind-policy verification. Eye-shape override must revalidate the native target atomically. Shared eye/head joints must compose at the same phase, including pause/resume, contribution toggles and synthetic blink isolation.
3. Resolve the live multi-target `boneRigMatrices` composition policy before claiming native morph-bind fidelity. The existing four-frame experiment selected `h091` head/eye binds under a world-bind-relative policy; in that policy bind and inverse cancel, and the visible improvement comes from eye vertex morphs. That is a useful **diagnostic**, not a general five-target REDengine rule. Do not silently mix the experiment policy into production idle. The source eye has lash and wetness chunks: decide their material/alpha/depth relationship to the existing modded eyelashes before exposing a normal-looking result. Likewise, map the game eye-gradient atlas, IrisMask channels and optical response rather than painting the source eye with the legacy folded eye PNG without UV proof.
4. In an isolated `?verify=1` workspace, compare reference/native at neutral and saved five-morph poses, including frames 0/169/331/490 and the entire 663-phase loop. Check appearance, blink clearance, pupil/gaze motion, persistent selection, eye-shape changes, absent/corrupt files, idle pause/subsets, mobile/compact panes and performance. One batched in-game character-creator observation should then discriminate the remaining lower strip, material depth and live graph/state. Only after this evidence should `native-study` be offered as an opt-in UI choice; it must remain labelled approximate until game parity is demonstrated.

The preparation code intentionally stops at the intake boundary. Adding a toggle now would imply a useful visual alternative while the source iris shader, wetness/eyelash rendering and morph-bind composition remain unresolved. The next smallest implementation step is a private comparison viewport adapter that loads this manifest and publishes an explicit *diagnostic* state without changing the saved V or the default eye.
