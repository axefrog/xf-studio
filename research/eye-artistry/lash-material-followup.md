# Saved Soft Natural lash material follow-up — 24 September 2026

This is an offline check of the reference save's `icxrus_softnaturaleyelashes` / `05_brown_liquorice` option, extending the [brow/lash material study](brow-lash-fidelity.md#lash-colour-source-based-approximation-unresolved-hair-shader). It changes no saved V, game resources, browser shader or exported assets. All source images, extracted resources and compiled-program bytes remain in ignored local space.

## What the browser used at the time

**Superseded 25 September 2026:** the preview now derives the lash albedo from the decoded `hair.mt` overlay and lights it with the decoded hair light; see [hair shading](../../knowledge/hair-shading.md). The `#302d29` swatch fit below is historical.

The browser's ignored `public/assets/lashes/profile.json` pins app hash `6047185506343464350`, definition `05_brown_liquorice` and installed vanilla `brown_liquorice.hp` resource SHA-256 `57b9999e9918137ada13e536ccc130caca48f6aca08290525063b54b9e2cdcec`. Its `Strand_ID` placeholder is constant RGB `(107,105,107)` and `Strand_Gradient` placeholder is constant `(255,255,255)`. Looking up red-channel values `107/255` and `1` through the sorted profile stops gives `(106.3704,108.2470,109.9111)` and `(214,197,174)`. The current browser multiplies these channelwise, then fits one scalar to the saved selector swatch `(50,44,40)`; its material colour is **`#302d29`**. This is a reproducible description of the *browser's approximation*, not an engine-derived colour.

The preview's `lashes-alpha.png` SHA-256 `c844d762c249ebf7e17c009605929c736aa039e53e698863d3d9fa6415be82de` exactly equals the locally converted Soft Natural `Strand_Alpha` image. At 32×128, its RGB channels are byte-identical greyscale (0–255, mean 26.05), while PNG alpha is uniformly 255. Three.js samples green for `alphaMap`, which therefore gives the same per-pixel value as either red or blue on this particular image; substituting PNG alpha would make solid cards. The saved lash GLB's UV0 vertices occupy U **0.20166–0.79785** and V **0.02344–0.99065**, so the source alpha lies within its single tile. The current transparent Three material uses `alphaTest=0.01`, `depthWrite=false` and draws after makeup; that is a browser ordering approximation, not a measured game setting.

## Compiled game hair programs: useful boundary, not a colour formula

The installed 2.31 `F:/Games/Cyberpunk 2077/engine/shader_final.cache` SHA-256 is `339145371a3b5aaa08eb4ef82d558f445b632e28603ee0f3ccfa`. A read-only scan of its compilation metadata found 234 `hair` variants. For `VF: MeshSkinned` without dismemberment, separate pixel programs include `renderstage_hair_alpha_accum` GUID **2782105832921211528**, SHA-256 `2b0f35971acfe9c38eb7fa304962a8ef9271357b9964fd743aacb93cf8a4267a`, and `renderstage_hair_basecolor_blend` GUID **7571795766366002052**, SHA-256 `7647ccdcb67473f7dcc90e415ad2591da70beaeceb2d9169b045b0a2c1bcbf23`. A further `renderstage_hair_gbuffer_solid` program is GUID **2903833597335136032**, SHA-256 `ade6c2a6fe7bf980b117e41a4eb2b296f7a71491cedcb18aca56ecd1b73808cc`. These are candidate template variants; no runtime trace proves which exact pass this saved mod invokes.

Disassembling the alpha-accum program with the installed Windows SDK `dxc -dumpbin` shows one sampled texture's **R** channel entering a threshold and position-dependent coverage calculation, followed by atomic accumulation into a 2D-array target. Because the saved alpha PNG has equal R/G/B, its selected scalar is source-consistent; the browser's simple alpha test and ordinary transparency do **not** reproduce this accumulation/order behavior. The base-colour program samples two material textures' red channels, uses those values to address a separate 2D colour texture, and performs additional colour operations; the later decode of those operations (a luminance-switched overlay) is in [hair shading](../../knowledge/hair-shading.md#3-base-colour). The serialized program does not label these resources, and the local source does not expose the runtime-generated colour texture or binding table. It therefore cannot justify replacing the current preview's product-plus-swatch fit with a purported exact REDengine value. These program observations are compiled-program evidence, not reconstructed editable shader source or a claim that the UI swatch equals rendered colour.

To reproduce the pixel-program inspection, run `bun projects/xf-studio/authoring/tools/extract-brow-shader.ts <GUID>` for each GUID above (the extractor is generic despite its name), then `dxc.exe -dumpbin` on the ignored `research/consumers/brow-shader/raw/<GUID>.dxbc`. The variant names and GUIDs come from the cache compilation metadata, using the same bounded parser format as `tools/inspect_shader_cache.ts`; extracted bytes and disassembly are deliberately untracked. See the earlier [source chain and illustrated-guide limits](brow-lash-fidelity.md#lash-colour-source-based-approximation-unresolved-hair-shader). The mod's creator, **icxrus**, supplied the custom geometry and alpha texture; the profile and shader are installed game resources. The community docs credited to **manavortex** explained the two profile lookup roles but did not provide the final per-pixel colour formula. WolvenKit supplied binary resource decoding; Windows SDK `dxc` inspected installed compiled bytes. No third-party code or assets were incorporated.

## Decision

No browser correction was accepted from this audit. The exact Soft Natural opacity image and its usable channel are already loaded; both colour-driving placeholders are spatially constant; the current swatch-calibrated colour is intentionally labelled approximate. A [25 September source follow-up](brown-liquorice-profile-overlap.md) found an enabled Alliekat `brown_liquorice.hp` candidate with materially different gradients alongside the pinned vanilla input. The archive resolver cannot yet prove which payload wins over the game base, so no automatic colour substitution follows. A different tint, alpha threshold, sorting mode or per-strand gradient would be speculative without a material-binding trace and a fixed camera/light game comparison. The most useful next evidence is a matched in-game close-up of this exact saved lash choice, plus the run's effective ArchiveXL and mod-resource bindings. That can decide whether to refine a cheap preview approximation or invest in modelling the game's separate hair passes.
