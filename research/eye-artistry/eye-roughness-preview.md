# Exact saved-eye roughness: opt-in browser study

24 September 2026. This is a local preview experiment, **not** a REDengine eye shader reproduction or a fix for the reported waxiness. It adds no game or mod textures to Git and does not affect recipes, makeup output, lip materials or export. The original diffuse-only eye material remains the default and the fallback for any unmatched or invalid local input.

## Source and bounded mapping

The saved `7132639559252259433` / `eye_16_diffuse` appearance is Kala’s Eyes Standalone V2 eye 16, selected via nutboy/brocreate’s Unique Eyes to CCXL bridge. The exact ignored source PNGs are `eye_16_diffuse.png`, SHA-256 `cc06290fe63cba59b42f11b97c06e364661e704c206b1e63a3b2c9420bc84d35`, and `eye_16_roughness.png`, SHA-256 `1d30af6b0fc1d742287b01f517a56eb9f8ca427f684b0f79b39b412232f42c9e`, both 512². The latter is consumed only when the saved appearance, definition and verified image hashes match a local `xfs/local-eye-assets-2` manifest. The manifest and images remain ignored under `public/assets/eyes/`; `bun tools/intake_eyes.ts` refuses different source bytes.

The [2.31 shader audit](eye-lip-optics-audit.md) established that this eye G-buffer variant samples roughness **R**, multiplies it by the `eye.mt` `RoughnessScale` default `0.493420988`, then writes the roughness output. The game cache SHA-256 is `339145371a3b5aaa08eb4ef82d558f445b632e28603ee0f3b4860270dfc3ccfa`, selected eye pixel shader GUID `14845425953312192161` / DXBC SHA-256 `38cc7fb4b2800be113c1075e428eb609a49036c5b8a61ca008286612926f42d3`, and `eye.mt` SHA-256 `c6eff77a473912680a5d3e2e439ef4fe6d9e664ee6238d0745e1e39b801e073e`. The new adapter copies raw PNG R bytes to G because Three.js `MeshStandardMaterial.roughnessMap` reads G; it sets scalar roughness to the recorded scale and leaves texture colour space linear. This is an explicit *browser approximation* of the one known arithmetic term, not a claim that Three’s BRDF or the game's full pass is equivalent.

The archived eye shader samples roughness at original interpolated UV while albedo/primary normal use a computed, view-dependent UV. The existing browser eye mesh has one folded UV0 for both eyes. Consequently this study shares that UV for diffuse and roughness. It does not reconstruct the packed RG normal Z, because orientation, tangent basis and `NormalBubble`/refraction composition are still unresolved; treating it as an ordinary Three RGB normal would be misleading. The study is opt-in under Head & lighting and persists with other preview settings only.

## Browser comparison and limits

At fixed 30° frontal camera, light angle 329°, exposure 1.2, saved Kala eye and hair/makeup disabled, I toggled source roughness on/off without camera or pose movement. At full-face and both-eye close-up, both iris reflections changed. The source-R mode produced a broader grey reflection in the centre of each iris; it did **not** make the eyes unequivocally less waxy. The eye outlines/texture registration did not visibly jump. The same toggle was exercised with the character-creator facial idle active, head motion muted, then paused; both eyes continued rendering and no browser shader error appeared. This checks gross alignment and shader compilation, not native UV equivalence or photographic fidelity. One close-up may hide smaller inverted-UV errors because the roughness map is low-frequency after mip filtering.

`bun test`, `bunx tsc --noEmit`, `bun run build` and `bun tools/intake_eyes.ts` are the project checks for this branch. The browser study used only a temporary ignored local save appearance JSON and an isolated test route; the route is removed from the committed source. Texture hash mismatch, decode failure or no exact saved choice leave the diffuse-only material active and report why when the study is requested. A game capture with matching pose, light, exposure and eye is still required to decide whether to promote or rework this optical approximation.
