# Saved brow and lash material study

24 September 2026. This is a browser preview correction for the reference save's Arkhe brow 18, not a claim of game-renderer parity. The selected geometry, saved identities, skinning, morphs, toggles and idle binding are unchanged. The game-derived and mod-derived images remain ignored local inputs; Git contains only adapter code, tests and findings.

## The resolved brow chain

The save selects app hash `10685882159528859062`, `ark_eyebrows_02_ccxl_18`, definition `10_brown_ombre`. The unique installed Arkhe II FULLER candidate and three source image hashes are established in [the provider audit](brow-texture-audit.md). The mod instance derives from `base\materials\mesh_decal_double_diffuse.mt`. A fresh hash-based extraction from the installed game's `memoryresident_1_general.archive` produced template SHA-256 `8546e26140c0a2af78495e20c50c077d686de35435608a253fb3e55ac876bfb7` (resource hash `10501783642502886761`). The installed 2.31 compiled `MeshSkinned` post-G-buffer shader GUID `8834363738920290566` has SHA-256 `8397be365eb46c682e35d452cc9de7bb11dd5fe30b9f2a00eb2c96164ae73133`; [the previous diagnostic](brow-lash-preview-diagnostic.md) traces its dataflow.

The instance overrides `DiffuseAlpha=1`, `SecondaryDiffuseAlphaIntensity=0.7`, `UseGradientMap=1`, `GradientMapIntensity=0.5`, primary colour `(103,81,71)` and secondary colour `(62,49,42)`. Current template defaults used by this instance are `AlphaMaskContrast=0`, `SecondaryMaskInfluence=0`, `GradientMapUV=1`; gradient sampler 1 clamps U/V. At default contrast, the observed coverage path simplifies to `p = primary.a`, `s = secondary.a`, `coverage = (p + (1-p)*s*0.7)^2`. This is **not** `primary.g`, which the old Three.js `alphaMap` sampled. The square occurs after texture filtering in the compiled shader. The adapter samples both RGBA maps in `onBeforeCompile` before combining them, rather than baking per-texel coverage and filtering that result. Tests include a filtered-edge counterexample.

The same shader replaces the primary tint path with a gradient sample at `(GradientMapUV, 0.5)` when enabled, multiplied by `GradientMapIntensity`, and adds the secondary colour path. A new hash-based extraction of Alliekat Natural Hair Tones' selected `hh_cap_grad__brown_ombre.xbm` produced resource SHA-256 `1dc22d5095808b62aacefb808af2c64115bf00ce366a40aa83acfe64f2a94dbd`, decoded 32×4 RGBA PNG SHA-256 `53cfa17949db9dd729de1d364754a2c9bb43c41a6e7448ab25f89e4eaf18a4cd`. The browser loads the audited primary (`5fac5306...56f`), secondary (`1684bedf...eaf`) and this gradient only through an ignored local manifest that binds the exact 64-bit app hash, definition, URL, dimensions and full SHA-256 of each image. A missing manifest keeps the old provisional material; invalid bytes show an error and fall back. `intake_brow_material.py --primary <decoded Arkhe diffuse PNG> --secondary <decoded Arkhe secondary PNG> --gradient <decoded Alliekat gradient PNG>` creates that manifest without modifying source archives. The gradient itself is not in Git.

The browser colour path is a **study approximation** of the compiled game's material path. It retains the two diffuse terms and saved gradient input, but MeshStandardMaterial lighting, tonemapping and sRGB conversion differ from the engine's post-G-buffer blend. The instance's packed normal texture and normal-coverage controls are not yet reproduced. The installed archive candidate is not proven to be the effective runtime winner. These limits matter for hair darkness and visual thickness; they preclude a parity claim.

A [separate base-game/Alliekat comparison](brown-ombre-gradient-equivalence.md)
subsequently found that the two XBM resources differ in metadata and smaller
mips, while all 128 decoded base-level RGBA texels are identical. The selected
shader samples the gradient at a constant `(1,0.5)`. Accordingly, Alliekat is
an installed provider candidate, but its base palette is **not a different
colour source** for this selected brow close-up. The Studio already uses those
same base pixels. This narrows the unresolved colour gap to the other material,
lighting and runtime-binding factors; it does not prove game parity.

## Controlled browser comparison

The isolated branch server ran at `127.0.0.1:4451/?verify=1`. AutoSave-12 was imported locally, the actual saved eye diffuse resolved, makeup/surface guides/hair were hidden, and brow/lash toggles remained on. The saved camera/pose was kept while comparing the new three-input shader with the former manifest-absent fallback. The browser reported no shader errors. At that pose, the new brow is darker and less opaque at its fringe; the fallback is visibly paler and fuller. ## Lash colour: source-based approximation, unresolved hair shader

**Superseded 25 September 2026** by the decoded `hair.mt` colour and hair-light model in [hair shading](../../knowledge/hair-shading.md) and the [colour evidence note](hair-colour-pipeline-2026-09-25.md); the swatch-fitted `#302d29` described here is historical.

The save selects Soft Natural Eyelashes `icxrus_softnaturaleyelashes`, `05_brown_liquorice` (app hash `6047185506343464350`). Its mesh's local `@lashes` material points at a dynamic `base\characters\common\hair\textures\hair_profiles\{material}.hp`. The vanilla `brown_liquorice.hp` resource hash `13919918321801903732` was present in the installed game's `basegame_4_appearance.archive`, not in the checked Hair Profiles CCXL archive. A later [selected-route source audit](brown-liquorice-profile-overlap.md) also found a **different, enabled Alliekat Natural Hair Tones candidate for this exact hash**; base-versus-mod precedence and the photographed session's effective binding remain unproved. The current private Studio intake still pins vanilla. Decoded CHairProfile SHA-256 `57b9999e9918137ada13e536ccc130caca48f6aca08290525063b54b9e2cdcec` contains four **ID-gradient** and four **root-to-tip** entries. They are shader inputs, not a direct RGB value. The latter runs from RGB `(109,105,105)` to `(214,197,174)`.

The source chain rules out inventing a detailed lash colour texture: Soft Natural's `.mi` overrides `Strand_Alpha` only and inherits `eyelashes__default.mi`, which overrides `Strand_Gradient` to vanilla placeholder `white.xbm`. Installed `base\materials\hair.mt` leaves `Strand_ID` at vanilla placeholder `grey.xbm`. Current decoded 32×32 placeholder pixels are constant `(255,255,255)` and `(107,105,107)` respectively, throughout the images. The grey and white decoded PNG hashes are `54add2f6f731ce8c208ec4f735140099c0d945357b0cf7f0b537c3f6517abac2` and `3ebfe32c143d33a422e093a51ee55cca1ebf575944aab6d5ed867412191d9140`. The installed Hair Profiles CCXL `.xl` patches vanilla `player_wa_lashes.mesh` but does not name this custom Soft Natural mesh. The custom mesh's own dynamic `@lashes` profile binding is observable in its serialized resource. A mod override elsewhere or runtime substitution is still possible, not proven here.

The [local Cyberpunk Modding Docs hair-profile page](../../../Cyberpunk-Modding-Docs/for-mod-creators-theory/files-and-what-they-do/file-formats/materials/hair-profiles-.hp.md) and [hair-material page](../../../Cyberpunk-Modding-Docs/for-mod-creators-theory/materials/configuring-materials/hair-and-skin-material-properties.md), clone commit `be2f44ee`, both credit manavortex and explain that `Strand_ID` selects the ID gradient and `Strand_Gradient` selects the root-to-tip gradient. Neither hair section has an illustrative screenshot. The second page's two referenced images, `.gitbook/assets/skin_shader_microdetail_scale.png` and `skin_shader_UV_scale.png`, were inspected; they explain skin microdetail/UV layout, not lash colour. These guides support the lookup concept, not exact runtime lighting or gradient composition.

The ignored `public/assets/lashes/profile.json` is generated by `intake_lash_profile.py` from hash-checked local game resources. It binds the exact saved app and definition, the two constant sampled pixels, both profile gradient arrays and the saved selector swatch `(50,44,40)`. The browser sorts the unsorted ID stops and interpolates at `107/255`, yielding approximately `(106.37,108.25,109.91)`; the white root-to-tip lookup reaches `(214,197,174)`. Channelwise multiplication gives about `(89,84,75)`. A single exposure fit to the saved UI swatch gives displayed `#302d29` instead of the former hand-chosen `#30221b`. This is a **source-driven colour approximation**, not a decoded REDengine hair-shader output. The resulting slight neutralisation of the lashes visually moves toward the in-game reference photograph, but cannot establish a colour match because the game's anisotropic reflection, scattering, tonemapping, shadows, and actual effective runtime resources remain unresolved. Since the source textures are constant, adding artificial per-strand/root-to-tip variation would be less truthful than keeping this profile colour spatially uniform. Alpha, geometry, morphs and the toggle remain as before.

A [24 September compiled-program follow-up](lash-material-followup.md) verifies the exact preview alpha-image digest and `#302d29` result, then finds separate hair alpha-accumulation and base-colour passes in the installed 2.31 shader cache. That evidence does not yield an exact game RGB or ordering formula for this saved mod, so no speculative lash material change followed.

## Reproduction and provenance

`WolvenKit.CLI.exe unbundle <archive> --hash <decimal resource hash>` and `convert serialize` inspected the current binary resources; `uncook --uext png` decoded placeholder images, and `export --uext png` decoded the Alliekat gradient. The local CLI was 8.17.4, game 2.31. The browser source uses Three.js 0.186.0; its `alphaMap` green-channel rule led to the brow correction, and `extendSkin` now composes an existing material shader hook rather than replacing it. `bun test` passed 208 tests, `bun run check` and `bun run build` passed. The browser comparison used only the isolated verification workspace; its UI explicitly labels the lash colour approximate. No game launch, installation or distribution of third-party assets occurred.

Community learning and tool use: [Arkhe's Beautiful EYEBROWS II](https://www.nexusmods.com/cyberpunk2077/mods/26168) supplied the saved style/material; [Alliekat's Natural Hair Tones](https://www.nexusmods.com/cyberpunk2077/mods/15787) supplied the installed gradient candidate; [icxrus's Soft Natural Eyelashes](https://www.nexusmods.com/cyberpunk2077/mods/29582) supplied the lash geometry/material chain; [redacted-c01's Hair Profiles CCXL](../../docs/community-credits.md) clarified that a dynamic hair-profile overlay may affect the binding; [WolvenKit](https://github.com/WolvenKit/WolvenKit) decoded the local resources.
