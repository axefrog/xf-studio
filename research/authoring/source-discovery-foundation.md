# Source discovery foundation

24 September 2026. `authoring/src/source-discovery.ts` is a read-only local inventory for the configured launch route. It accepts the validated `xfs/local-settings-1` settings and returns typed `SourceCandidate` rows, loose-file assessments, issues and explicit limits. The two adapters scan (1) `gameRoot/archive/pc` plus an optional `manualModRoot/archive/pc` install-shaped tree for direct launches, and (2) those same physical game/manual files plus a selected MO2 profile's listed mod directories and overwrite for MO2 launches. Direct mode excludes staged MO2 content. Only `.archive`, `.xl`, loose `.inkcharcustomization` and `archive/pc/mod/modlist.txt` are inventoried. No archive is opened, extracted or copied.

Every candidate records virtual path, physical path, route/profile, provider, active state, MO2 priority evidence where applicable, size, modification time and discovery time. `sha256` is deliberately null pending a separate bounded fingerprint stage. Disabled MO2 mods remain candidates for diagnosis. The scanner validates settings and profile names, rejects invalid/duplicate modlist rows, skips links and non-files, and bounds total entries, depth and profile byte size. Any scan error or truncation makes the result incomplete and suppresses loose-file precedence conclusions. A fresh call re-reads files; this stage has no persistent cache. Physical paths and profile names are private host metadata and must not enter portable recipes, collections or public manifests.

`looseFiles` groups physical candidates by case-insensitive virtual path. It may select `sourceDerivedFirst` when one active candidate exists in the scanned roots, or when only MO2 mods/overwrite compete and their profile priority is distinct. Game/manual collisions remain ambiguous. `runtimeObservedWinner` is always null. Archive candidates are not assigned a resource/depot winner by this API. A profile `+` means selected activation intent only; neither a selected route nor a physical file proves what a specific game run loaded. This distinction follows the [local catalog prototype](../character-customization/catalog-prototype.md) and [MO2 source-resolution research](../character-customization/mod-source-resolution.md).

The next stages need selected archive-index/hash inspection, route-specific archive order and visible `modlist.txt` interpretation, base-versus-mod resolution, ArchiveXL registration/patch/scope/fix/merge processing, REDmod and other deployment transforms, cache fingerprints/invalidation, and independent runtime trace evidence. Do not infer those from the inventory. The API is not wired to UI, package compilation or installation. Synthetic adapter fixtures live in `authoring/tests/source-discovery.test.ts`; no game/mod payload or personal path is tracked.
