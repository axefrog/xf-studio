# XF Studio presentation boundary — incremental extractions

24 September 2026. This is an incremental implementation checkpoint, **not** the completed gate for the Opus 5.5 UI overhaul. See [the delegation brief](../backlog/claude-ui-overhaul.md) for that gate.

## What is now independent of controls

`authoring/src/collection-actions.ts` exposes typed in-process commands for preset add/copy/rename/move/remove/restore/select/expand; collection rename, open, undo-open and recipe import; and save-result reconciliation. The adapter returns a detached read-only-by-copy view, provides `capability(action)` with a disabled reason for known invalid targets, and can notify subscribers after successful commands. It calls the existing `CollectionSession`, so draft switching, per-preset editor memory, stable identities, recovery and in-flight save reconciliation still follow the same validated rules. `collection-ui.ts` now routes these operations through the controller. The view retains HTTP, files, downloads, package request and DOM concerns; those are not controller commands yet.

`authoring/src/editor-actions.ts` provides typed `layer.edit` and `layer.setEnabled` operations over recipes, plus target-aware capability checks. The returned recipe is validated; its source is not mutated. `main.ts` routes layer-list actions, including visibility, through that path. `RecipeHistory` now owns the existing deduplicated, bounded 80-entry history and returns detached snapshots. The current controls and surface gestures still call `checkpoint` and `undo` in `main.ts`, which delegate to that class. Structural layer changes still trigger the original full slot replacement; visibility still redraws only its affected slot.

The second extraction adds `authoring/src/recipe-actions.ts`. It exposes target-aware typed actions and capability reasons for layer selection, point selection/removal, Bézier conversion/mode, warp selection/add/remove/clear/reach, pigment strength and edge softness, colour/opacity/symmetry/finish, and all current Glitter preview-model settings. It validates a proposed recipe before publishing and keeps untouched layer object identities so deferred per-layer renders are not lost if another layer changes before the next frame. The controller returns detached read-only snapshots and notifies subscribers after successful actions. The present UI adapters now dispatch these actions; a discrete action records one recipe Undo entry, while slider gestures still use their existing begin hooks so a continuous interaction produces one entry. Renderer scheduling remains in `main.ts`, using the action's target layer and immediate/scheduled effect. Glitter model comparison memory remains workspace-only; only the selected model/settings enter the portable recipe.

These are internal commands, not a network or plugin execution interface. The collection/layer action IDs are `preset.edit`, `preset.select`, `preset.expand`, `collection.rename`, `collection.filesOpen`, `collection.open`, `collection.undoOpen`, `collection.importRecipe`, `collection.saved`, `layer.edit`, and `layer.setEnabled`. Recipe action IDs are `layer.select`, `point.select`, `point.remove`, `path.edit`, `field.select`, `field.add`, `field.remove`, `field.clear`, `field.setReach`, `pigment.edit`, `softness.edit`, `layer.setColor`, `layer.setOpacity`, `layer.setSymmetry`, `layer.setFinish`, `glitter.selectModel`, `glitter.setClassic`, `glitter.setIrregular`, and `glitter.setDirect`. Collection, layer and recipe capability checks are synchronous; validation remains authoritative at dispatch. A future menu may query capabilities, then dispatch the same command. A stale target after the query is still rejected at dispatch.

## Remaining coupling and next phases

1. `main.ts` still owns mutable `recipe`, selection variables, workspace snapshot and autosave timing. The extracted controller reads and writes through callbacks rather than owning the document as the sole authority. UV and on-head pointer adapters still mutate live points, tangents, fields and whole shapes during gestures; their begin/change/cancel hooks remain in `main.ts`. Move those operations behind the same action boundary with explicit gesture begin/update/commit/cancel transactions and target-staleness checks, then make application state authoritative. Preserve the current mirrored mapping, surface validity, shape rejection and whole-gesture Undo/Escape. Renderer/raster scheduling should subscribe to changes rather than each handler deciding how to schedule them.
2. `collection-ui.ts` still owns transport, import/export files, package requests, busy state, status text and initial legacy draft merge. Split these into injected application services, with typed async progress/results, conflict/retry handling and stale-request protection. Keep SQLite revision rules in the existing store. The controller should own the collection draft and subscribe to editor state, eliminating the current read/show callback cycle.
3. `main.ts` still creates the Three scene, mask worker, canvases, surface and UV editors and controls their lifecycle. Define a viewport adapter with explicit attach/detach/resize, input capture, selection/picking and render-request contracts. Preserve the current surface constraints, worker cancellation and complete-bundle publication. Do not expose scene objects or worker messages to the presentation.
4. Workspace persistence still reads DOM fields and layout details in `snapshot()` and uses document-wide input/change/click autosave listeners. Separate durable authoring/preview preferences from replaceable dock layout state, subscribe to application-state changes, and restore through typed commands without changing recipe or SQLite formats.
5. Complete the action catalogue with IDs, parameters, target scope, capability reasons, Undo/transaction behavior, async behavior and examples. The current recipe capability check covers target existence and relevant modes, with final recipe validation at dispatch; it does not yet publish the full structured disabled-reason taxonomy or export eligibility. Include viewport/camera/light/animation, asset and saved-V selection, quality, imports/exports/builds, and every pointer editing tool. Add contract tests and isolated browser acceptance scenarios before Opus receives the redesign branch.

The existing sidebar/accordion markup is an implementation of today's UI, not a design constraint. This extraction makes no aesthetic or layout decision. The current branch has no dockable-panel implementation, and the handoff gate remains unmet.
