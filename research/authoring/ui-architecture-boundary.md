# XF Studio presentation boundary — incremental extractions

24 September 2026. This is an incremental implementation checkpoint, **not** the completed gate for the Opus 5.5 UI overhaul. See [the delegation brief](../backlog/claude-ui-overhaul.md) for that gate.

## What is now independent of controls

`authoring/src/collection-actions.ts` exposes typed in-process commands for preset add/copy/rename/move/remove/restore/select/expand; collection rename, open, undo-open and recipe import; and save-result reconciliation. The adapter returns a detached read-only-by-copy view, provides `capability(action)` with a disabled reason for known invalid targets, and can notify subscribers after successful commands. It calls the existing `CollectionSession`, so draft switching, per-preset editor memory, stable identities, recovery and in-flight save reconciliation still follow the same validated rules. `collection-ui.ts` routes these operations through the later `CollectionService`.

`authoring/src/editor-actions.ts` provides typed `layer.edit` and `layer.setEnabled` operations over recipes, plus target-aware capability checks. The returned recipe is validated; its source is not mutated. `main.ts` routes layer-list actions, including visibility, through that path. `RecipeHistory` now owns the existing deduplicated, bounded 80-entry history and returns detached snapshots. The current controls and surface gestures still call `checkpoint` and `undo` in `main.ts`, which delegate to that class. Structural layer changes still trigger the original full slot replacement; visibility still redraws only its affected slot.

The second extraction adds `authoring/src/recipe-actions.ts`. It exposes target-aware typed actions and capability reasons for layer selection, point selection/removal, Bézier conversion/mode, warp selection/add/remove/clear/reach, pigment strength and edge softness, colour/opacity/symmetry/finish, and all current Glitter preview-model settings. It validates a proposed recipe before publishing and keeps untouched layer object identities so deferred per-layer renders are not lost if another layer changes before the next frame. The controller returns detached read-only snapshots and notifies subscribers after successful actions. The present UI adapters now dispatch these actions; a discrete action records one recipe Undo entry, while slider gestures still use their existing begin hooks so a continuous interaction produces one entry. Renderer scheduling remains in `main.ts`, using the action's target layer and immediate/scheduled effect. Glitter model comparison memory remains workspace-only; only the selected model/settings enter the portable recipe.

The third extraction puts UV and on-head gesture proposals through `RecipeActions.applyGesture`. The adapters still perform input capture, picking, coordinate conversion, mirrored mapping and gesture bookkeeping, but they no longer write live recipe points, fields or whole shapes. Each proposed edit carries its layer identity (and point/field identity where relevant), is parsed against the current recipe schema before publication, and schedules only its affected layer. Existing gesture start/cancel hooks retain the one-step Undo and Escape behaviour. `ViewportAdapter` gives the two editors explicit attach/detach/resize/cancel/capture lifecycle; detach removes their listeners and render resources. `PreviewActions` provides DOM/Three-independent commands, detached camera/preference snapshots and capability reasons for FOV, front view, exposure, key light, surface guides, wireframe, normals, eye optics and brow/lash/hair visibility. Orbit/pan camera state is read through its injected port when snapshotted, including changes made by the renderer controls.

The fourth extraction adds `CollectionService` and an injected `CollectionTransport`. List/load/save/copy/export/import/package sequences, legacy-draft merge, immutable request snapshots, busy/progress/success/error state and capability reasons now live outside `collection-ui.ts`. The service preserves editor changes made while a save is in flight and refuses to reconcile a save response onto a different collection identity. Package checks/builds use the unsaved draft snapshot without writing SQLite; the server's `unsupported_finish` code and plain-language layer-specific message remain available to a future UI. The current view still reads a selected local file and initiates a download, but it no longer chooses request order, draft reconciliation or package result text. The HTTP adapter retains the current local endpoints and SQLite rules.

The fifth extraction adds `MotionActions`, `PreviewQualityActions` and `SavedAppearanceActions`. Motion restore, pause, head/facial contribution switches, blink commands and readable state are independent of the controls; the renderer's phase and animation implementation remain injected. Quality tier validation, selection and recoverable error state are similarly separate, while `main.ts` still owns worker cancellation, texture disposal and render ordering through an injected replacement callback. Saved-V parsing, validation, application and suggested eye selector value form one command; the view only selects a local file and paints the result. `PreviewActions` now also covers eye-shape and piercing visibility/style/colour, with available choices supplied by the renderer port. These services publish detached snapshots, subscriptions and capability reasons. No portable recipe or SQLite format changed.

The sixth extraction adds `AuthoringDocument` and `WorkspacePersistence`. The former is the live in-process owner of recipe, active layer/point, selected warp and Undo history; `main.ts` reads and publishes these through it instead of retaining parallel top-level variables. It provides change subscriptions, detached snapshots, validated atomic restore and the original bounded/deduplicated history. Gesture proposals still preserve live layer identity and explicitly publish their in-place change. The latter owns the 180 ms autosave, explicit activation after startup, page-hide/visibility flush, isolated verification key, and the protected-storage policy when restore failed. It receives an injected workspace capture and storage port. Workspace and recipe schemas remain unchanged.

These are internal commands, not a network or plugin execution interface. The collection/layer action IDs are `preset.edit`, `preset.select`, `preset.expand`, `collection.rename`, `collection.filesOpen`, `collection.open`, `collection.undoOpen`, `collection.importRecipe`, `collection.saved`, `layer.edit`, and `layer.setEnabled`. Recipe action IDs are `layer.select`, `point.select`, `point.remove`, `path.edit`, `field.select`, `field.add`, `field.remove`, `field.clear`, `field.setReach`, `pigment.edit`, `softness.edit`, `layer.setColor`, `layer.setOpacity`, `layer.setSymmetry`, `layer.setFinish`, `glitter.selectModel`, `glitter.setClassic`, `glitter.setIrregular`, and `glitter.setDirect`. Collection, layer and recipe capability checks are synchronous; validation remains authoritative at dispatch. A future menu may query capabilities, then dispatch the same command. A stale target after the query is still rejected at dispatch.

## Remaining coupling and next phases

1. `AuthoringDocument` now owns the live recipe, selection and history, but some trusted in-process adapters still receive the mutable layer identity needed for gesture proposals and the controller still reads/writes through `main.ts` callbacks. Its setters do not independently validate each intermediate write; validation occurs in the existing actions and full restore. Pointer begin/commit/cancel transactions and editor view memory still reside in adapters and `main.ts`; the API does not expose a complete tool/gesture catalogue or transactional preview state. Move gesture transactions behind an application command boundary while preserving mirrored mapping, surface validity, shape rejection and one-step Undo/Escape. Renderer/raster scheduling should subscribe to state changes rather than each handler deciding how to schedule them.
2. `CollectionService` now owns the async sequences and local draft merge, but the view still chooses local files and downloads, and the editor remains an injected read/show callback pair. The service serializes requests and returns error codes, including conflict and unsupported finish; a future application shell should add explicit retry/cancellation policy for long-running package builds and make the editor state subscription authoritative. Keep SQLite revision rules in the existing store.
3. `main.ts` still creates the Three scene, mask worker, canvases and editors. The new viewport lifecycle covers attach/detach/resize/capture, but selection/picking, render requests, camera orbit/pan and worker resource ownership are still concrete-adapter concerns. Expose those as typed ports where useful without passing scene objects or worker messages to the presentation. Preserve surface constraints, cached occlusion, worker cancellation and complete-bundle publication.
4. `WorkspacePersistence` owns autosave timing and protected-write policy, but its `main.ts` capture still reads layout and some preview values from DOM fields, and presentation adapters still use document-wide input/change/click listeners for those values. New preview services own their corresponding values; `main.ts` still assembles the saved workspace and owns the quality resource callback. Separate durable authoring/preview preferences from replaceable dock layout state and subscribe to a single application state stream without changing recipe or SQLite formats.
5. Complete the action catalogue with IDs, parameters, target scope, capability reasons, Undo/transaction behavior, async behavior and examples. The current recipe capability check covers target existence and relevant modes, with final recipe validation at dispatch; gesture proposals currently have no public capability query. The catalogue does not yet publish a full structured disabled-reason taxonomy or export eligibility. Include asset availability and picker operations, async package cancellation/retry, and every pointer editing tool. Add contract tests and full isolated browser acceptance scenarios before Opus receives the redesign branch.

The existing sidebar/accordion markup is an implementation of today's UI, not a design constraint. This extraction makes no aesthetic or layout decision. The current branch has no dockable-panel implementation, and the handoff gate remains unmet.

## Verification

The full authoring suite passes (268 tests), along with TypeScript check and browser bundle build, after the three ignored local GLB preview fixtures are present in the isolated worktree. Those files are test inputs only and remain ignored. New contract tests cover document snapshot isolation, atomic invalid restore, Undo history, debounced latest-state save, verification-key isolation and protected/failed storage writes. In isolated `?verify=1` browser sessions, Add warp produced a second control, Undo removed it, and a subsequent Add warp survived reload with its Undo history; Undo after reload removed it again. Prior sessions also confirmed an unsaved Glitter finish produced the server's specific export warning for that layer, while saved collections remained at their previous revision, and list refresh and page reload both retained the unsaved finish. Preview texture size changed from 1K to 512 and persisted after reload. The head preview reported an asset/renderer error in that isolated worktree, so this is not evidence for live saved-V, on-head, camera, idle or piercing interaction or renderer fidelity. No game runtime was performed for these extractions.
