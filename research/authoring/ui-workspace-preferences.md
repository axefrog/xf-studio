# UI workspace preferences contract

24 September 2026. `authoring/src/ui-preferences.ts` defines a workspace-only preference record, `xfs/ui-preferences-1`. It is included in the existing `xfas/workspace-1` browser document as `uiPreferences`; it never enters portable makeup recipes, SQLite collection revisions, build plans or mod files. Older workspaces have no `uiPreferences` property and load with `{theme:"system"}` and no saved dock layout. Invalid theme values fall back to System; a malformed layout is omitted without losing the authored workspace. The existing workspace storage key and recipe schema are unchanged.

`theme.set` accepts `system`, `light` or `dark`. System is the default and resolves against the live OS preference; the override is retained independently of the OS setting. `UIPreferenceActions` publishes detached snapshots, capabilities and change notifications. A future presentation should subscribe it to `WorkspacePersistence.request()` and pass its snapshot through the optional `WorkspaceComposer.uiPreferences()` port. Current `main.ts` supplies no such port, so this checkpoint adds persistence capability without changing today's visible UI.

Dock layout is an **opaque** `{format,version,state}` JSON envelope. Generic validation bounds it to 128 KiB, 8,192 nodes and depth 32, rejects cycles, non-finite numbers, unsupported values and unsafe object keys, then makes a detached JSON copy. It does not assume a split tree, tab structure, panel positions or visual design. The panel implementation owns its format/version and must supply a recovery adapter before applying saved state.

`recoverDockLayout(saved, {workAreas,panelIds}, recover)` returns no layout when the envelope, current screen description or recovery adapter is absent/invalid. The adapter must recognize its own format, check current panel identities and inspect its own geometry against the supplied display work areas. It must move, clamp or dock inaccessible floating panels and certify that the result is on-screen; otherwise it rejects the layout and the UI uses its safe default. Generic code cannot prove that an opaque panel tree is visible. A successful recovery is rechecked for JSON bounds and matching format/version. Saved opaque data may remain in the workspace even when the current UI uses its default; a future compatible panel engine can try recovery without changing authored work.

This is a port contract, not a dock model. The panel implementation must still satisfy the [Opus handoff brief](../backlog/claude-ui-overhaul.md): dock/float/magnetic/tab behavior, cursor-position snapping, keyboard alternatives and off-screen recovery. An integration check should restore a layout after narrowing the window, changing monitor topology and removing a panel, and verify that every necessary panel remains reachable. Light/dark/system choice, layout restore and invalid-layout fallback should be tested in `?verify=1` without touching Nathan's draft. The pure preference and workspace migration tests cover the current code boundary; no UI or docking behavior has been implemented here.
