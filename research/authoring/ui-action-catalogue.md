# XF Studio action and capability catalogue for the UI handoff

**Desktop update gate, 25 September.** `GET /api/desktop/update` returns a detached `xfs/desktop-update-1` snapshot with installed version/channel/hash, optional checked update, phase, disabled reason and separate `canCheck`, `canDownload`, `canApplyAndRestart` capabilities. `POST /api/desktop/update` accepts only `{schema:"xfs/desktop-update-action-1", action:"check"|"download"|"applyAndRestart"}` after the existing session and same-origin write checks. Each dispatch is explicit user consent for that one stage; `applyAndRestart` additionally asks in the desktop About view. The trusted host owns the feed, signing and trial gates; the browser cannot supply an update URL, path or hash. No action changes a recipe, Undo or SQLite revision. Production is disabled pending the recorded acceptance gates; the host test exercises refusal and the pure two-version harness exercises the transition policy. [Service](../../projects/xf-studio/authoring/desktop/update-service.ts), [host tests](../../projects/xf-studio/authoring/desktop/tests/update-service.test.ts).

**Desktop shell extension, 25 September.** The private Electrobun host exposes `GET /api/desktop/capabilities` only behind its loopback session cookie. Its detached read-only snapshot reports packaged `version`, `channel` and `buildHash` from `Resources/version.json`, the shell's `userDataPath`, preview-asset presence, package Check support and explicit `false` for package Build, installation and updater. The desktop-only About control and missing-assets first-run state consume that snapshot; they have no recipe/Undo effect and no writable path action. The endpoint rechecks preview-asset presence on each read. An unavailable host or invalid packaged metadata fails visibly rather than borrowing a source `package.json` version. The localhost entry has no desktop About/update action. Desktop `package.check` snapshots unsaved work through the existing file workflow; its host validates and compiles in a fresh Bun worker with a 15-second deadline, one active Check at a time, and a complete result or typed error. It never changes the recipe, history or SQLite revision. [Host contract](../../projects/xf-studio/authoring/desktop/host.ts), [transport test](../../projects/xf-studio/authoring/desktop/tests/server.test.ts), [packaging gate](../../projects/xf-studio/authoring/desktop/verify-canary.ts).

24 September 2026. This is a source audit of the **current in-process API**, not a promise that every capability is already one public command. It complements the [functional inventory](ui-capability-inventory.md) and [Opus handoff brief](../backlog/claude-ui-overhaul.md). The command strings below are exact implemented `kind` values unless a section explicitly says **missing/proposed**. They are TypeScript application boundaries, not an HTTP scripting endpoint. A new UI should preserve validation, Undo, persistence and results through these boundaries; it should not mutate a snapshot, invoke a hidden DOM button or write SQLite directly. `StudioApplication` now aggregates `snapshot/subscribe`, exact action/request/gesture descriptors, `actionsFor` and `descriptorsFor(target)`, `capability/dispatch`, `contextCapability(target,action)` for concrete target/payload checks, `choicesFor(target,kind,field,base?)` for enumerated choices with current capability, `requestCapability/execute`, and explicit control/gesture transactions. The registry covers all 60 implemented public top-level action IDs, nine async request IDs and four low-level gesture proposals at compile time. A descriptor identifies payload types, required fields, target versus input sources, nested variants, static limits, scope and Undo/async policy; it does **not** predict every final parser constraint. Renderer-supplied piercing labels/definitions are now a detached application snapshot; other dynamic asset choices still need similar ports. The service-specific contracts below remain authoritative.

## How to read and query the current API

For a replacement presentation, obtain `StudioPresentationPort` from the trusted composition root. Its grouped `authoring`, `library`, `files`, `viewport`, `preferences` and read-only `previewReadiness` surfaces are the current callable contract; `snapshot()` combines detached state and `subscribe()` covers all six sources. Readiness reports `ready`, `updating` or `blocked` from current worker/resource state, not merely the selected resolution. The port forwards actions to the existing validators and does not expose the authoring document, renderer, worker or storage transport. The one composition root, `studio-startup.ts` (started by the localhost entry `studio-main.ts` and by the desktop bootstrap), constructs it and passes it to `studio-ui/`; `tests/trusted-studio-bootstrap.test.ts` also mounts it with no page controls. [Composite port](../../projects/xf-studio/authoring/src/studio-presentation.ts), [independent browser acceptance](ui-port-acceptance-2026-09-24.md).

A menu can pass the actual hit layer ID to `choicesFor({kind:"layer",id}, "layer.setFinish", "finish")`; each finish value carries a candidate action and current structured capability. For a form or keyboard command with a concrete value, call `contextCapability(hitTarget, action)` before showing/enabling it, then call `dispatch(action)` when invoked. The latter validates again in case the document changed. A missing required value returns `needs_input`; a mismatched hit target returns `missing_target`; a value outside a declared range returns `limit`. `capability(action)` itself applies the same payload types and ranges, so `dispatch` and `controlEdit` refuse out-of-range values too. An exception after that gate is classified by source: a collection service code, `unavailable` for preview/camera/motion/quality devices, `internal` for a programming fault, otherwise `invalid_value`. These checks do not turn the static schema into a complete parser or discover whether a coordinate hits the shape.

**Cheap read-only views (added 24 September for the redesigned presentation).** `port.editor.recipe()/layer()/active()/selected()/selectedField()/revision()/canUndo()` read the cached detached editor view; `library.summary()` returns a primitive projection (collection id/name/revision, presets with live layer counts, removal stack, previous draft) without cloning histories; `authoring.previewState()` returns preview/motion/quality/saved-V/gesture/control state without the document or collection; `authoring.finishCatalogue()` and `glitterModelCatalogue()` return labels, descriptions and export status mirroring the compiler gate; `port.status.snapshot()` reports browser autosave, preview asset diagnostics, Glitter measurements and the latest adapter message. Use these for painting; `snapshot()` clones every Undo history and is for diagnostics. The custom target-aware context menus, command palette, dock/float/magnetic/tab panel system and theme preference are now implemented in `src/studio-ui/` ([delivery record](ui-overhaul-2026-09-24.md)).

For current context-menu hits, `ViewportAttachment.contextAt(source,clientX,clientY)` uses the existing UV or on-head editor picker and calls `StudioApplication.contextQuery(hit)`. It returns the source, mirrored instance and visual affordance, plus a bound context for `uv-empty`, `head`, `shape`, `point`, `tangent` or `field`, relevant **existing** command candidates and each candidate's current capability. Layer, preset and collection rows can call `contextQuery` directly with their stable IDs. Input candidates carry `requiresInput:true` and a command/variant ID; after collecting a value, call `boundActionCapability(context, action)`, then `dispatchContext(context, action)`. Dispatch rechecks the target, collection/preset identity, geometry revision for layer/shape/point/tangent/field hits, payload, domain capability and final parser. An unrelated command or a stale bound context is refused. Empty UV space has no standalone edit command yet; pan/zoom and coordinate-based insertion remain adapter gestures, so the query returns no invented action. Pickers classify most specific first: a visible control of the selected layer (on-head only while surface controls are on), then painted makeup (the selected layer, then the frontmost other visible layer, so a right-click on another layer's makeup offers *Select this layer*), then bare character geometry (`head`: skin, eyes, plate or another visible detail, never makeup hidden behind them) or `uv-empty`. Only a position with no geometry at all (or outside the canvas) is no hit, the true background. This is read-only hit discovery, not a menu UI or a second geometry evaluator. [Viewport attachment](../../projects/xf-studio/authoring/src/viewport-attachment.ts), [hit context builder](../../projects/xf-studio/authoring/src/studio-context-targets.ts), [facade](../../projects/xf-studio/authoring/src/studio-application.ts).

## Exact commands: collection, preset and library

`CollectionAction` targets the **current draft**. `preset.edit.command` is a nested discriminated union; its inner `kind` is not a top-level command ID. IDs are UUIDs. Collection edits do not create a recipe Undo entry; preset removal has its own last-20 recovery stack, and opening/importing a collection has a separate four-draft browser recovery queue. Switching presets stashes the recipe, selected layer/point/field and up to 80 recipe Undo entries for the outgoing preset. [Collection session](../../projects/xf-studio/authoring/src/collection-session.ts), [workspace operations](../../projects/xf-studio/authoring/src/collection-workspace.ts).

| Exact action/payload | Target, result and capability/validation |
|---|---|
| `preset.edit` `{command:{kind:"add"}}` | Collection; add empty preset with fresh stable ID, select it. No explicit fixed preset cap. |
| `preset.edit` `{command:{kind:"copy"|"remove",id}}` | Named preset ID. Copy gets a new ID; remove can be restored. Missing ID disables. |
| `preset.edit` `{command:{kind:"rename",id,name}}` | Named preset ID; trimmed, nonempty name up to 120 characters is validated at dispatch. |
| `preset.edit` `{command:{kind:"move",id,to}}` | Named preset ID and zero-based destination in current order. Invalid index or stale ID disables. Stable ID survives reorder. |
| `preset.edit` `{command:{kind:"restore"}}` | Restore most recently removed preset at its old position with editor memory. Disabled if removal stack is empty. |
| `preset.select` `{id}` | Draft selection; preserves the outgoing preset's editor state. Unknown preset disables. Workspace state, not recipe Undo. |
| `collection.rename` `{name}` | Current collection name. Invalid collection name fails validation. |
| `collection.open` `{collection,revision?}`; `collection.undoOpen` | Open a validated collection object; add the current draft to the bounded recovery queue. Recover walks the queue, keeping the draft left behind reachable. `collection.undoOpen` capability reports availability; the summary projects the next draft, queue count/limit and oldest draft for a capacity warning. In normal UI, use async `CollectionRequest.open` to fetch by ID first. |
| `collection.importRecipe` `{recipe,name}` | Add an imported recipe as a **new preset**; preserves existing presets. File reading/1 MB budget is outside this command. |
| `collection.saved` `{result,sourceId}` | **Internal reconciliation**, not a user command: update saved identity/revisions after transport returns, retaining in-flight draft edits and rejecting a different current collection. |

`CollectionRequest` is the async/library and file-data layer. `execute` serializes requests through `busy`; save/export requests snapshot the draft before transport. `StudioFileOperations` now wraps local file selection/download and mask baking through a typed device port, then delegates collection validation, package outcomes and recovery to the existing service. [Collection service](../../projects/xf-studio/authoring/src/collection-service.ts), [file workflow service](../../projects/xf-studio/authoring/src/studio-file-operations.ts).

| Exact request/payload | Effect, side effect and recovery |
|---|---|
| `initialize`; `refresh` | List SQLite collection summaries; initialize merges a legacy draft if no restored collection, or creates an unsaved one-preset draft from the current workspace when the library is empty. No SQLite write until Save. |
| `open` `{id}` | Fetch saved collection by ID, then open as a recoverable prior-draft switch. ID must still be in the current list; otherwise refresh. |
| `save`; `saveCopy` | SQLite immutable revision; copy creates a new collection ID. Transport enforces revision conflicts. Edits made during the request remain in the live draft; a stale result for another draft is rejected. |
| `exportCollection`; `exportPlan` | **Save first**, then return portable collection JSON or a compiler build-plan JSON and filename for a download adapter. A build plan is not a mod. These operations can cause a SQLite write or conflict. |
| `import` `{text,bytes}` | Parse a portable collection (current 16 MB budget) and open it as a recoverable draft switch. Invalid JSON/schema leaves current draft. File acquisition is outside the service. |
| `package` `{action:"check"|"build"}` | Snapshot the **unsaved** draft without saving SQLite. Check reports eligible retained presets and every omitted active unsupported layer/whole preset; Build creates an offline-verified private candidate if content remains. Both use the same package filter. Build uses a localhost server, one build at a time, and cannot be cancelled by closing the page. Neither installs or game-tests a mod. Errors include no exportable content, invalid input, missing local resources and verifier failure. [Package contract](studio-to-mod-pipeline.md). |

## Exact commands: layer structure and recipe editing

`LayerAction` is `{kind:"layer.edit",command:LayerCommand}` or `{kind:"layer.setEnabled",id,enabled}`. Its nested commands are `add`, `duplicate(id)`, `remove(id)`, `reset(id)`, `rename(id,name)` and `move(id,to)`. The layer array is **bottom-to-top**; `to` is zero-based. Add creates a mirrored four-point Bezier upper-lid wash without a warp field. Reset applies that starting shape while preserving ID/name; duplicate gets a new ID and keeps its source geometry. Removing the last layer is legal. `AuthoringLayerActions` checkpoints, and the preview coordinator replaces/render-reschedules the stack for structural edits and redraws the affected slot for visibility. `layer.setEnabled` is a recipe edit, not a view-only hide. [Layer stack](../../projects/xf-studio/authoring/src/layer-stack.ts), [layer actions](../../projects/xf-studio/authoring/src/authoring-layer-actions.ts).

`RecipeAction` uses stable `layerId` for every variant. A selected point still uses an **index**, not a stable point ID. The wrapper has `dispatch(action, record=false)`: discrete callers explicitly request one Undo checkpoint, while slider controls use separate start hooks to avoid one history entry per intermediate value. Selection effects do not record Undo; content edits validate the complete proposed recipe before publication. Render effects are `selection`, `scheduled` or `immediate`, with affected layer index. [Recipe actions](../../projects/xf-studio/authoring/src/recipe-actions.ts), [render scheduler](../../projects/xf-studio/authoring/src/authoring-render-scheduler.ts).

| Exact action/payload | Target and effect; current capability or final validation |
|---|---|
| `layer.select` `{layerId}`; `point.select` `{layerId,index}` | Workspace editor selection; missing layer/point disables. No recipe Undo. |
| `point.remove` `{layerId,index}` | Remove contour point, minimum three. Missing point or minimum count disables; discrete UI records one Undo. |
| `path.edit` `{layerId,command:{kind:"enable-bezier"}}` or `{kind:"point-mode",index,mode:"aligned"|"symmetric"|"corner"}` | Explicit legacy-curve conversion or point tangent constraint. `recipeActionCapability` only checks layer existence here; invalid point/path mode fails in the path helper/parser. One discrete Undo. |
| `field.select` / `field.add` / `field.remove` / `field.clear` `{layerId,fieldId?}` | Selected warp field, new zero-vector field, removal or vector reset. Select/remove/clear require an existing field ID; add disables at eight fields. Select is workspace-only; others edit recipe. |
| `field.setReach` `{layerId,fieldId,radius}` | Warp radius clamped to 0.005–0.2 UV; existing field required. Reach is a Gaussian influence scale, not a hard boundary. |
| `pigment.edit` `{layerId,command:{kind:"point-strength",index,value}}` | Per-point pigment `0..1`. Invalid index/range fails in pure helper. |
| `pigment.edit` `{...,command:{kind:"smooth-strength",enabled}}` or `{kind:"strength-blend",value}` | Toggle continuous point gradients or set its blend distance; blend requires smooth mode and must be `0.000125..0.02`. Old recipes are upgraded only by explicit edit. |
| `softness.edit` `{layerId,command:{kind:"variable-softness",enabled}}` | Toggle interpolated point widths; disabling retains the widths for later reuse. |
| `softness.edit` `{...,command:{kind:"point-softness",index,value}}` or `{kind:"uniform-softness",value}` | Edge widths `0.0005..0.06` UV; point edit requires boundary mode and a valid point. |
| `layer.setColor` `{layerId,color}`; `layer.setOpacity` `{layerId,opacity}` | Authored pigment colour (`#rrggbb`) and opacity (`0..1`). Parser validates; continuous controls use `controlBegin/Edit/Commit/Cancel` for one Undo. `controlEdit` runs the same capability gate as `dispatch` and returns `{ok}` or `{ok:false,code,message}`. Direct facade dispatch records a discrete one-step Undo. |
| `layer.setSymmetry` `{layerId,symmetry}`; `layer.setFinish` `{layerId,finish}` | Mirroring and one of the current finish families. Immediate recipe/render effects; UI records a discrete Undo. Finish selection does not imply game-export support. |
| `glitter.selectModel` `{layerId,model:"classic"|"irregular"|"direct"|"clustered"|"fine"}` | Select versioned Glitter preview model; wrong finish or unknown model disables. Selected settings enter recipe; alternate comparison settings live in workspace memory. Discrete Undo. |
| `glitter.setClassic` `{layerId,key:"cells"|"density"|"tilt",value}` | Classic flake controls, also used for Shimmer. Incompatible current model disables. Numeric limits are finally validated by recipe parser. |
| `glitter.setIrregular` `{layerId,key:"count"|"radius"|"spread"|"tilt"|"color",value}`; `glitter.setDirect` `{layerId,key:"density"|"fineShare"|"strength"|"color",value}` | Model-specific preview settings. Wrong mode disables; parser enforces actual limits and colour type. These are browser studies, not game-export adapters. |

The recipe remains portable and per-preset; `AuthoringDocument` holds current recipe, selection and up to 80 deduplicated Undo snapshots. `RecipeActions.snapshot()` and `AuthoringDocument.snapshot()` are detached copies. `AuthoringPresentation` supplies compile-time read-only detached recipe/layer/field reads and selection to today's layer/property controls; `AuthoringGeometry` supplies cached detached reads to UV and on-head coordinate adapters, preserving captured target identity through an in-place gesture and invalidating it on replacement. Collection switching uses `AuthoringDocument.restore()` to publish recipe, selection, field selection and history atomically. `AuthoringDocument` still exposes trusted in-process setters and live recipe references to application/renderer wiring in the composition root (`studio-startup.ts`): **do not present these as a safe general script surface**. The complete recipe parser/gesture validation and `AuthoringGestures` are the mutation gates. [Presentation port](../../projects/xf-studio/authoring/src/authoring-presentation.ts), [document](../../projects/xf-studio/authoring/src/authoring-document.ts), [geometry](../../projects/xf-studio/authoring/src/authoring-geometry.ts), [recipe parser](../../projects/xf-studio/authoring/src/recipe.ts).

`recipe.undo` is a workspace-scoped action with live `canUndo` capability; `recipe.redo` and `history.jumpTo` (below) complete the history actions, and the History panel lists `historyTimeline()`. It delegates to the same atomic recipe replacement and renderer-resource reset as the original shortcut; it creates no new Undo entry. The current button, shortcut and replacement-presentation fixture all dispatch it. [Application boundary](../../projects/xf-studio/authoring/src/studio-application.ts).

## Exact gesture proposals, viewing, preview and character context

The adapter-facing `StudioGestureProposal` variants are `shape.replace {next}`, `point.replace {index,next}`, `field.replace {fieldId,next}` and `path.replacePoints {points}`. UV and on-head adapters derive these from movement, tangent drags, insertion/splitting and whole-shape transforms. The facade captures source and live layer/point/field identity at begin, then builds the internal `GestureEdit` with those references. `AuthoringGestures` checkpoints once, rejects stale source/layer/point/field targets, commits one gesture Undo or cancels it on Escape/lost capture. The adapters still own pointer capture, picking, mirrored coordinate mapping, wheel bursts and view transforms. Standalone coordinate commands exist beside the gestures; see [Coordinate, history and query additions](#coordinate-history-and-query-additions). [UV adapter](../../projects/xf-studio/authoring/src/uv-editor.ts), [surface adapter](../../projects/xf-studio/authoring/src/surface-editor.ts), [pure transform](../../projects/xf-studio/authoring/src/shape-transform.ts), [gesture service](../../projects/xf-studio/authoring/src/authoring-gestures.ts).

**Input bindings.** Every pointer gesture and keyboard shortcut is catalogued in [`input-bindings.ts`](../../projects/xf-studio/authoring/src/input-bindings.ts), which maps viewport, input, exact modifiers and target to an effect, a real action ID and variant from this catalogue, a label and a cursor. The gesture adapters and key handlers resolve through it. `viewport.input()` and `viewport.subscribeInput()` publish a read-only snapshot of held modifiers plus each adapter's hover target and gesture, from which the presentation derives hint strips, target tooltips and cursors (`viewportHints`, `targetTip`, `cursorFor`). The dialog, menu and palette shortcut labels come from `bindingReference()` and `shortcutLabel()`. The `inputHints.set` preference action toggles the hints and tooltips; it never touches a recipe, Undo or SQLite. See [input bindings](input-bindings.md).

`ViewportAttachment.uvCommand("both"|"single"|"other"|"fit")` now exposes the current UV view buttons to a replacement layout. It checks readiness and single-eye mode for Other, then asks the retained editor to update and persist its view. Wheel zoom and right-drag pan remain editor gestures. View commands do not edit portable recipes or create Undo entries. [Viewport attachment](../../projects/xf-studio/authoring/src/viewport-attachment.ts).

`StudioFileOperations` is a separate in-process workflow port; its IDs also have compile-time descriptors in the application registry (`fileKinds()`, `fileDescriptors()`, `registry()`). Its typed IDs are `recipe.import`, `recipe.export`, `mask.export`, `savedV.import`, `savedV.export`, `collection.import`, `collection.export`, `collection.plan`, `package.check`, `package.build` and `collection.recover`. `capability(action)` reports missing selection, preview readiness, collection busy/loading and undo-open availability; `execute(action)` rechecks and returns `{ok,code,message}` with typed collection or saved-V results. An unavailable or overlapping call returns its reason directly without changing the active transaction or last completed result; the call that acquired the file transaction alone releases it on success, error or cancellation. The UI can show the refused call's message from its returned outcome. `snapshot()`/`subscribe()` expose current local-file activity, collection progress, the last outcome metadata, a detached partial-package Check/Build result and recovery capability. `package.freshness` is `current` only while the live authored collection equals the exact snapshot captured for that request, including after an in-flight edit; otherwise the historical result is `stale`. The service acquires files and downloads blobs through `StudioFilePort`; the browser adapter owns picker, download, worker and canvas mechanics. Recipe and saved-V imports keep their 1 MB and 128 MiB limits; collection import retains the service's 16 MB limit. Recipe, collection, plan, saved appearance and 2048² alpha-mask filenames/formats remain unchanged. Collection export still saves a SQLite revision first; package check/build still snapshot unsaved work without saving it. [File workflow service](../../projects/xf-studio/authoring/src/studio-file-operations.ts).

`LocalSetupActions` is an additional typed host-configuration port on `StudioPresentationPort`: `setup.refresh`, `setup.save` with validated game/build/source fields and expected revision, and `setup.restorePrevious` for damaged-primary recovery. There is no plate field: Build derives the built-in eye plate from the game, and `readiness.build` carries `plate_source_missing`/`plate_source_unsupported` issues and a plate limit for the presentation to show. Its read-only snapshot supplies readiness codes/reasons, current editable fields, revision, recovery state and active environment-override names. The browser device sends these only to the same-origin `/api/local-settings` endpoint; the package action still accepts just a collection snapshot and action. This state is private host configuration, separate from recipe, collection, browser layout and package manifest. [Local setup contract](../../projects/xf-studio/authoring/LOCAL-SETTINGS.md).

The desktop first-run **Continue without paths** control dispatches the existing `setup.save` with the validated default fields. That explicit opt-out advances the private settings revision, so fresh-start prompting stops across restarts while Check and UV authoring stay available; About can reopen setup later. A damaged primary continues to offer `setup.restorePrevious` instead of this opt-out. No recipe, SQLite collection or package result changes. [Desktop browser acceptance](../../projects/xf-studio/authoring/desktop/tools/review-first-run.ts).

### Host actions

`PreviewPreparationActions` (`src/preview-preparation.ts`) and `WolvenKitSetupActions` (`src/wolvenkit-setup.ts`) are renderer-side host request ports used by the preview card (`src/browser-preview-card.ts`, shared by localhost and desktop); their IDs have descriptors in `PREVIEW_PREPARATION_DESCRIPTORS` and `WOLVENKIT_DESCRIPTORS`. `preview.refresh` (read), `preview.prepare` (effect `derive`, cancellable) and `preview.cancel` take no payload. `wolvenkit.refresh` and `wolvenkit.recheck` (read; recheck forgets cached runtime and tool detection) take none; `wolvenkit.install` (effect `install-tool`, cancellable) takes only `{version}`, the person's consent to download exactly the pinned release the consent dialog showed, and `capability` refuses any other version or a state that cannot install; `wolvenkit.cancel` stops a running download. The host supplies the URL, hash, folder and every path; none has Undo. Both ports poll while work runs and publish detached `xfs/preview-core-state-1` / `xfs/wolvenkit-setup-1` snapshots, which pure view functions (`previewView`, `wolvenKitCard`, `wolvenKitConsent`) turn into plain card and dialog text. The desktop host's `/api/desktop/open-link` opens only named official pages (`wolvenkit-licence`, `wolvenkit-release`, `runtime-installer`, `runtime-page`) resolved from the host's own state; on localhost the card opens the same state-resolved URL in a new tab. When the host's setup changes outside Studio's panel (game folder chosen, WolvenKit ready, preview prepared), the card calls the composition root's `onSetupChanged`, which re-reads the shared `LocalSetupActions` snapshot so Build availability follows (no window event). [WolvenKit on first use](../../projects/xf-studio/authoring/desktop/README.md#wolvenkit-on-first-use).

`InstallDetectionActions` is published on `StudioPresentationPort` as `installDetection`. Its three read-only host requests are `detect.gameInstalls`, `detect.mo2Instances` and `detect.frameworkVersions`. All have scope `host`, effect `read`, no payload and no Undo, and all are listed in `DETECTION_DESCRIPTORS`. `capability(action)` reports when the host has no transport or when a detection is already running. `dispatch` rechecks that capability. It publishes a detached result, or a typed error when the host returns an unexpected schema.

The snapshot holds the latest `xfs/game-install-detection-1`, `xfs/mo2-instance-detection-1` and `xfs/framework-version-check-1` results:

- game install candidates confirmed by executable, each with its Steam/GOG/Epic/MO2 evidence, plus rejected registered paths;
- MO2 instances, each with its kind, game path, selected profile, configured directories and profile list;
- framework versions (ArchiveXL, TweakXL, Codeware, RED4ext, redscript, CET) for the game folder and the configured MO2 profile, with the XF Eye Artistry minimums and a plain-language message and Nexus Mods/GitHub links for each shortfall. The host reads its own local settings for this check; the report carries mod and profile names, not paths. The same report feeds the advisory `frameworks` Local setup readiness entry. [Framework check](framework-version-check.md).

These results are private host metadata. Detection changes no setting: a setup view offers a candidate, and saving the choice goes through `setup.save`. The browser device calls the fixed GET endpoint `/api/install-detection?target=games|mo2|frameworks`, and the browser supplies no path, key or command. [Detection and precedence](source-discovery-foundation.md), [actions](../../projects/xf-studio/authoring/src/install-detection-actions.ts).

|---|---|---|
| Editable makeup | `AuthoringDocument.snapshot()`; `RecipeActions.snapshot()`; collection session stashes per-preset state. | Recipe in portable preset; current editor/history in browser workspace. Explicit SQLite save makes an immutable revision. Content edits use recipe Undo; selection does not. |
| Draft/library | `CollectionService.view()` includes detached draft, saved summaries, `busy` and progress. | Draft autosaves locally; SQLite only on explicit Save/Save copy or collection/plan export. Preset restore and undo-open differ from recipe Undo. |

No recipe Undo. Workspace composition uses service snapshots; the current layout adapter still reads panel/scroll state from DOM. |
| Preview calculation | Quality `blocked/error`; mask-client diagnostics and renderer readiness in main orchestration. | Worker jobs are cancellable/cooperative internally; partial results must not be shown as ready. No unified immutable `layerReady/stale/failed` selector yet. |
| Package operation | `CollectionService.view().progress` and `StudioFileOperations.snapshot()` publish status, last detached Check/Build result, errors and collection-open recovery capability; `xfs/local-package-1` is the manifest. | Unsaved-draft snapshot. Manifest identifies original/filtered SHA-256, retained presets and omissions; `installed:false`, `gameRenderingVerified:false`. No server-build cancellation contract. |
| Workspace save | `WorkspacePersistence.snapshot()` and subscription (published only on change): `idle/saved/nearly-full/full/repaired/protected/unavailable`. | 180 ms debounce after activation, page-hide/visibility flush, separate `?verify=1` key. Unchanged content is not rewritten. ## Contextual menus: useful commands and honest gaps

These are **candidate menu contents**, not a prescribed menu design. The redesigned presentation now implements them in `src/studio-ui/target-menus.ts`, opened from the row panels and `panels/viewports.ts` (bound through `contextQuery`/`contextAt`, dispatched through `dispatchContext`); `allowsNativeTextMenu` keeps native text editing menus, and right-drag still pans. Every offered command should query its typed capability against the **hit target ID**, then revalidate at dispatch. A contextual action must not first change the active selection merely to reach another target. [Current native-menu policy](../../projects/xf-studio/authoring/src/context-menu.ts).

For example, an already constructed service can query and invoke a nonselected preset without changing selection first:

```ts
const action = { kind: "preset.edit", command: { kind: "copy", id: hitPresetId } } as const;
const capability = service.actionCapability(action);
if (capability.available) service.dispatch(action);
else renderDisabledReason(capability.reason); // Presentation callback, not a Studio API.
```

**Menu rules (implemented).** Context menus are actionable, not informational. Every menu (head view, UV map, layer, preset and collection rows) is composed from sections through `menuFromSections`, which drops any section without an action or submenu; a disabled entry counts only because it states why in words, and only where the command is genuinely relevant to the target. No section merely reports that nothing is available (the old "Background · No editable control under the cursor", "View changes are not edits", "No shape here" and "Target changed" captions are gone). Target-specific actions come first, labelled by what is under the cursor (with the owning layer and "mirrored copy" where it applies), then the viewport's view actions under a short "Head view" or "UV view" heading. Bare skin, empty UV space and background therefore show the view section alone. `tests/context-menu-sections.test.ts` checks every section of every target kind's menu (a `Record` over hit kinds makes a new kind fail to compile until it is covered), and `tests/context-hit-classification.test.ts` checks the head/background/makeup/handle classification with real rays in both views. [Target menus](../../projects/xf-studio/authoring/src/studio-ui/target-menus.ts), [menu sections](../../projects/xf-studio/authoring/src/studio-ui/menu.ts).

A point-menu command similarly uses the hit layer/index; the caller decides the discrete Undo checkpoint by passing `true`. A long drag instead enters `AuthoringGestures` once and commits/cancels that transaction. These two paths must not each add their own checkpoint for one interaction.

| Hit target | Immediately reusable commands | Missing typed/queryable bridge before a reliable menu |
|---|---|---|
| Collection or saved-list row | Rename draft; Save/Save copy; Refresh; Open by saved ID; Undo open; Export collection/plan; Check/Build. | Collection create, dirty/conflict selector, structured package eligibility per preset, package cancellation. |
| Preset row | Select, copy, rename, move, remove; restore last removal at collection scope. | Multi-select/bulk commands, revision browsing/restore, structured disabled reasons for all data validation. |
| Layer row | Select, enable, duplicate, rename, move, reset, remove; colour/opacity/finish/symmetry editing. | Unified top-level layer dispatcher and target-aware confirmation/transaction for destructive edits; layer isolation and blend modes are future work. |
| Point or tangent | Select/remove point; set strength/softness; enable Bézier and choose aligned/symmetric/corner mode. | High-level insert/move/tangent command and capability for hit geometry. Existing gestures use an index and an opaque application-held live identity; presentation reads detached geometry. |
| Warp origin/vector/reach | Select, add, remove, clear vector, set reach. | Typed origin/vector commands and position-aware capability outside pointer proposals. |
| Shape interior/empty UV/bare skin | A bound shape hit (any visible layer) offers layer selection, add warp and Bézier conversion where applicable. Empty UV and bare skin offer no standalone command, so their menus show only view actions. Existing gesture adapters translate/rotate/scale and insert near a curve; UV can fit, pan, zoom or switch eye view. | Tool-mode and UV navigation action IDs, high-level shape transform/insert command with one Undo and coordinate-aware capability. Empty-canvas menus must not imply a contour exists. |
| Viewport/background | Front, FOV, visibility, preview tier/rebuild, lighting, motion, eye/piercing context. | Orbit/pan/zoom commands, asset/job readiness selector, custom contextual menu and keyboard equivalence. |

## Coordinate, history and query additions

Added 25 September; contracts and tests are summarised in the [boundary assessment](ui-architecture-boundary.md#application-api-additions-25-september). Coordinates are canonical (unmirrored) UV.

| Exact action/query | Payload and behaviour |
|---|---|
| `point.move` | `{layerId,index,u,v}`; one Undo. |
| `point.insert` | `{layerId,u,v}`; nearest contour section in UV (exact Bézier split); selects the new point; refused at 24 points. |
| `point.setTangent` | `{layerId,index,side:"in"|"out",du,dv}`; relative arm, respecting aligned/symmetric/corner; needs Bézier handles. |
| `shape.transform` | `{layerId,command:{kind:"translate",du,dv}|{kind:"rotate",radians}|{kind:"scale",factor},pivotIndex?}`; pivot defaults to the selected point; scales widths, blends and warps like the gesture; rejected atomically. |
| `field.setOrigin` / `field.setVector` | `{layerId,fieldId,u,v}` / `{layerId,fieldId,du,dv}` (pull within ±0.1 UV). |
| `recipe.redo` | Workspace action; session-only Redo, discarded by any other edit, preset switch or restore. `authoring.history()` gives the Undo/Redo labels and depths. |
| `history.jumpTo` | `{entryId}` from `historyTimeline()` (a step ID or its `startId`). Goes to the look right after that step as **one** change: the application applies the Undo or Redo steps between atomically, publishes the recipe once and resets preview resources once. It creates no entry of its own and keeps every step (done steps become redo-able; redo-able ones become done). Refused with `busy` while a gesture or form transaction is open, `missing_target` for an ID that is no longer in the history (another preset, a restored history, or undone steps that a new edit discarded) and `invalid_value` for the current step. `consequences()` reports `recoverableBy: recipe.redo` for a jump back and `recipe.undo` for a jump forward. |
| `authoring.historyTimeline()` | Detached `HistorySnapshot` of the current preset: `steps` oldest first (`id`, `label`, `actionKind`, optional `layerId`, optional `at` epoch ms, `state: "done"|"undone"`), `current` (index of the step the look follows, −1 at the oldest kept state), `redoCount`, `trimmed` ("Older steps were not kept") and `startId`. IDs are opaque, session-unique and stable across Undo, Redo and jumps; labels and times are session-only (restored steps read "Earlier change" without a time). It carries no recipes, so the planned look-wide history ([feature-module platform §3](feature-module-platform.md#3-undo-history-and-persistence-budgets-core-02)) can publish the same shape. |
| `camera.navigate` | `{command:{kind:"orbit",yaw,pitch}|{kind:"dolly",factor}|{kind:"pan",dx,dy}}`; view state only. |
| `viewport.uvNavigate` | `{kind:"pan",du,dv}` or `{kind:"zoom",factor,at?}`; view state only, persisted like wheel/right-drag. |
| `authoring.limitsFor(target,kind,variant?)` | Current input limits and units, including state-dependent Glitter bounds and mode requirements. |
| `authoring.consequences({action}|{file}|{request})` | Replaced content, durable writes, recoverable state that would be lost, recovery path, whether to confirm. |
| `library.persistence()` | Draft versus library revision: `baseline`, `dirty`, `dirtyPresets`, `structureDirty`. |
| `files.activity()` / `files.cancel(id)` | In-flight file and collection work with request IDs; cancel refuses honestly. |
| `previewReadiness.snapshot().layers`, `viewport.snapshot().uv.selection` | Per-layer preview state; whether the selected point/warp is inside the UV view. |

Capability refusals may carry `issue: {code, field, message}` for structured validation.

## Remaining contract work and expansion

The following are **missing API work**, even when a current control or pointer gesture already performs the behavior: fully authoritative disabled-reason codes from every domain validator (the facade currently translates known textual failures), non-piercing renderer asset options and complete parameterized capabilities for shape/empty-canvas hits; authoritative immutable asset state (per-layer preview readiness now exists); and presentation of the new coordinate, history and query contracts (arrow-key nudging, consequence-driven confirmation beyond collection replacement). The new hit-context query covers existing commands and stale identity, but cannot claim unavailable coordinate-based operations. File acquisition and download now have a typed device port; UV/head coordinate adapters use detached copies that cannot mutate the document, though their local types remain mutable for gesture identity. A versioned dock/theme preference contract is present, while the custom context menu, dockable/floating/magnetic/tabbed panels and theme UI do not exist yet. Dock snap decisions must use cursor position, with keyboard alternatives. These requirements are from the [handoff brief](../backlog/claude-ui-overhaul.md); they do not dictate visual composition. The facade and composite port are exercised without any page controls by `tests/studio-application.test.ts`, `tests/studio-presentation.test.ts` and `tests/trusted-studio-bootstrap.test.ts`; the former standalone boundary fixture page and `/port-smoke.html` were retired with the sidebar shell.

Design the action *categories* to grow: more cosmetic finish adapters and material combinations; brows, jewellery/piercings, cheek makeup, hair, expression/animation and later tattoos; provider-neutral source assets; release/installation and runtime package evidence; and longer-term quest design. Current brow/lash/hair/piercing controls are preview context, **not** authoring actions for those categories. Each later authoring feature requires discussion with the maintainer before implementation. Do not hard-code one special control per present category, finish, model or package stage. [Product direction](../../projects/xf-studio/data/product-direction.md), [future feature backlog](../backlog/jewellery-and-customization.md), [functional inventory](ui-capability-inventory.md).

Examples for acceptance: ask capability for Duplicate on a nonselected layer ID and dispatch that same ID; change a point's strength and softness, then Undo the intended transaction; begin a UV shape drag, change preset, and confirm stale proposals cannot commit; Save while continuing draft edits and inspect both the stored revision and current draft; Check a collection with one Glitter-only preset and one Matte preset, then Build the same draft and compare omissions/retained identities against the manifest; recover from unavailable optional hair without blocking makeup editing; reload with camera, UV, imported V, preview quality and per-preset history intact. After the missing layout/theme services exist, also reload dock state and system/light/dark override without touching recipe data. Use `?verify=1` and keep game rendering claims separate from offline package verification.
