# XF Studio action catalogue

Generated by `bun tools/action-catalogue.ts` (in `projects/xf-studio/authoring`) from the action registry (`src/compose/studio-registry.ts`); don't edit it by hand. `tests/action-catalogue.test.ts` fails when it is stale.

Every user-visible action is registered by exactly one owner, a system family or a feature module, in the order below. An action's qualified ID is `<owner>/<kind>`. **Scope** is what it targets, **Effect** what it changes, **Undo** the history it records into (`none` records nothing), **Inputs** its payload fields (`?` marks an optional one) and **Variants** its named commands, with their Undo policy where it differs. Capabilities, limits and history labels are answered at run time by the registry (`capability`, `limitsFor`, `choicesFor`). Modules whose actions route through their own service instead are recorded exceptions in the [UI architecture boundary](ui-architecture-boundary.md).
