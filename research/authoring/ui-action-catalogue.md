# XF Studio action and capability catalogue for the UI handoff

24 September 2026. This is a source audit of the **current in-process API**, not a promise that every capability is already one public command. It complements the [functional inventory](ui-capability-inventory.md) and [Opus handoff brief](../backlog/claude-ui-overhaul.md). The command strings below are exact implemented `kind` values unless a section explicitly says **missing/proposed**. They are TypeScript application boundaries, not an HTTP scripting endpoint. A new UI should preserve validation, Undo, persistence and results through these boundaries; it should not mutate a snapshot, invoke a hidden DOM button or write SQLite directly. `StudioApplication` now aggregates `snapshot/subscribe`, exact action/request/gesture descriptors, `actionsFor` and `descriptorsFor(target)`, `capability/dispatch`, `contextCapability(target,action)` for concrete target/payload checks, `choicesFor(target,kind,field,base?)` for enumerated choices with current capability, `requestCapability/execute`, and explicit control/gesture transactions. The registry covers all 53 implemented public top-level action IDs, nine async request IDs and four low-level gesture proposals at compile time. A descriptor identifies payload types, required fields, target versus input sources, nested variants, static limits, scope and Undo/async policy; it does **not** predict every final parser constraint or supply dynamic renderer choices. The service-specific contracts below remain authoritative.

## How to read and query the current API

A menu can pass the actual hit layer ID to `choicesFor({kind:"layer",id}, "layer.setFinish", "finish")`; each finish value carries a candidate action and current structured capability. For a form or keyboard command with a concrete value, call `contextCapability(hitTarget, action)` before showing/enabling it, then call `dispatch(action)` when invoked. The latter validates again in case the document changed. A missing required value returns `needs_input`; a mismatched hit target returns `missing_target`; a value outside a declared range returns `limit`. These checks do not turn the static schema into a complete parser or discover whether a coordinate hits the shape.

| Boundary | Call and read contract | What the capability query actually knows |
|---|---|---|
| Collection draft | `CollectionService.dispatch(CollectionAction)` and `actionCapability(action)`; `view()` returns a detached draft/progress/list copy and `subscribe()` notifies changes. `CollectionActions` provides the underlying detached `view()`, `snapshot()` and `capability()`. | Busy/loading, missing preset, invalid move position, no removed preset or prior collection. Name and recipe validation can still fail at dispatch. A query is not a reservation; recheck when invoked. |
| Async collection/library | `CollectionService.execute(CollectionRequest)` and `capability(request)` return `{ok,result}` or `{ok:false,code,message}`; `view().progress` has working/success/error and `view().busy`. | Busy/loading, stale saved-list ID, 16 MB collection import budget and whether the draft has at least one valid preset for export/package. **It does not precompute package omissions, hardware/tool availability or compiler success.** |
| Layer structure | `AuthoringLayerActions.capability/dispatch` owns the checkpoint and publishes the validated result; `main.ts` only resets renderer resources after structural edits. The underlying `layerCapability`/`applyLayerAction` remain pure. | Missing layer, 32-layer preview limit, invalid reorder index; final recipe validation remains authoritative. Document subscriptions report changes. |
| Recipe document | `RecipeActions.capability(action)`, `dispatch(action, record?)`, detached `snapshot()` and `subscribe(effect)`. `AuthoringDocument` owns live recipe/selection/history and publishes state/effect notifications. | Missing layer/point/warp field, minimum three points, eight-field limit, incompatible Glitter model and mode. Many scalar, path and combination constraints are checked by the final parser/edit helpers at dispatch, not fully predicted by the capability query. |
| Presentation read port | `AuthoringPresentation.recipe()/layer()/selectedField()` return `ReadonlyDeep` values from a versioned detached geometry view; `active`, `selected` and `subscribe(change)` expose selection and change notifications. Current production layer and property controls use this port. | It carries state, not action capability. The geometry cache avoids cloning on each draw or control read; a malicious runtime cast can mutate only the detached projection, never the authored recipe. |
| Gesture transaction | Public adapters use `StudioApplication.beginGesture(source,layerId)`, `applyGesture(source,proposal)`, `gestureCapability(source,target)` and `endGesture(source,cancel)`. It resolves live references internally before `AuthoringGestures`/`RecipeActions` validate. UV/head editors read a versioned detached `AuthoringGeometry` view, cached between document changes. | A session/target identity reason is queryable; geometry hit testing, transform bounds and pointer capture remain in UV/head adapters. The detached view cannot mutate authored data, but is not compile-time read-only yet. |
| Preview and motion | `PreviewActions`, `MotionActions`, `PreviewQualityActions`, `SavedAppearanceActions` each have `capability`, `dispatch`, `snapshot` and `subscribe`. Renderer/file ports remain injected. | Numeric limits, some missing optional assets, idle/blink conflicts, quality assessment and saved-file size. Readiness and fidelity require additional renderer/resource evidence. |

## Exact commands: collection, preset and library

`CollectionAction` targets the **current draft**. `preset.edit.command` is a nested discriminated union; its inner `kind` is not a top-level command ID. IDs are UUIDs. Collection edits do not create a recipe Undo entry; preset removal has its own last-20 recovery stack, and opening/importing a collection has a separate prior-draft recovery slot. Switching presets stashes the recipe, selected layer/point/field and up to 80 recipe Undo entries for the outgoing preset. [Collection session](../../projects/xf-appearance-studio/authoring/src/collection-session.ts), [workspace operations](../../projects/xf-appearance-studio/authoring/src/collection-workspace.ts).

| Exact action/payload | Target, result and capability/validation |
|---|---|
| `preset.edit` `{command:{kind:"add"}}` | Collection; add empty preset with fresh stable ID, select it. No explicit fixed preset cap. |
| `preset.edit` `{command:{kind:"copy"|"remove",id}}` | Named preset ID. Copy gets a new ID; remove can be restored. Missing ID disables. |
| `preset.edit` `{command:{kind:"rename",id,name}}` | Named preset ID; trimmed, nonempty name up to 120 characters is validated at dispatch. |
| `preset.edit` `{command:{kind:"move",id,to}}` | Named preset ID and zero-based destination in current order. Invalid index or stale ID disables. Stable ID survives reorder. |
| `preset.edit` `{command:{kind:"restore"}}` | Restore most recently removed preset at its old position with editor memory. Disabled if removal stack is empty. |
| `preset.select` `{id}`; `preset.expand` `{expanded}` | Draft selection or expansion state; selection preserves the outgoing preset's editor state. Unknown preset disables. These are workspace state, not recipe Undo. |
| `collection.rename` `{name}`; `collection.filesOpen` `{open}` | Current collection name or file-section preference. Invalid collection name fails validation. File-section state is presentation memory, not exported collection data. |
| `collection.open` `{collection,revision?}`; `collection.undoOpen` | Open a validated collection object; undo/swap the prior draft. The prior slot is queried by `collection.undoOpen` capability. In normal UI, use async `CollectionRequest.open` to fetch by ID first. |
| `collection.importRecipe` `{recipe,name}` | Add an imported recipe as a **new preset**; preserves existing presets. File reading/1 MB budget is outside this command. |
| `collection.saved` `{result,sourceId}` | **Internal reconciliation**, not a user command: update saved identity/revisions after transport returns, retaining in-flight draft edits and rejecting a different current collection. |

`CollectionRequest` is the async/library and file-data layer. `execute` serializes requests through `busy`; save/export requests snapshot the draft before transport. The UI currently chooses a local file or performs the returned download. [Collection service](../../projects/xf-appearance-studio/authoring/src/collection-service.ts), [current adapter](../../projects/xf-appearance-studio/authoring/src/collection-ui.ts).

| Exact request/payload | Effect, side effect and recovery |
|---|---|
| `initialize`; `refresh` | List SQLite collection summaries; initialize also merges legacy draft if no restored collection. Read only to library, may populate draft. |
| `open` `{id}` | Fetch saved collection by ID, then open as a recoverable prior-draft switch. ID must still be in the current list; otherwise refresh. |
| `save`; `saveCopy` | SQLite immutable revision; copy creates a new collection ID. Transport enforces revision conflicts. Edits made during the request remain in the live draft; a stale result for another draft is rejected. |
| `exportCollection`; `exportPlan` | **Save first**, then return portable collection JSON or a compiler build-plan JSON and filename for a download adapter. A build plan is not a mod. These operations can cause a SQLite write or conflict. |
| `import` `{text,bytes}` | Parse a portable collection (current 16 MB budget) and open it as a recoverable draft switch. Invalid JSON/schema leaves current draft. File acquisition is outside the service. |
| `package` `{action:"check"|"build"}` | Snapshot the **unsaved** draft without saving SQLite. Check reports eligible retained presets and every omitted active unsupported layer/whole preset; Build creates an offline-verified private candidate if content remains. Both use the same package filter. Build uses a localhost server, one build at a time, and cannot be cancelled by closing the page. Neither installs or game-tests a mod. Errors include no exportable content, invalid input, missing local resources and verifier failure. [Package contract](studio-to-mod-pipeline.md). |

## Exact commands: layer structure and recipe editing

`LayerAction` is `{kind:"layer.edit",command:LayerCommand}` or `{kind:"layer.setEnabled",id,enabled}`. Its nested commands are `add`, `duplicate(id)`, `remove(id)`, `reset(id)`, `rename(id,name)` and `move(id,to)`. The layer array is **bottom-to-top**; `to` is zero-based. Reset preserves ID/name; duplicate gets a new ID. Removing the last layer is legal. Main orchestration currently checkpoints, replaces/render-reschedules the stack for structural edits and redraws the affected slot for visibility. `layer.setEnabled` is a recipe edit, not a view-only hide. [Layer stack](../../projects/xf-appearance-studio/authoring/src/layer-stack.ts), [main wiring](../../projects/xf-appearance-studio/authoring/src/main.ts).

`RecipeAction` uses stable `layerId` for every variant. A selected point still uses an **index**, not a stable point ID. The wrapper has `dispatch(action, record=false)`: discrete callers explicitly request one Undo checkpoint, while slider controls use separate start hooks to avoid one history entry per intermediate value. Selection effects do not record Undo; content edits validate the complete proposed recipe before publication. Render effects are `selection`, `scheduled` or `immediate`, with affected layer index. [Recipe actions](../../projects/xf-appearance-studio/authoring/src/recipe-actions.ts), [render scheduler](../../projects/xf-appearance-studio/authoring/src/authoring-render-scheduler.ts).

| Exact action/payload | Target and effect; current capability or final validation |
|---|---|
| `layer.select` `{layerId}`; `point.select` `{layerId,index}` | Workspace editor selection; missing layer/point disables. No recipe Undo. |
| `point.remove` `{layerId,index}` | Remove contour point, minimum three. Missing point or minimum count disables; discrete UI records one Undo. |
| `path.edit` `{layerId,command:{kind:"enable-bezier"}}` or `{kind:"point-mode",index,mode:"aligned"|"symmetric"|"corner"}` | Explicit legacy-curve conversion or point tangent constraint. `recipeActionCapability` only checks layer existence here; invalid point/path mode fails in the path helper/parser. One discrete Undo. |
| `field.select` / `field.add` / `field.remove` / `field.clear` `{layerId,fieldId?}` | Selected warp field, new zero-vector field, removal or vector reset. Select/remove/clear require an existing field ID; add disables at eight fields. Select is workspace-only; others edit recipe. |
| `field.setReach` `{layerId,fieldId,radius}` | Warp radius clamped to 0.005–0.2 UV; existing field required. Reach is a Gaussian influence scale, not a hard boundary. |
| `pigment.edit` `{layerId,command:{kind:"point-strength",index,value}}` | Per-point pigment `0..1`. Invalid index/range fails in pure helper. |
| `pigment.edit` `{...,command:{kind:"smooth-strength",enabled}}` or `{kind:"strength-blend",value}` | Toggle continuous point gradients or set its blend distance; blend requires smooth mode and must be `0.000125..0.02`. Old recipes are upgraded only by explicit edit. |
| `softness.edit` `{layerId,command:{kind:"variable-softness",enabled}}` | Toggle interpolated point widths; disabling retains the widths for later reuse. |
| `softness.edit` `{...,command:{kind:"point-softness",index,value}}` or `{kind:"uniform-softness",value}` | Edge widths `0.0005..0.06` UV; point edit requires boundary mode and a valid point. |
| `layer.setColor` `{layerId,color}`; `layer.setOpacity` `{layerId,opacity}` | Authored pigment colour (`#rrggbb`) and opacity (`0..1`). Parser validates; continuous controls use `controlBegin/Edit/Commit/Cancel` for one Undo. Direct facade dispatch records a discrete one-step Undo. |
| `layer.setSymmetry` `{layerId,symmetry}`; `layer.setFinish` `{layerId,finish}` | Mirroring and one of the current finish families. Immediate recipe/render effects; UI records a discrete Undo. Finish selection does not imply game-export support. |
| `glitter.selectModel` `{layerId,model:"classic"|"irregular"|"direct"|"clustered"|"fine"}` | Select versioned Glitter preview model; wrong finish or unknown model disables. Selected settings enter recipe; alternate comparison settings live in workspace memory. Discrete Undo. |
| `glitter.setClassic` `{layerId,key:"cells"|"density"|"tilt",value}` | Classic flake controls, also used for Shimmer. Incompatible current model disables. Numeric limits are finally validated by recipe parser. |
| `glitter.setIrregular` `{layerId,key:"count"|"radius"|"spread"|"tilt"|"color",value}`; `glitter.setDirect` `{layerId,key:"density"|"fineShare"|"strength"|"color",value}` | Model-specific preview settings. Wrong mode disables; parser enforces actual limits and colour type. These are browser studies, not game-export adapters. |

The recipe remains portable and per-preset; `AuthoringDocument` holds current recipe, selection and up to 80 deduplicated Undo snapshots. `RecipeActions.snapshot()` and `AuthoringDocument.snapshot()` are detached copies. `AuthoringPresentation` supplies compile-time read-only detached recipe/layer/field reads and selection to today's layer/property controls; `AuthoringGeometry` supplies cached detached reads to UV and on-head coordinate adapters, preserving captured target identity through an in-place gesture and invalidating it on replacement. Collection switching uses `AuthoringDocument.restore()` to publish recipe, selection, field selection and history atomically. `AuthoringDocument` still exposes trusted in-process setters and live recipe references to application/renderer wiring in `main.ts`: **do not present these as a safe general script surface**. The complete recipe parser/gesture validation and `AuthoringGestures` are the mutation gates. [Presentation port](../../projects/xf-appearance-studio/authoring/src/authoring-presentation.ts), [document](../../projects/xf-appearance-studio/authoring/src/authoring-document.ts), [geometry](../../projects/xf-appearance-studio/authoring/src/authoring-geometry.ts), [recipe parser](../../projects/xf-appearance-studio/authoring/src/recipe.ts).

## Exact gesture proposals, viewing, preview and character context

The adapter-facing `StudioGestureProposal` variants are `shape.replace {next}`, `point.replace {index,next}`, `field.replace {fieldId,next}` and `path.replacePoints {points}`. UV and on-head adapters derive these from movement, tangent drags, insertion/splitting and whole-shape transforms. The facade captures source and live layer/point/field identity at begin, then builds the internal `GestureEdit` with those references. `AuthoringGestures` checkpoints once, rejects stale source/layer/point/field targets, commits one gesture Undo or cancels it on Escape/lost capture. The adapters still own pointer capture, picking, mirrored coordinate mapping, wheel bursts and view transforms. There are **no standalone `point.insert`, `shape.transform`, `field.setOrigin` or `field.setVector` command IDs** yet, even though those interactions work through validated gesture proposals and pure helpers. [UV adapter](../../projects/xf-appearance-studio/authoring/src/uv-editor.ts), [surface adapter](../../projects/xf-appearance-studio/authoring/src/surface-editor.ts), [pure transform](../../projects/xf-appearance-studio/authoring/src/shape-transform.ts), [gesture service](../../projects/xf-appearance-studio/authoring/src/authoring-gestures.ts).

| Exact action family | Typed payload and scope | Capability, persistence and side effect |
|---|---|---|
| `camera.front`, `camera.setFov`, `camera.endFovGesture`, `camera.restore` | No payload; `{degrees:10..90}`; no payload; `{camera:CameraState}`. | Camera workspace state, never recipe Undo. Front/FOV may return `{limited:true}` when framing hits bounds. Orbit/pan/zoom still live in renderer controls; camera snapshot reads that port. |
| `preview.setExposure`, `preview.setKeyAngle`, `preview.setEyeShape` | `{value:0.5..2}`, `{degrees:0..360}`, `{index:0..21}`. | Preview workspace preferences; invalid ranges disable. Eye shape can override imported context without editing saved V. |
| `preview.setPiercingPreview`, `preview.setPiercings` | `{style,definition}`, `{enabled}`. | Viewport-only jewellery context. Invalid style/definition or missing local assets disables enabling. Does not alter imported V or portable makeup. |
| `preview.setSurfaceControls`, `preview.setWire`, `preview.setNormals`, `preview.setEyeOptics`, `preview.setHair`, `preview.setDetail` | `{enabled}` except Detail `{detail:"brows"|"lashes",enabled}`. | Visibility/study state in workspace. Optional brows/lashes/hair can report asset-unavailable reasons through port; fidelity is not asserted by an enabled flag. |
| `motion.setIdle`, `motion.setPaused`, `motion.setContributions` | `{enabled}`, `{paused}`, `{body,face}`. | Workspace/renderer motion. File picker and exported appearance JSON remain UI adapters. |

## Persistence, async boundaries and truthful state

| Kind of state | Current owner and safe read | Persistence/Undo rule |
|---|---|---|
| Editable makeup | `AuthoringDocument.snapshot()`; `RecipeActions.snapshot()`; collection session stashes per-preset state. | Recipe in portable preset; current editor/history in browser workspace. Explicit SQLite save makes an immutable revision. Content edits use recipe Undo; selection does not. |
| Draft/library | `CollectionService.view()` includes detached draft, saved summaries, `busy` and progress. | Draft autosaves locally; SQLite only on explicit Save/Save copy or collection/plan export. Preset restore and undo-open differ from recipe Undo. |

## Contextual menus: useful commands and honest gaps

These are **candidate menu contents**, not a prescribed menu design. The menu system itself is not implemented; current policy merely suppresses the browser menu on non-text Studio surfaces while preserving native text editing menus and right-drag pan. Every offered command should query its typed capability against the **hit target ID**, then revalidate at dispatch. A contextual action must not first change the active selection merely to reach another target. [Current native-menu policy](../../projects/xf-appearance-studio/authoring/src/context-menu.ts).

For example, an already constructed service can query and invoke a nonselected preset without changing selection first:

```ts
const action = { kind: "preset.edit", command: { kind: "copy", id: hitPresetId } } as const;
const capability = service.actionCapability(action);
if (capability.available) service.dispatch(action);
else renderDisabledReason(capability.reason); // Presentation callback, not a Studio API.
```

A point-menu command similarly uses the hit layer/index; the caller decides the discrete Undo checkpoint by passing `true`. A long drag instead enters `AuthoringGestures` once and commits/cancels that transaction. These two paths must not each add their own checkpoint for one interaction.

| Hit target | Immediately reusable commands | Missing typed/queryable bridge before a reliable menu |
|---|---|---|
| Collection or saved-list row | Rename draft; Save/Save copy; Refresh; Open by saved ID; Undo open; Export collection/plan; Check/Build. | Collection create, dirty/conflict selector, structured package eligibility per preset, package cancellation. |
| Preset row | Select, copy, rename, move, remove; restore last removal at collection scope. | Multi-select/bulk commands, revision browsing/restore, structured disabled reasons for all data validation. |
| Layer row | Select, enable, duplicate, rename, move, reset, remove; colour/opacity/finish/symmetry editing. | Unified top-level layer dispatcher and target-aware confirmation/transaction for destructive edits; layer isolation and blend modes are future work. |
| Point or tangent | Select/remove point; set strength/softness; enable Bézier and choose aligned/symmetric/corner mode. | High-level insert/move/tangent command and capability for hit geometry. Existing gestures use an index and an opaque application-held live identity; presentation reads detached geometry. |
| Warp origin/vector/reach | Select, add, remove, clear vector, set reach. | Typed origin/vector commands and position-aware capability outside pointer proposals. |
| Shape interior/empty UV | Existing gesture adapters translate/rotate/scale and insert near a curve; UV can fit, pan, zoom or switch eye view. | Tool-mode and UV navigation action IDs, shape transform/insert command with one Undo and stale-context query. Empty-canvas menus must not imply a contour exists. |
| Viewport/background | Front, FOV, visibility, preview tier/rebuild, lighting, motion, eye/piercing context. | Orbit/pan/zoom commands, asset/job readiness selector, custom contextual menu and keyboard equivalence. |

## Remaining contract work and expansion

The following are **missing API work**, even when a current control or pointer gesture already performs the behavior: fully authoritative disabled-reason codes from every domain validator (the facade currently translates known textual failures), renderer-driven asset options and complete parameterized capabilities for shape/empty-canvas hits; high-level validated insert/move/transform/warp-vector and UV/camera navigation commands; compile-time read-only signatures for the UV/head coordinate adapter geometry hooks (their current detached view is safe by copy but mutable locally); authoritative immutable preview/asset/job state including complete/stale/failed layer bundles; file acquisition and download ports for recipe, collection, mask and saved-appearance JSON; explicit retry/cancellation policy for asynchronous jobs; and separate persistent dock/layout and system/light/dark preference state. The current custom context menu, dockable/floating/magnetic/tabbed panels and theme override do not exist yet. Dock snap decisions must use cursor position, with keyboard alternatives. These requirements are from the [handoff brief](../backlog/claude-ui-overhaul.md); they do not dictate visual composition. The standalone [boundary fixture](../../projects/xf-appearance-studio/authoring/public/application-boundary-fixture.html) exercises the current facade without the existing sidebar; build its script with `bun build src/application-boundary-fixture.ts --outdir public/build --target browser` from `authoring/`.

Design the action *categories* to grow: more cosmetic finish adapters and material combinations; brows, jewellery/piercings, cheek makeup, hair, expression/animation and later tattoos; provider-neutral source assets; release/installation and runtime package evidence; and longer-term quest design. Current brow/lash/hair/piercing controls are preview context, **not** authoring actions for those categories. Nathan requires discussion before implementing each later authoring feature. Do not hard-code one special control per present category, finish, model or package stage. [Product direction](../../projects/xf-appearance-studio/data/product-direction.md), [future feature backlog](../backlog/jewellery-and-customization.md), [functional inventory](ui-capability-inventory.md).

Examples for acceptance: ask capability for Duplicate on a nonselected layer ID and dispatch that same ID; change a point's strength and softness, then Undo the intended transaction; begin a UV shape drag, change preset, and confirm stale proposals cannot commit; Save while continuing draft edits and inspect both the stored revision and current draft; Check a collection with one Glitter-only preset and one Matte preset, then Build the same draft and compare omissions/retained identities against the manifest; recover from unavailable optional hair without blocking makeup editing; reload with camera, UV, imported V, preview quality and per-preset history intact. After the missing layout/theme services exist, also reload dock state and system/light/dark override without touching recipe data. Use `?verify=1` and keep game rendering claims separate from offline package verification.
