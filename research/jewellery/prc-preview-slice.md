# Private PRC preview: three resolved female nose slots

24 September 2026. This is a viewport-only continuation of the [read-only PRC inventory](prc-inventory.md), not a distributed asset or a claim that Nathan's current game rendered this exact combination. No character-creator authoring, save editing, archive installation or game launch occurred.

The selected MO2 `2025 (again)` profile enables eagul's PRC framework v1.1 and two item folders: **Nose stud** (`fpm50`) and **Nose ring on both sides (front)** (`fpm72`, `fpm74`). Current MO2 settings do not enforce archive load order; the maintained MO2 game's default alphabetical-first rule puts item archives `PRC_f_*` ahead of `PRC_z_999_Framework_128.archive`, so their same-path morph targets are source-supported candidates to replace framework placeholders. Profile flags and this ordering rule are not a measured runtime winner. This probe covers only the three named selected item slots and framework `.app`, not every enabled archive or a launch log.

## Exact slot-72 chain

The framework archive supplies `base\characters\head\player_base_heads\appearances\head\piercings\i0_000__earring_14.app` (serialized SHA-256 `01d4cf980d5531a76fd7424555356103979f48a4d4a60e297ba67074529abe13`). Its female silver appearance `i0_000_pwa__earring__01_silver` has an `fpm72` morph component whose resource hash is `13024786168400224632`, the FNV-1a hash of `eagul\piercingmorphs\female\fpm72.morphtarget`; component chunk mask is `9223372036854775807`. PRC's slot components live in compiled appearance data, while the familiar vanilla earring parts use separate part overrides. The item archive `PRC_f_72_nostril_ring_right_1.archive` supplies that morph resource (SHA-256 `d7b5238fd9cd4990fb9b3f4a53fa8148b0ae7b9fc60c9fe8f16b4b576008fc32`). Its base mesh is the game's female `i1_000_pwa_c__basehead_earring_03.mesh`, so WolvenKit Console 8.17.4 resolves skin and morph data without a third-party linked-mesh search path.

The exported private GLB has one visible submesh, two sets of skin influences, one skin and 21 facial morph targets. Its SHA-256 is `b243873de5c4d5ed07198c61174b53a401a9eaa752af384a43cbb1a0738c6d2a`. The intake script checks the app/morph relationship, base mesh, appearance name, chunk mask, skin/morph shape and hashes; it copies only verified GLBs into ignored local `public/assets/prc`, with a strict parsed manifest. Neither extracted resource nor GLB is tracked in Git. The evidence record is [prc-piercing-intake.json](../../projects/xf-appearance-studio/authoring/evidence/prc-piercing-intake.json).

For local reproduction, extract the framework `.app` from `PRC_z_999_Framework_128.archive` into `research/consumers/prc-preview/raw/framework`; extract `fpm72.morphtarget` from `PRC_f_72_nostril_ring_right_1.archive` into the parallel `raw/rings72` folder; run WolvenKit `convert s` over `raw`, then `export` the slot-72 morph into `research/consumers/prc-preview/export` with the installed game path (`-gp`). The script expects `fpm72.morphtarget.glb` there. The framework and selected item archive SHA-256 values are respectively `6e73610b3cdd85552aeb61f6a5a7c7fd3a9cf0f26b4d4f475977b255c8e17499` and `0fd967c071ca5c5c77ce9911accaf426ebe8c896dd72324326e6fc72e87b4cc5`. It stops if the pinned 2.31 app/morph structure changes; a new source version needs review rather than silent ingestion.

The studio presents slot 72 and the additional slots below beside the existing vanilla choices. All share the Piercings visibility toggle, but selection remains viewport-only and never changes saved V, makeup recipes or exported collections. Silver browser materials are **approximate**; no PRC `.mi` shader parity or game comparison has been established. Resource and geometry loading have independent failure handling, so absent PRC inputs do not suppress vanilla choices. Loaded skinned meshes join the saved-face morph and idle-animation updates.

## Linked-mesh resolution for slots 50 and 74

The first `export -gp <installed game>` converted both morph resources but emitted missing-linked-mesh warnings and skinless GLBs. The linked resources are not missing from Nathan's enabled MO2 candidates; they are missing from the **game-only resolver scope**. Source inspection at WolvenKit commit `11720772f1e20581301b3dec88a59f7b5ee05675` found that its [`UncookTask`](https://github.com/WolvenKit/WolvenKit/blob/11720772f1e20581301b3dec88a59f7b5ee05675/WolvenKit.Modkit/RED4/Tasks/UncookTask.cs) indexes each specified `.archive`, while [`MorphTargetTools`](https://github.com/WolvenKit/WolvenKit/blob/11720772f1e20581301b3dec88a59f7b5ee05675/WolvenKit.Modkit/RED4/Tools/MorphTargetTools.cs) looks up the morph's base mesh in that index to build its skin. We supplied the **three explicit enabled candidate archives** together to `uncook` into an ignored local directory, filtering to `female\\fpm(50|74)\.morphtarget$`. No game directory, MO2 profile or installed archive was modified.

## Verification and provenance

The original `bun tools/intake_prc.ts`, typecheck, bundle build and 212 authoring tests passed with slot 72. In the isolated `?verify=1` browser on port 4438, slot 72 visibly sat on the nose; turning Piercings off removed it, turning it back on restored it, and it remained attached during the current idle motion. Reload preserved the selected PRC style, silver choice, visibility and idle settings. Switching to vanilla Piercing 01 displayed its own ear/nose geometry and hid the PRC-only ring. The browser console reported no warnings or errors. See the later verification section below for the three-slot extension. This is browser evidence only, not REDengine proof.

The three-slot extension's intake, typecheck and bundle build passed; all **227 authoring tests** passed after supplying the ignored local head/detail test inputs in its isolated worktree. At `http://127.0.0.1:4439/?verify=1`, the new **slot 50** appeared as a tiny metallic stud on the viewer's right nostril, while **slot 74** appeared as a hoop on the viewer's left. The Piercings toggle removed/restored the stud; reload preserved slot 50 and its disabled toggle; enabling it and starting the character-creator idle kept the stud attached during visible head movement. Switching from slot 74 to vanilla Piercing 01 removed the PRC hoop and showed the vanilla pair. The preview did not display a visible error. This was the original uniform-colour browser pass; the stud's [second-chunk silver material](prc-catalog-audit.md#stud-second-chunk-material-resolution-24-september) has since been traced and split from the framework colour. No game launch or runtime archive-winner test occurred.
