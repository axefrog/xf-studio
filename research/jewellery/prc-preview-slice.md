# Private PRC preview: one resolved female nostril slot

24 September 2026. This is a viewport-only continuation of the [read-only PRC inventory](prc-inventory.md), not a distributed asset or a claim that Nathan's current game rendered this exact combination. No character-creator authoring, save editing, archive installation or game launch occurred.

The selected MO2 `2025 (again)` profile enables eagul's PRC framework v1.1 and two item folders: **Nose stud** (`fpm50`) and **Nose ring on both sides (front)** (`fpm72`, `fpm74`). Current MO2 settings do not enforce archive load order; the maintained MO2 game's default alphabetical-first rule puts item archives `PRC_f_*` ahead of `PRC_z_999_Framework_128.archive`, so their same-path morph targets are source-supported candidates to replace framework placeholders. Profile flags and this ordering rule are not a measured runtime winner. This probe covers only the three named selected item slots and framework `.app`, not every enabled archive or a launch log.

## Exact slot-72 chain

The framework archive supplies `base\characters\head\player_base_heads\appearances\head\piercings\i0_000__earring_14.app` (serialized SHA-256 `01d4cf980d5531a76fd7424555356103979f48a4d4a60e297ba67074529abe13`). Its female silver appearance `i0_000_pwa__earring__01_silver` has an `fpm72` morph component whose resource hash is `13024786168400224632`, the FNV-1a hash of `eagul\piercingmorphs\female\fpm72.morphtarget`; component chunk mask is `9223372036854775807`. PRC's slot components live in compiled appearance data, while the familiar vanilla earring parts use separate part overrides. The item archive `PRC_f_72_nostril_ring_right_1.archive` supplies that morph resource (SHA-256 `d7b5238fd9cd4990fb9b3f4a53fa8148b0ae7b9fc60c9fe8f16b4b576008fc32`). Its base mesh is the game's female `i1_000_pwa_c__basehead_earring_03.mesh`, so WolvenKit Console 8.17.4 resolves skin and morph data without a third-party linked-mesh search path.

The exported private GLB has one visible submesh, two sets of skin influences, one skin and 21 facial morph targets. Its SHA-256 is `b243873de5c4d5ed07198c61174b53a401a9eaa752af384a43cbb1a0738c6d2a`. The intake script checks the app/morph relationship, base mesh, appearance name, chunk mask, skin/morph shape and hashes; it copies only this GLB into ignored local `public/assets/prc`, with a strict parsed manifest. Neither extracted resource nor GLB is tracked in Git. The evidence record is [prc-piercing-intake.json](../../projects/xf-appearance-studio/authoring/evidence/prc-piercing-intake.json).

For local reproduction, extract the framework `.app` from `PRC_z_999_Framework_128.archive` into `research/consumers/prc-preview/raw/framework`; extract `fpm72.morphtarget` from `PRC_f_72_nostril_ring_right_1.archive` into the parallel `raw/rings72` folder; run WolvenKit `convert s` over `raw`, then `export` the slot-72 morph into `research/consumers/prc-preview/export` with the installed game path (`-gp`). The script expects `fpm72.morphtarget.glb` there. The framework and selected item archive SHA-256 values are respectively `6e73610b3cdd85552aeb61f6a5a7c7fd3a9cf0f26b4d4f475977b255c8e17499` and `0fd967c071ca5c5c77ce9911accaf426ebe8c896dd72324326e6fc72e87b4cc5`. It stops if the pinned 2.31 app/morph structure changes; a new source version needs review rather than silent ingestion.

The studio presents `PRC · front nostril ring (slot 72)` beside the existing vanilla choices. Both share the Piercings visibility toggle, but selection remains viewport-only and never changes saved V, makeup recipes or exported collections. Its silver browser material is **approximate**; no PRC `.mi` shader parity or game comparison has been established. Resource and geometry loading have independent failure handling, so absent PRC inputs do not suppress vanilla choices. Loaded skinned meshes join the saved-face morph and idle-animation updates.

## Deliberate exclusions and next resolver step

The enabled `fpm50` nose stud uses `eagul\piercingmorphs\female\fpm50_linked.mesh`; the enabled `fpm74` ring uses `eagul\piercingmorphs\wa_linked.mesh`. WolvenKit exported their `.morphtarget` GLBs with a warning that these linked meshes could not be found through the specified installed-game archive path. Both GLBs lacked skin data; displaying them as if they followed head motion would be misleading. Their source archives are recorded locally and they need a safe mod-aware export path or an independently verified linked-mesh reconstruction before entering the preview. The selected `nim_piercings_recolor_silver.archive` supplies `base\eagul\mat_1.mi`, but its actual material application is not proven here. Broader PRC cataloguing should flow through the [provider-neutral resolver](../character-customization/mod-source-resolution.md), including archive conflict candidates and ArchiveXL changes, before advertising effective installed choices.

## Verification and provenance

`bun tools/intake_prc.ts`, typecheck, bundle build and all 212 authoring tests pass. In the isolated `?verify=1` browser on port 4438, slot 72 visibly sat on the nose; turning Piercings off removed it, turning it back on restored it, and it remained attached during the current idle motion. The browser console reported no warnings or errors. This is browser evidence only, not REDengine proof. Rerun checks after integration.
