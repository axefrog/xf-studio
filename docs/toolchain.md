### The three.js patch

`projects/xf-studio/authoring/patches/three@0.186.0.patch`, applied by `bun install` from `package.json`'s `patchedDependencies` (Bun's own patch mechanism; the lockfile records it). It changes `build/three.module.js` only, the build the package's `import` condition resolves to.

- **What:** each `WebGLRenderer` exposes its context's morph-target textures as `xfsMorphTextures`, with `get(geometry)` and `set(geometry, count, texture, size)`. `set` registers a texture as Three's own `WebGLMorphtargets.update` registers one: the entry, and its release when the geometry is disposed. A restored context makes a new one, as Three makes a new `WebGLMorphtargets`. Nothing else in Three changes.
- **Why:** Three builds a geometry's morph texture whole inside its first draw (50–102 ms for the head on real data). The Studio makes it ahead, in steps, and needs to hand it to that renderer (`src/platform/scene/morph-textures.ts`; [experiment 043 §13](../experiments/043-scene-runtimes/README.md#13-chunk-4a-vi-routing-by-named-view-editors-per-view-the-s2-gates-built)). Before the patch the Studio found Three's private map by wrapping `WeakMap.prototype.get` during a draw, which re-entrant draws on two renderers could confuse.
- **On a Three upgrade:** run `bun patch three` in `authoring/`, re-apply the two hunks to the new `build/three.module.js` (the `get` and `set` functions returned by `WebGLMorphtargets`, and `_this.xfsMorphTextures = morphtargets` in `initGLContext`), check that `update` still fills the texture as `morphTextureSteps` does, then `bun patch --commit node_modules/three`, which writes the new versioned patch file and updates `patchedDependencies`. Delete the old patch file. `tests/morph-textures.test.ts` fails without the patch and holds the made-ahead texture byte for byte against Three's own build; the T2 probe `tests/webgl-scene-runtimes.test.ts` (6c) checks it on a GPU. Without the patch the Studio still works: Three builds its morph textures at the draw, as it did before.
- **Licence:** three.js is MIT; its notice already accompanies distributed builds (see the [community credits](community-credits.md#threejs)). MIT asks for no notice of modification.

Last verified 25 September 2026: authoring `bun test` passes 448 (including desktop tests), `tsc --noEmit` is clean in authoring and desktop, and the site tests, build and check pass.

## Nexus connection

A personal Nexus API key was once stored with Windows CurrentUser DPAPI at `%LOCALAPPDATA%/CP2077ModdingHQ/credentials/nexus-api-key.dpapi`. As of 25 September that file is no longer present, and no current tool needs it: downloads use official public release pages. If Nexus API access is needed again, ask the maintainer to supply a key and store it the same way; never print or record it.

Do not display the decrypted key or write it into project files. Future download helpers can decrypt it in-process for requests to the official Nexus API. Prefer official public GitHub assets for frameworks that publish them. Check version, game compatibility, selected optional files and rollback manifests before updating a mod; a valid key alone does not select the right archive variant.
