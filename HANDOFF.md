## What's on the branch (0.8.4)

- **The pin over a showroom head** stands at its crown (`kPieceLift` 0.12 m above the eyes; was 0.25). No doubled offset: the game's in-world pin profile scales the marker by distance with no offset (TweakDB 2.31, read offline), so near the camera it grows above its point. Pins at V unchanged. `ui.state` pins gain `xf_mark.point_px`.
- **`game_wait` lets the main pipe go between polls** (as `session_wait`; the command API's `release`), so a second process's calls answer at once. Tested with two processes against the self-test host.
- **The comment box wraps at words.** CET 1.37.1's Dear ImGui (1.91.1) has no wrapping box and its binding no callback, so the window swaps a space for a line break where a line runs past the box and hands the text to the box in one read-only frame (which reloads it and keeps the cursor). Ctrl+Enter sends, Enter starts a line; sent text has spaces where it wrapped.
- **`test.save.delay {ms}`** (MCP `test_save_delay`): holds the next `game.save` after its prepare step, checking the kill switch every 50 ms. Refused `test_hooks_off` unless `[bridge] allow_test_hooks` (only the -writes zip sets it). Card row L1 uses it.
- **`player_state`'s z** was read from the wrong field in session 11: `position` is V's feet (17.99 before and after), `camera.position` her eyes (19.59). Documented in both commands; the undo already uses the same reference.
- **Sweeps** in photo mode hide photo mode's menu and cursor and put them back.
- **The kill key:** default Ctrl + Shift + End; the XF Runtime Bridge window's Keys line ("Stop key", the key, Change..., Reset) takes the next key with Ctrl, Shift or Alt, applies it at once and saves it to `config.ini` (new native `XFBridge_KillKey`, natives 20). Warns (never refuses) when the game's bindings (`inputUserMappings.xml`, Input Loader's `r6/input`) or a CET hotkey (`bindings.json`) use it; refuses only the bridge's own answer keys alone and Off. `bridge_info.kill_key` carries the key, spelling, default, warnings and notes.
- **The UI review's fixes:** 1 the answer buttons' hover is the Studio's primary hover (`XfAccentHover`, generated from `.btn.primary:hover`); 2 every button ignores clicks for 0.4 s after the content above it changes height, and "Sent: ..." stays until the next question; 3 answer buttons wrap at the window's text width; 4 the XF box stands at the ink panel's anchor, offsets and floors, scaled (`core/overlay` `PanelOrigin`; was a fixed 700, 12); 7 plain copy (pin tooltip, the stopped state shows only "Saving stays locked until you load a save." when the bridge changed something, errors with one next step). Trivial ones from 8 and 10: the kill-key hint in the muted colour with a tooltip, the footer "Version 0.8.4". The theme's light palette is documented as covering the window, the XF box and the CET line only.
- **The Sol review's fixes:** the kill key's save needs a whole read, keeps `config.ini.bak`, writes a flushed temporary file and moves it over the original, then reads it back (`core/Win32`); it replaces the last `kill_key` line (the effective one); Input Loader's `r6/input` is walked recursively (bounded); the comment box keeps its soft breaks through Undo and Redo (a history of its last 64 states); sweeps restore the menu and the cursor independently. Warnings end with the next step; game-bound keys stay a warning (the coordinator's decision).
- **Card:** session 12 section; session 11's B3 now sends x 0 to centre anchors. K5 records where `config.ini` and `config.ini.bak` landed under MO2.
