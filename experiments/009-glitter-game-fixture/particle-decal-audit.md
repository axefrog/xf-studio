# `mesh_decal_particles` is a flipbook decal, not a fine-glint solution

25 September 2026. This is a **read-only installed-game 2.31 source check** of a plausible alternative to the guarded Glitter export. It does not establish in-game appearance. The earlier [recipe-driven fixture](recipe-driven-boundary.md) already proves that authored coverage can feed `mesh_decal` pigment, resolved facet normal/roughness/metalness, and an optional separate emissive mask. Its source-map fine facets collapse with minification; this audit asks whether the stock *particles* decal adds a missing glint evaluator.

## Export decision

**No new supported automatic Glitter exporter follows from this candidate.** The stock `mesh_decal_particles` route adds animated atlas controls to a decal but does not supply the browser direct-glint model's UV facet selection, screen-footprint filtering and per-fragment light/view response. Its highlight pass is not that response either. Animated atlas frames could make marks move, which is a different effect and would risk the unrelated flicker Nathan reported. This inference combines the selected compiled-code observations with the already measured [stock-map minification loss](recipe-driven-boundary.md); no game render was observed.

The narrow source-supported **approximation route** remains the existing `mesh_decal` recipe-mask fixture: a separately named opt-in export profile could feed pigment plus **resolved** tilted normal/roughness/metalness facets, with a separately switchable emissive decal for stylized sparkle. The independent facet profile cannot be silently inferred from the browser `uv-cell-direct-3` controls. island_dancer's explained triangle/square axial-gradient-to-normal technique informed the tilt question, but no `.sbs` graph or pixels are copied. Its strong source-level slopes are already shown to collapse under BOX reduction, so a larger texture or `mesh_decal_particles` is not a parity solution. The separate emissive mask is light-independent.

To lift the production guard, a versioned, recipe-driven *game* adapter still needs measured shape/channel equivalence, authored-preset ordering, separate component wiring and Off clearing, a native-weight morphed plate with clearance, archive verification, and one batched in-game comparison at close and face scales under light/view/dim/blink changes. The checked stock-material approximation may turn out visually useful, but must be described as such. This audit changes no production compiler, package eligibility or authored recipe.
