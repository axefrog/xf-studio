# Authoring data to game-material candidate: explicit lossy bridge

24 September 2026. This is a proposed offline adapter boundary, **not** a Studio compiler implementation or export permission. The [fixture](README.md) uses an independently generated eye-shaped test mask rather than one of Nathan's recipes; its numerical findings test material channels and filtering, not a saved preset's look. The production [`mesh-decal-flat-v1` compiler](../../projects/xf-appearance-studio/authoring/src/preset-compiler.ts) still rejects every Glitter layer.

| Authoring source | Candidate output | What survives / changes |
| --- | --- | --- |
| Parsed `xfs/recipe-7` irregular or `xfs/recipe-8`/`-9` direct-glint layer, with stable ID and path/warp/softness settings | Shared evaluator's completed coverage mask, at an explicit chosen export size | Shape and coverage can use the same recipe geometry. The fixture's synthetic mask cannot substitute for this. Preserve original recipe bytes and layer order. |
| Layer base `color`, opacity and pigment strength | Diffuse RGB plus square-root-encoded alpha for the inspected `mesh_decal` coverage equation | A concrete engine encoding, subject to filtered-edge and game-render checks. The current fixture fixes one dark colour and test coverage. |
| A *new, separately versioned approximation profile* with seeded polygon positions, size/tilt spread and fixed-versus-axial normal option | BC5 R/G normal map; separate red normal-coverage, roughness and metalness textures | The direct browser model's `density`, `fineShare`, `strength` and `seed` do **not** determine an equivalent stock-material texture. Its view/light-dependent per-fragment facets and minification fade are lost. Do not silently reinterpret or overwrite these recipe fields. |
| Optional approximation accent with its own deterministic sparse coverage | A separate red emissive mask and `mesh_decal_emissive_subsurface` component | Light-independent emission is intentionally a second, independently switchable artistic effect. It is not a reflection lobe. |

The future adapter should return a labelled result such as `mesh-decal-resolved-glitter-study-v1`, source recipe/layer identity, chosen export tier, approximation profile and seed, generated map hashes, material/template hashes, and explicit limitations. Store the approximation choices in a build plan or opt-in export request, not by rewriting `uv-cell-direct-1` or `-2` into a different recipe model. This fixture's profile is only a fixed synthetic test: it is **not** an implicit default for real authored Glitter.

For a complete preset, bottom-to-top layers and different finishes require a deliberate material/plate assembly plan. The flat compiler already merges matte, satin and metallic destination channels; it cannot simply absorb a Glitter map and promise a second reflection lobe. A separate Glitter component needs overlap, depth, morph, clearing and skin-preservation validation. The 2.31 shader's separate normal mask and square-root diffuse coverage are the bounded channel contract; the [shader audit](shader-and-minification-audit.md) pins the exact programs. The owned plate still has unresolved clearance, and the game has not rendered this fixture.

Decision gate: retain the export guard until a versioned, recipe-driven adapter passes independent evaluator/map comparisons and a controlled game session demonstrates acceptable close and face-framed appearance, light/view response, blink stability, skin preservation and component switching. The source BOX metrics in [result.json](result.json) already show that an axial height pattern is **not** a filtering cure. Community input on the axial test is credited through [island_dancer's analysis](../../research/materials/island-dancer-glitter-graph.md); root should add this bridge to the central learning record during integration. No community graph or texture is shipped here.
